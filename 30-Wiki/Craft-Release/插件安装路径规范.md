# 插件安装路径规范

> [!important] 一句话
> **插件装错目录 = 宿主扫描不到 = 用户以为你的插件坏了。**
> 这是"插件不出现"最常见的原因，而且**完全没有报错**。

## 本机实测（2026-10-15）

| 路径 | 状态 | 说明 |
|---|---|---|
| `/Library/Audio/Plug-Ins/Components/` | ✅ 存在，0 个 | **AU**（系统级） |
| `/Library/Audio/Plug-Ins/VST/` | ✅ 存在，0 个 | VST2（已淘汰） |
| `/Library/Audio/Plug-Ins/VST3/` | ❌ **不存在** | 装了 VST3 宿主才会创建 |
| `~/Library/Audio/Plug-Ins/Components/` | ✅ 存在，0 个 | AU（用户级） |
| `~/Library/Audio/Plug-Ins/VST/` | ✅ 存在，0 个 | VST2（用户级） |

> [!note] 为什么 VST3 目录不存在
> macOS 不会预建 `VST3` 目录——**它由第一个安装 VST3 插件的程序创建**。
> 你还没装任何 VST3 宿主（Ableton 未安装），所以目录不存在。
> **这本身就是一个提示：目录不存在不代表不能用，安装时创建即可。**

## 一、macOS 路径

| 格式 | 系统级 | 用户级 |
|---|---|---|
| **VST3** | `/Library/Audio/Plug-Ins/VST3/` | `~/Library/Audio/Plug-Ins/VST3/` |
| **AU** | `/Library/Audio/Plug-Ins/Components/` | `~/Library/Audio/Plug-Ins/Components/` |
| **CLAP** | `/Library/Audio/Plug-Ins/CLAP/` | `~/Library/Audio/Plug-Ins/CLAP/` |
| **VST2** | `/Library/Audio/Plug-Ins/VST/` | `~/Library/Audio/Plug-Ins/VST/` |

**系统级 vs 用户级怎么选**：

| | 系统级 `/Library/...` | 用户级 `~/Library/...` |
|---|---|---|
| 谁能用 | 所有用户 | 只有当前用户 |
| 安装权限 | 需要管理员密码 | 不需要 |
| 卸载 | 需要权限 | 直接删 |
| **推荐** | ✅ **正式发布用这个** | 开发调试时方便 |

> [!tip] JUCE 的 `COPY_PLUGIN_AFTER_BUILD`
> 构建后自动复制到插件目录。默认装到**用户级**（不需要密码）。
> 发布时安装包应该装到**系统级**。

### AU 的特殊之处

AU 是 macOS 原生格式，除了放对目录，还需要：

1. **正确的 Info.plist**（`AudioComponents` 段声明 TYPE/SUBT/MANU）
2. 系统会缓存 AU 注册信息（`AudioComponentRegistrar`）
3. 改了 AU 之后**可能需要重启宿主或清缓存**才生效

> [!warning] AU 缓存是"改了没生效"的常见原因
> 你重新构建了 AU，但宿主还是用旧版本。
> 解法：重启宿主；或删掉宿主重新扫描；严重时清系统 AU 缓存。

## 二、Windows 路径

| 格式 | 路径 |
|---|---|
| **VST3** | `C:\Program Files\Common Files\VST3\` |
| **VST2** | 用户自定义（历史原因，没有标准位置） |
| **CLAP** | `C:\Program Files\Common Files\CLAP\` |
| **AAX** | `C:\Program Files\Common Files\Avid\Audio\Plug-Ins\` |

> [!important] VST3 在 Windows 有**标准位置**，这是 VST3 相对 VST2 的一大改进
> VST2 时代每个用户把插件放哪都不一样，宿主必须让用户手动指定路径。
> VST3 规定了标准目录，**装对了宿主就能自动找到**。

**32-bit vs 64-bit**：
- 64 位插件：`C:\Program Files\Common Files\VST3\`
- 32 位插件：`C:\Program Files (x86)\Common Files\VST3\`
- **2026 年了，只做 64 位。**

## 三、插件 bundle 的内部结构

**VST3 在 macOS 上是一个 `.vst3` 目录（bundle）**：

```
MyPlugin.vst3/
└── Contents/
    ├── Info.plist              # 元数据（含插件代码）
    ├── MacOS/
    │   └── MyPlugin            # 可执行文件（真正的二进制）
    └── Resources/              # 图片、字体等
```

**AU 是 `.component` 目录**：

```
MyPlugin.component/
└── Contents/
    ├── Info.plist              # ⚠️ 含 AudioComponents 声明
    ├── MacOS/
    │   └── MyPlugin
    └── Resources/
```

> [!danger] 为什么这个结构重要
> **代码签名要签"每一层"**，不只是可执行文件。
> 见 [[macOS 代码签名]]。
>
> 如果你手动拷贝插件时漏了 `Resources/`，插件可能加载失败但**报错信息很不明确**。

## 四、"插件不出现"的排查清单

> [!important] 按出现频率排序

| # | 原因 | 怎么查 |
|---|---|---|
| 1 | **装错目录** | 对照上面的路径表 |
| 2 | **宿主没重新扫描** | REAPER: Preferences → Plug-ins → Re-scan |
| 3 | **格式没勾选** | 宿主设置里只启用了某些格式 |
| 4 | **架构不匹配** | Apple Silicon 宿主 + Intel-only 插件（需要 Rosetta） |
| 5 | **AU 缓存没刷新** | 重启宿主；清 AU 缓存 |
| 6 | **签名问题**（macOS） | Gatekeeper 拦截 → 看 `spctl` 输出 |
| 7 | **Info.plist 里的代码不对** | TYPE/SUBT/MANU 与代码不一致 |
| 8 | **插件在扫描时崩溃** | 看宿主的扫描日志（REAPER 有详细日志） |
| 9 | **位深不匹配** | 32 位插件 + 64 位宿主 |
| 10 | **权限问题** | 文件权限不对 |

> [!tip] REAPER 是最容易排查的宿主
> 它有**详细的插件扫描日志**，会告诉你：
> - 扫描了哪些路径
> - 哪个插件失败了、为什么
> - 崩溃的插件会被隔离
>
> 见 [[插件验证工具]]。

## 五、开发时的路径策略

| 阶段 | 建议 |
|---|---|
| **日常开发** | 用 `COPY_PLUGIN_AFTER_BUILD` 装到**用户级**（不需要密码） |
| **多格式测试** | 确保宿主启用了所有格式 |
| **发布前** | 用安装包装到**系统级** |
| **跨平台** | Windows 用标准 VST3 目录；macOS 用 `/Library/...` |

### CMake 里的配置

```cmake
juce_add_plugin(MyPlugin
    FORMATS VST3 AU
    COPY_PLUGIN_AFTER_BUILD TRUE   # 构建后自动复制
    ...)
```

> [!warning] 跨平台注意
> `FORMATS AU` 在 Windows 上会被忽略（AU 只有 macOS 有）。
> 一份 CMakeLists 两个平台都能用。见 [[跨平台开发 macOS 与 Windows]]。

## 六、卸载残留

> [!warning] 插件卸载往往不干净

| 残留 | 位置 |
|---|---|
| **插件本体** | 两个插件目录（系统级 + 用户级） |
| **AU 注册缓存** | 系统缓存，可能需要重启 |
| **预设 / 配置** | `~/Library/Application Support/<厂商>/`（macOS）、`%APPDATA%`（Windows） |
| **宿主缓存** | 宿主的插件数据库 |

**给用户建议的清理命令**（macOS）：

```bash
# 检查两个位置是否都有残留
ls -d /Library/Audio/Plug-Ins/VST3/MyPlugin.vst3 2>/dev/null
ls -d ~/Library/Audio/Plug-Ins/VST3/MyPlugin.vst3 2>/dev/null
ls -d /Library/Audio/Plug-Ins/Components/MyPlugin.component 2>/dev/null
```

## 七、AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **把 VST3 当成单个文件** | 拷贝/签名时漏掉内部结构 | VST3 在 macOS 是**目录** |
| 2 | **Windows 路径用正斜杠** | 可能不生效 | 用 `\\` 或 `juce::File` |
| 3 | **硬编码用户目录** | 别人用不了 | 用系统级路径 + 安装包 |
| 4 | **以为 AU 有标准安装命令** | 手动拷贝漏了注册步骤 | 需要 Info.plist 正确 + 缓存刷新 |
| 5 | **混淆 VST2 / VST3 目录** | 装错位置 | VST2 是 `VST/`，VST3 是 `VST3/` |
| 6 | **忘了 macOS 的大小写** | 路径写错但本地不报错 | 见 [[跨平台开发 macOS 与 Windows]] |
| 7 | **手拼路径字符串** | 跨平台失败 | 用 `juce::File::getSpecialLocation` |

## 八、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 宿主里看不到插件 | 装错目录 | 对照路径表 |
| 重新构建后宿主还用旧版 | 缓存 | 重启宿主 / 重新扫描 |
| AU 完全不出现 | Info.plist 的 AudioComponents 不对 | 对照 JUCE 生成的模板 |
| 拷贝到别的机器不能用 | 签名/架构问题 | 见 [[代码签名与公证]] |
| 插件加载后崩溃 | 缺 Resources 或权限 | 检查 bundle 完整性 |
| Windows 上找不到 | 装到了 32 位目录 | 用 `Program Files\Common Files\VST3` |

## 九、怎么验证

```bash
# macOS：检查插件是否正确安装
# 1. VST3 存在性
ls -la /Library/Audio/Plug-Ins/VST3/MyPlugin.vst3/Contents/MacOS/

# 2. AU 是否存在且被系统识别
ls -la /Library/Audio/Plug-Ins/Components/MyPlugin.component/

# 3. 签名有效性（见 [[macOS 代码签名]]）
codesign -v --deep --strict /Library/Audio/Plug-Ins/VST3/MyPlugin.vst3

# 4. Gatekeeper 是否放行
spctl -a -vv -t install /Library/Audio/Plug-Ins/VST3/MyPlugin.vst3
```

> [!note] 本机实测的工具可用性
> - `codesign` ✅（`/usr/bin/codesign`）
> - `spctl` ✅（`/usr/sbin/spctl`）
> - `notarytool` ✅（通过 `xcrun --find notarytool` 找到）
> - `auval` ✅（`/usr/bin/auval`）
>
> **但你还没有插件，所以这些命令暂时没有对象可测。**
