```python
import numpy as np, wave

SR, DUR, FREQ = 48000, 2.0, 440.0
t = np.arange(int(SR * DUR)) / SR
x = np.sin(2 * np.pi * FREQ * t)              # ← 这一行就是"振荡器"

y = (x * 0.5 * 32767).astype(np.int16)        # 0.5 = 留 -6dB 余量
with wave.open('sine440.wav', 'wb') as f:
    f.setnchannels(1); f.setsampwidth(2); f.setframerate(SR)
    f.writeframes(y.tobytes())
```

```bash
afplay sine440.wav     # macOS 自带播放
```

## 已埋好的两个「防污染」机制

**1. 三层物理隔离**
`10-Sources/`（只读）→ `20-Notes/`（你的理解）→ `30-Wiki/`（AI 综合）
三个月后你仍然能分清哪句话是论文说的、哪句是 AI 推的、哪句是你想的。

**2. AI 必须报告不确定性**
写 MOC 时，AI 主动列出了 **17 条外部事实待核实**（F1–F17）和 **7 条内容疑虑**（C1–C7），
而不是把它们写成确定结论。

> [!tip] 第二条尤其重要
> 它意味着：**你可以信任这个库里的"沉默"**。
> 没被标注的内容，是真的没问题的内容。这比"什么都写得很确定"有价值得多。

写这些实验的过程中，我**六次**得出"代码有 bug"的结论，**六次都是测量方法错了**。

这不是意外，是 DSP 工作的常态。已经整理成：

📄 [[2026-10-14 测量工具会骗你 —— 六次踩坑记录]]

**三条防御规则**（写进了工具库）：

1. 结果"反常"时，**先怀疑测量，再怀疑代码**
2. 用**已知正确的简单例子**校准你的测量方法
3. **交叉验证**：两种独立方法测同一个东西

> [!tip] 为什么这一页最重要
> 技术知识你可以查文档、问 AI。
> 但"我的测量在骗我"这个认识，只能通过踩坑获得。
