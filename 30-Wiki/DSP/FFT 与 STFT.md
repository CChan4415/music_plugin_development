# FFT 与 STFT

> [!important] 一句话
> **FFT 把"随时间变化的波形"变成"各频率有多少能量"。**
> 它是你验证一切 DSP 的主要工具——**耳朵会骗你，频谱不会。**

## 为什么这一页对你特别重要

你已经知道本库的踩坑记录里**六次"代码没错、是测量错了"**。
FFT 就是那个"正确的测量工具"。

**具体用途**：

| 场景 | 用 FFT 做什么 |
|---|---|
| 验证滤波器 | 喂脉冲 → FFT → 和解析解对比（`exp-002` 做到 0.0021 dB） |
| 验证失真/饱和 | 看有没有**非谐波**成分 → 判断是否混叠 |
| 验证混响 | 看衰减曲线的频谱 → 判断阻尼是否工作 |
| 验证振荡器 | 看谐波结构，判断抗混叠是否有效 |
| 频谱分析仪 UI | 这就是插件里那个跳动的图 |

---

## 一、DFT、FFT、以及它们的区别

| 名称 | 是什么 |
|---|---|
| **DFT** | 离散傅里叶变换。**数学定义**，$O(N^2)$ |
| **FFT** | 快速傅里叶变换。**DFT 的快速算法**，$O(N\log N)$ |
| **STFT** | 短时傅里叶变换。对信号**分段**做 FFT，得到"频谱随时间变化" |

> [!note] 常见误解
> "FFT 是一种变换" —— 不准确。
> **FFT 算的就是 DFT**，只是算得快。结果完全一样。
> 所以看到"FFT 的频率分辨率"时，说的其实是 DFT 的性质。

**DFT 定义**：

$$X[k] = \sum_{n=0}^{N-1} x[n]\, e^{-j 2\pi k n / N}$$

**逆变换（IDFT）**：

$$x[n] = \frac{1}{N}\sum_{k=0}^{N-1} X[k]\, e^{+j 2\pi k n / N}$$

> [!warning] 归一化约定不统一
> 不同库对 $1/N$ 放哪里不一样：
> - **numpy**：`rfft` **不**除以 N，`irfft` 除以 N ✅ **已实测确认**
> - **JUCE**：`performRealOnlyForwardTransform` 据文档不归一化 ⚠️ **未实测**（本机无 JUCE）
> - 有的库正反变换都除以 $\sqrt{N}$
>
> **实测确认 numpy 的行为**（输入 `[1,2,3,4]`）：
> ```
> rfft(x)[0] = 10.0 = sum(x)   ← 没除以 N
> irfft(rfft(x)) == x          ← irfft 内部除以 N
> ```
>
> **后果**：如果你对比两个库的输出，幅度可能差 $N$ 倍。
> **做 null test 前先确认归一化约定。** 这是"同名不同物"陷阱的一种
> （见 [[2026-10-14 测量工具会骗你 —— 十一次踩坑记录]]）。
>
> ⚠️ **JUCE 那一行我无法在本机验证**（未安装 JUCE）。等你到阶段 4 时，
> 用 `irfft(rfft(x)) == x` 这个测试自己确认一遍。

## 二、频率分辨率：最重要的一个概念

$$\Delta f = \frac{f_s}{N}$$

$N$ 是**参与变换的样本数**，不是 FFT 的点数。

**实测验证**（48kHz 采样率，两个正弦相差 6Hz）：

| 观测时长 | N | 分辨率 Δf | 能否分辨 6Hz 间隔 |
|---|---|---|---|
| 0.1 s | 4800 | 10.0 Hz | ❌ 糊在一起 |
| 0.2 s | 9600 | 5.0 Hz | ❌ 边缘 |
| 0.5 s | 24000 | 2.0 Hz | ✅ 能（凹陷 6.02 dB） |

> [!danger] 零填充（zero-padding）**不会**提高分辨率
> 这是最常被误解的一点。实测（同样两个 6Hz 间隔的正弦）：
>
> | 零填充 | 频点数 | 两频率间的凹陷 |
> |---|---|---|
> | 1x | 2401 | 0.000 dB（糊在一起） |
> | 4x | 12001 | -0.312 dB（仍糊） |
> | 16x | 40801 | -0.323 dB（仍糊） |
> | 64x | 156001 | -0.350 dB（仍糊） |
>
> **零填充只是把同一条曲线画得更细，不产生新信息。**
> 要提高真实分辨率，**只能增加观测时间**（或换更高采样率）。
>
> **为什么零填充看起来"有用"**：它让峰值位置更精确（插值效果），
> 也更好看。但它**不能**把两个已经糊在一起的频率分开。

> [!warning] 我在这里踩过一次坑
> 我最初用"数局部极大值的个数"来判断能否分辨——
> 结果零填充后 Hann 窗的**旁瓣**产生了假的局部峰，让我得出"能分辨"的错误结论。
> 改成"看两个已知频率中点的电平凹陷"才得到正确答案。
>
> **又是一次测量方法错。** 见 [[2026-10-14 测量工具会骗你 —— 十一次踩坑记录]]。

## 三、窗函数：为什么必须加窗

FFT 假设信号是**周期性的**（首尾相接）。实际信号被截断后首尾不连续 →
**频谱泄漏（leakage）**：能量从主瓣"漏"到旁瓣，看起来像宽频噪声。

**加窗**就是把信号两端平滑地衰减到 0。

| 窗 | 主瓣宽度 | 旁瓣 | 用途 |
|---|---|---|---|
| **矩形**（不加窗） | 最窄 | 最高（-13 dB） | 信号恰好整周期时 |
| **Hann** | 2 倍 | -31 dB | **通用首选** |
| **Hamming** | 2 倍 | -43 dB | 类似 Hann，旁瓣更低但衰减慢 |
| **Blackman** | 3 倍 | -58 dB | 需要极低泄漏时 |
| **Flat-top** | 很宽 | 极低 | **测幅度精度**（如校准） |

> [!important] 窗的取舍
> **主瓣越宽 → 分辨率越差；旁瓣越低 → 泄漏越少。**
> 二者不可兼得。
>
> **默认用 Hann**：泄漏和分辨率平衡得好，是最通用的选择。

> [!warning] ⚠️ 对称 vs 周期性窗 —— 又一个"同名不同物"
> `numpy.hanning(N)` 给的是**对称**版本（分母 `N-1`），两端都是 0。
> **重叠相加（OLA）要用周期性版本**（分母 `N`）。
>
> 实测 COLA 条件 $w[n] + w[n+N/2] = 1$：
> - 对称版：误差 **1.5e-3** ❌
> - 周期性版：误差 **4.4e-16** ✅
>
> 本库的 `audio_io.hann_periodic()` 提供正确的版本。

## 四、FFT 的正确用法（三个必须遵守的规则）

### 规则 1：只对"稳态"信号做 FFT

FFT 假设信号在观测窗口内是**平稳**的。
- ✅ 正弦、稳态噪声、滤波器脉冲响应
- ❌ 单个瞬态、鼓点、语音

### 规则 2：加窗

```python
X = np.fft.rfft(x * np.hanning(len(x)))
```

### 规则 3：区分"测频响"和"测信号"

| 目的 | 正确方法 | 错误方法 |
|---|---|---|
| **测系统频响** | 喂**脉冲** → FFT 脉冲响应 | ❌ 喂白噪声看频谱（有随机起伏） |
| **测信号频谱** | 加窗 FFT | ❌ 不加窗 |

> [!tip] 为什么"脉冲响应 + FFT"是测频响的最佳方法
> 因为脉冲响应是**确定性**的——它**完全描述**一个线性时不变系统。
> 白噪声 FFT 有随机方差（单次实现的起伏很大），
> 扫频需要做反卷积。**脉冲响应最直接、最精确。**
>
> `exp-002` 用这个方法把 Biquad 验证到 **0.0021 dB** 的精度。

## 五、STFT：频谱随时间变化

对信号**分段**（加窗）做 FFT，把结果排成二维图（时间 × 频率 × 能量）。

```
帧 1: [====窗====]                    → FFT → 第 1 列
帧 2:      [====窗====]               → FFT → 第 2 列
帧 3:           [====窗====]          → FFT → 第 3 列
                    ↓
              频谱图（spectrogram）
```

**参数取舍**：

| 参数 | 影响 |
|---|---|
| **窗长（FFT size）** | 长 → 频率分辨率高、时间分辨率低。**这就是海森堡不确定性原理在信号处理里的体现** |
| **hop size（步进）** | 通常 = 窗长 / 2 或 / 4。越小越平滑，CPU 越高 |
| **窗函数** | 见上 |

> [!important] 时间-频率不确定性
> **你不能同时拥有完美的时间分辨率和频率分辨率。**
> $\Delta t \cdot \Delta f \geq \text{const}$
>
> 直觉：要测准一个低频（周期长），你必须观察足够长的时间；
> 但观察时间长，就不知道它"什么时候"发生的。
>
> **插件里的选择**：
> - **频谱分析仪**：通常 FFT 2048–8192，追求频率分辨率
> - **瞬态检测**：短窗（256–512），追求时间分辨率

### 重叠相加（OLA）重建

要从 STFT 回到时域，需要**重叠相加**，并满足 **COLA 条件**：
用 Hann 窗 + 50% 重叠时，$w[n] + w[n+N/2] = 1$，输出幅度恒定。

> [!warning] 相位声码器的"金属味"
> 如果你在频域**修改**了幅度或相位（如时间拉伸、变调），
> 再 OLA 重建时，各帧的相位不再一致 → 产生"金属味/回声感"。
>
> 这是**相位声码器（phase vocoder）**的固有问题，
> 需要专门的相位处理（phase locking / phase propagation）来缓解。
> 见 [[相位声码器 phase vocoder]]。

## 六、在插件里用 FFT

**JUCE 的接口**：

```cpp
juce::dsp::FFT fft (order);        // size = 1 << order
juce::dsp::WindowingFunction<float> window (size, juce::dsp::WindowingFunction<float>::hann);

// 前向变换（原地，需要 2*size 的缓冲区存复数）
fft.performRealOnlyForwardTransform (buffer);

// 逆变换
fft.performRealOnlyInverseTransform (buffer);
```

> [!warning] 实时线程里的 FFT
> - **FFT 对象必须在 `prepareToPlay` 里创建**（构造会分配内存）
> - 缓冲区也要预分配
> - **大 FFT 的耗时波动大** —— 8192 点的 FFT 可能在某个 block 里吃掉你全部预算
> - 常见做法：**把 FFT 放在低优先级的分析线程**，音频线程只做无锁数据传递
>
> 见 [[实时音频线程契约]]。

## 七、AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **不加窗** | 频谱全是"毛刺"，以为是自己代码错了 | 检查有没有 `* window` |
| 2 | **零填充后声称"分辨率提高了"** | 概念错误，可能误导后续设计 | 记住：分辨率只由 N 决定 |
| 3 | **归一化约定搞混** | 幅度差 N 倍，null test 失败 | 对比已知幅度的信号 |
| 4 | **在音频线程创建 FFT 对象** | 违反实时契约，可能爆音 | 检查是否在 `processBlock` 里 `new`/构造 |
| 5 | **用 FFT 测滤波器频响**（而不是脉冲响应） | 结果有随机起伏，看起来像 bug | 改用脉冲响应 |
| 6 | **忘了 `rfft` 只返回一半频谱** | 索引越界或对称性错误 | 实信号的频谱是共轭对称的，只需一半 |
| 7 | **对称/周期性窗混用** | OLA 重建幅度不平 | 见上面的 COLA 实测 |

> [!tip] 最有效的检查
> **喂一个已知答案的信号**：例如 440Hz 正弦，
> 看 FFT 峰值是否正好在 440Hz、幅度是否对。
> 如果这个都不对，后面全是错的。

## 八、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 频谱全是毛刺 | 没加窗 | `x * np.hanning(N)` |
| **幅度差 6 dB** | **加窗后没补偿相干增益** | **除以 `sum(w)` 而不是 `N`**（见下） |
| 峰值位置不准 | 频率不在频点上（**栅栏效应**） | 零填充可改善**峰值定位**（但不提高分辨率） |
| 两个频率分不开 | 观测时间不够 | 增加 N（不是零填充） |
| 幅度差很多倍 | 归一化约定不同 | 确认库的约定 |
| 低频测不准 | $\Delta f = f_s/N$，低频相对误差大 | 用**自相关**测基频（见 `audio_io.dominant_freq_autocorr`） |
| 频谱图有"回声" | STFT 相位不连续 | 相位声码器固有问题，需相位处理 |
| 结果每次不一样 | 用了随机信号（白噪声） | 改用确定性信号（脉冲/扫频） |

## 八点五、⚠️ 幅度误差 6 dB：最阴险的陷阱

**这是我自己的工具库里的真实 bug。** 实测（0.5 幅度正弦 @440Hz）：

| 窗 | 归一化 | 测得 | 结果 |
|---|---|---|---|
| 无窗 | `*2/N` | 0.5000 | ✅ |
| **Hann** | `*2/N` | **0.2500** | ❌ **差 6.02 dB** |
| Hann | `*2/sum(w)` | 0.5000 | ✅ |

**原因**：加窗把信号两端衰减到 0，**降低了总能量**。
Hann 窗的「相干增益」恰好是 **0.5**，所以幅度正好差一半（-6.02 dB）。

```python
# ❌ 错
X = np.abs(np.fft.rfft(x * np.hanning(N))) * 2.0 / N

# ✅ 对：除以窗函数之和
w = np.hanning(N)
X = np.abs(np.fft.rfft(x * w)) * 2.0 / np.sum(w)
```

> [!danger] 为什么这个 bug 特别危险
> 因为 **-6.02 dB 是一个"看起来完全合理"的数字**。
> 如果误差是 3.7 dB 或 11.2 dB，你立刻会起疑。
>
> 它会影响**所有**基于频谱的幅度测量：
> 验证滤波器增益、检查失真程度、测 THD、看混响的频响……
>
> **教训：当测量结果"看起来差不多对"时，反而要多验证一次。**
>
> 本库的 `audio_io.spectrum()` 已修正（现在对 hann/hamming/blackman/无窗
> 都给出精确幅度）。见 [[2026-10-14 测量工具会骗你 —— 十一次踩坑记录]]。

## 九、怎么验证你的 FFT 用法是对的

```python
import numpy as np, sys
sys.path.insert(0, '50-Playground/tools')
from audio_io import sine, spectrum, dominant_freq, dominant_freq_autocorr

# 1. 已知频率 → 看峰值位置
x = sine(440, 1.0, amp=0.5)
f, mag = spectrum(x, 48000)
peak_f = f[np.argmax(mag)]
assert abs(peak_f - 440) < 1, f"峰值位置错: {peak_f}"
print(f"✅ 峰值 {peak_f:.2f} Hz")

# 2. 已知幅度 → 看 dB 值（这一步能抓出 6dB 陷阱！）
peak_db = mag.max()
assert abs(peak_db - (-6.02)) < 0.2, f"幅度错: {peak_db:.2f} dB（差 6dB 就是没补偿相干增益）"
print(f"✅ 峰值 {peak_db:.2f} dB")

# 3. 低频用自相关对照
print(f"✅ 自相关测得 {dominant_freq_autocorr(x):.2f} Hz")
```

> [!tip] 三个必须通过的检查
> 1. **频率对不对**（峰值位置）
> 2. **幅度对不对**（dB 值）
> 3. **两种独立方法是否一致**（FFT vs 自相关）
>
> 第 3 条是本库踩坑记录总结出的规则：**交叉验证**。
