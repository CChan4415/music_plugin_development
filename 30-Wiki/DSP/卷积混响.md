# 卷积混响

> [!important] 一句话
> **卷积混响 = 把信号和一段真实空间的"脉冲响应"做卷积。**
> 它不"模拟"混响，而是**直接重现**某个真实空间。

## 与算法混响的区别

| | 卷积混响 | 算法混响 |
|---|---|---|
| 原理 | 和真实 IR 卷积 | 延迟网络 + 反馈（[[Schroeder 混响]] / [[反馈延迟网络 FDN]]） |
| 真实感 | ✅ **最高**（就是真实录音） | 🟠 近似 |
| 可调性 | ❌ 差（只能改 IR 或加 EQ） | ✅ **好**（每个参数都可调） |
| CPU | 高（尤其是长 IR） | 低 |
| 内存 | 大（IR 本身） | 小 |
| 延迟 | 有（分区卷积） | 通常很小 |
| 典型用途 | 电影后期、母带、复古硬件 | 实时演奏、需要调制 |

> [!note] 一句话选型
> **要真实感 → 卷积；要可调性和低延迟 → 算法。**

---

## 一、数学：就是卷积

$$y[n] = \sum_{k=0}^{L-1} h[k]\, x[n-k]$$

其中 $h$ 是空间的**脉冲响应**（Impulse Response, IR）。

> [!important] 为什么这样能重现空间
> 脉冲响应**完整描述**了一个线性时不变系统。
> 在真实空间里拍一次手（脉冲），录下回声（响应），
> 之后任何声音和这段响应卷积，就**等效于在那个空间里播放**。
>
> 这是 [[传递函数与 z 变换]] 的直接应用。

---

## 二、实测：FFT 卷积必须和直接卷积等价

**测试**（1 秒信号 × 0.5 秒 IR）：

```
len(x) = 48000, len(h) = 24000  →  输出 71999
直接卷积 vs FFT 卷积最大差异 = 3.886e-16  ✅
```

> [!danger] FFT 卷积必须零填充
> $$N_{\text{FFT}} \ge N_x + N_h - 1$$
>
> 不满足的话算的是**循环卷积**——尾部会绕回开头污染。
> 见 [[重叠相加 overlap-add]]。

```python
import numpy as np

def convolve_fft (x, h, nfft=None):
    """FFT 卷积（等价于 np.convolve）"""
    if nfft is None:
        nfft = 1 << int (np.ceil (np.log2 (len(x) + len(h) - 1)))

    # ⚠️ 必须零填充到 >= len(x)+len(h)-1
    X = np.fft.rfft (x, nfft)
    H = np.fft.rfft (h, nfft)
    return np.fft.irfft (X * H, nfft)[:len(x) + len(h) - 1]
```

## 三、实时处理：分区卷积

> [!important] 问题：IR 很长，但音频是流式的
> 一个 2 秒 IR 有 96000 个抽头。
> 直接卷积 = 每采样 96000 次乘加 → **不可能实时**。

**解法：分区卷积（partitioned convolution）**

把 IR 切成若干**分区**，每个分区用 FFT 卷积：

```
IR: [分区0][分区1][分区2]...[分区N]
      ↑ 最短，决定延迟
```

| 分区大小 | 延迟 | 分区数（2 秒 IR） | CPU |
|---|---|---|---|
| 64 | **1.33 ms** | 375 | 高（FFT 太短，效率低） |
| 128 | 2.67 ms | 188 | 中 |
| **256** | **5.33 ms** | 94 | ✅ 常用平衡点 |
| 512 | 10.67 ms | 47 | 低 |
| 1024 | 21.33 ms | 24 | 最低（但延迟大） |

> [!warning] 延迟 = 第一个分区的大小
> 因为必须等**攒满一个分区的输入**才能做 FFT。
>
> **这就是卷积混响的延迟来源**，必须用 `setLatencySamples` 报告。
> 见 [[延迟报告 latency reporting]]。

**两种分区策略**：

| 策略 | 第一个分区 | 其余分区 | 延迟 |
|---|---|---|---|
| **均匀分区** | P | P | P |
| **非均匀分区** | 小（如 64） | 递增 | **更小** ✅ |

> [!tip] 非均匀分区是常见优化
> 第一个分区用 64 采样（延迟仅 1.3 ms），后面用大分区（效率高）。
> JUCE 的 `dsp::Convolution` 就是这么做的。

## 四、IR 的内存占用

**实测**（float32，48 kHz）：

| IR 时长 | 采样数 | 内存 |
|---|---|---|
| 0.5 s | 24 000 | 0.09 MB |
| 1.0 s | 48 000 | 0.18 MB |
| **2.0 s** | **96 000** | **0.37 MB** |
| 4.0 s | 192 000 | 0.73 MB |

> [!note] 内存其实不是问题
> 即使 4 秒立体声 IR 也只有 **1.5 MB**。
> **真正的成本是 CPU**（FFT 运算）和**加载时间**。
>
> 但注意：**不能有几百个实例**。100 个卷积混响实例 × 0.37 MB = 37 MB，
> 但 CPU 才是瓶颈。

## 五、实现要点

```cpp
// JUCE 的卷积（推荐起点）
class ReverbProcessor
{
public:
    void prepare (const juce::dsp::ProcessSpec& spec)
    {
        convolution.prepare (spec);
        convolution.setLatencySamples? // ⚠️ 见下方说明
    }

    void loadImpulseResponse (const juce::File& irFile)
    {
        // ⚠️ 不能在音频线程调用！应在消息线程，或 prepare 前的加载阶段
        convolution.loadImpulseResponse (
            irFile,
            juce::dsp::Convolution::Stereo::yes,
            juce::dsp::Convolution::Trim::yes,
            juce::dsp::Convolution::Normalise::yes);
    }

    void processBlock (juce::AudioBuffer<float>& buffer, juce::MidiBuffer&)
    {
        juce::dsp::AudioBlock<float> block (buffer);
        juce::dsp::ProcessContextReplacing<float> ctx (block);
        convolution.process (ctx);
    }

private:
    juce::dsp::Convolution convolution;
};
```

> [!warning] 关于 `setLatencySamples`
> JUCE 的 `dsp::Convolution` **内部会调用** `setLatencySamples`。
> 但你如果自己实现分区卷积，**必须自己报告**。
>
> ⚠️ **具体 API 行为需查你锁定版本的 JUCE 文档**——本页不写死。

> [!danger] IR 加载绝不能阻塞音频线程
> - 读文件（IO）
> - 可能的重采样（如果 IR 采样率 ≠ 工程采样率）
> - FFT 预计算
>
> 这些都是**重活**。JUCE 的 `Convolution` 内部有后台线程处理，
> 但你要确保 **UI 上的"加载 IR"按钮不会卡住音频**。

## 六、IR 从哪来

| 来源 | 说明 |
|---|---|
| **自己录**（sine sweep + 反卷积） | 最灵活，可录任何空间 |
| **商业 IR 库** | 省事，注意许可证 |
| **硬件 IR**（弹簧混响、板混响） | 复古音色 |
| **合成 IR**（算法生成） | 可调、无版权问题 |

> [!note] 录音流程（扫频法）
> 1. 播放**对数扫频**（log sweep），同时录音
> 2. 用扫频的**逆滤波器**和录音卷积
> 3. 得到 IR
>
> 比"拍手"精确得多（信噪比高、覆盖全频段）。

> [!danger] IR 的许可证问题
> 商业 IR 库**通常禁止再分发**。
> 你的插件如果内置 IR，必须确认许可证允许。
> 见 [[开源与商业的许可证陷阱]]。

## 七、AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **FFT 卷积不零填充** | 循环卷积污染开头 | `nfft >= Nx+Nh-1` |
| 2 | **直接卷积长 IR** | CPU 爆炸 | 用分区卷积 |
| 3 | **不报告延迟** | 多轨错位 | `setLatencySamples` |
| 4 | **在音频线程加载 IR** | 读文件阻塞 → 爆音 | 消息线程加载 |
| 5 | **IR 采样率与工程不符不转换** | 混响时间/音色错 | 加载时重采样 |
| 6 | **忘了归一化 IR** | 音量差异巨大 | `Normalise::yes` |
| 7 | **每块重新做 FFT 预计算** | 浪费 CPU | prepare 里预计算 |
| 8 | **以为卷积混响零延迟** | 概念错误 | 至少一个分区 |
| 9 | **IR 太长导致内存暴涨** | 数百实例时 OOM | 限制 IR 长度 |
| 10 | **不处理单声道 IR + 立体声输入** | 声道配置错 | 明确 IR 的声道数 |

> [!danger] 第 3 和第 8 条组合起来最危险
> AI 会写"零延迟的卷积混响"，然后不报告延迟。
> 用户加载后发现**和其他轨错位**——而且因为延迟依赖分区大小，**很难诊断**。

## 八、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 开头有异常噪声 | 没零填充（循环卷积） | `nfft >= Nx+Nh-1` |
| CPU 占用极高 | 直接卷积长 IR | 分区卷积 |
| 多轨错位 | 没报告延迟 | `setLatencySamples` |
| 加载 IR 时爆音 | 音频线程做 IO | 消息线程加载 |
| 混响时间不对 | IR 采样率不匹配 | 加载时重采样 |
| 音量差异巨大 | IR 未归一化 | 归一化 |
| 内存占用高 | IR 太长/实例太多 | 限制长度 |
| 单声道 IR 输出怪 | 声道配置错 | 明确声道映射 |

## 九、怎么验证

**四个必做测试**：

| # | 测试 | 判据 |
|---|---|---|
| 1 | **FFT 卷积 == 直接卷积** | 误差 < 1e-10 |
| 2 | **延迟正确**：喂脉冲，测第一个非零输出位置 | 等于报告值 |
| 3 | **IR 加载正确**：输出 IR 应重现输入 IR 的形状 | 频谱吻合 |
| 4 | **CPU 可接受**：最大 IR 长度下测占用 | 单实例 < 5% |

```python
import numpy as np

def test_convolution_equivalence():
    """FFT 卷积必须和直接卷积等价"""
    rng = np.random.default_rng (1)
    x = rng.standard_normal (48000) * 0.1
    h = rng.standard_normal (24000) * 0.01

    y_direct = np.convolve (x, h)

    nfft = 1 << int (np.ceil (np.log2 (len(x)+len(h)-1)))
    y_fft = np.fft.irfft (np.fft.rfft(x,nfft) * np.fft.rfft(h,nfft), nfft)
    y_fft = y_fft[:len(y_direct)]

    err = np.max (np.abs (y_direct - y_fft))
    print (f"  最大差异 {err:.3e}  {'✅' if err < 1e-10 else '❌'}")
    assert err < 1e-10
    return err

def test_impulse_through_convolution (h, partition=256):
    """喂脉冲，输出应该就是 IR（延迟一个分区）"""
    x = np.zeros (len(h) + partition*2)
    x[0] = 1.0
    y = np.convolve (x, h)
    first_nonzero = np.argmax (np.abs (y) > 1e-12)
    print (f"  首个非零输出在 {first_nonzero} 采样（理论 0）")
    # 分区卷积会额外引入 partition 采样延迟
    return first_nonzero

test_convolution_equivalence()
```

**延迟测试**（最重要）：

```python
# 在插件里喂一个脉冲，找出输出的第一个非零样本
# 这个位置应该等于 setLatencySamples 报告的值
# 如果不等 → 宿主补偿错 → 多轨错位
```
