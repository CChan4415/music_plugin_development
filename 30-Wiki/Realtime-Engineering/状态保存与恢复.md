# 状态保存与恢复

> [!important] 一句话
> **用户保存工程时，你的插件必须把所有"用户能看到/听到的设置"写下来。**
> 漏一个 → 用户重开工程发现"我的设置没了"。

## 为什么这是"用户信任"问题

| 症状 | 用户感受 |
|---|---|
| 重开工程参数复位 | "这个插件有 bug" |
| 预设加载后声音不对 | "不可靠" |
| **老工程打不开** | ❌ **最严重**——用户的历史作品坏了 |

> [!danger] 最后一条是不可逆的
> 用户可能有几十个工程用了你的插件。
> 新版本打不开旧工程 = **他们的作品坏了**。

---

## 一、什么要保存，什么不要

> [!important] 核心区分：**参数 vs 运行状态**

| 类型 | 例子 | 保存吗 |
|---|---|---|
| **参数** | 增益、截止频率、ratio | ✅ **必须** |
| **开关** | 旁路、算法选择 | ✅ **必须** |
| **用户预设名** | "我的最爱" | 🟠 视情况 |
| **DSP 内部状态** | 滤波器延迟线、包络当前值 | ❌ **不要** |
| **音频缓冲区内容** | 混响尾巴 | ❌ 不要 |
| **UI 状态** | 窗口位置、缩放 | 🟠 宿主通常自己管 |

> [!danger] 为什么"运行状态"不该保存
> | 原因 | 说明 |
> |---|---|
> | **体积** | 延迟线可能几 MB |
> | **无意义** | 用户重开工程时，音频早就重新开始了 |
> | **可能有害** | 恢复旧的滤波器状态会产生爆音 |
>
> **判据**：**"用户能通过 UI 改的东西"才保存。**

> [!note] 一个例外
> 如果插件是**采样器/粒子合成**，且用户导入的采样是状态的一部分，
> 那么**文件路径**要保存（不是音频数据本身）。

## 二、实测：三个必须注意的技术点

### 1. 版本号必须放最前面（本库验证）

**实测**：一个含 5 个字段的状态序列化后 **17 字节**
（`version(4) + gain(4) + cutoff(4) + filterType(4) + bypassed(1)`）。

> [!danger] 没有版本号的后果
> ```
> v1 工程的字节流：[gain][cutoff][filterType][bypassed]      （16 字节）
> v2 插件加了字段，从第 17 字节开始读 → 越界 → 崩溃或乱码
> ```
>
> **有版本号**：先读前 4 字节知道版本 → 决定怎么解析 ✅

```cpp
// 保存
void getStateInformation (juce::MemoryBlock& destData) override
{
    const int version = 2;                       // ⭐ 版本号放最前
    juce::MemoryOutputStream out (destData, true);
    out.writeInt (version);
    out.writeFloat (gain);
    out.writeFloat (cutoff);
    out.writeInt (filterType);
    out.writeBool (bypassed);
    // v2 新增：
    out.writeFloat (mixAmount);
}

// 恢复（⭐ 必须处理旧版本）
void setStateInformation (const void* data, int sizeInBytes) override
{
    juce::MemoryInputStream in (data, (size_t) sizeInBytes, false);
    const int version = in.readInt();

    gain       = in.readFloat();
    cutoff     = in.readFloat();
    filterType = in.readInt();
    bypassed   = in.readBool();

    if (version >= 2)                            // ⭐ 只在有新字段时读
        mixAmount = in.readFloat();
    else
        mixAmount = defaultMix;                  // 旧版本的默认值
}
```

> [!important] 恢复时必须**向后兼容**
> 旧版本工程（少字段）要能读 → 用 `if (version >= N)` 判断。

### 2. 二进制 vs 文本

**实测**：`float 0.1f` 的位模式是 `0x3dcccccd`。

| 方式 | 精度 | 体积 |
|---|---|---|
| **二进制**（写 float） | ✅ **bit-exact** | 4 字节 |
| 文本（`"0.1"`） | ⚠️ 有精度损失 | 3+ 字节 |

> [!warning] 文本保存的精度问题
> 二进制浮点**无法精确表示 0.1**。
> 存成文本 `"0.1"` 再读回来，可能得到 `0.100000001...`。
>
> **对音频参数，用二进制。**
>
> ⚠️ 但二进制有**字节序**问题（见下）。

### 3. ⚠️ 不要 `memcpy` 整个 struct

**实测**：
```cpp
struct Padded { uint8_t a; uint32_t b; };
sizeof(Padded) == 8        // ⚠️ 不是 5！有对齐填充
```

> [!danger] 直接 memcpy struct 的三个问题
> | # | 问题 |
> |---|---|
> | 1 | **填充字节**被一起存进去（3 个字节的垃圾） |
> | 2 | 不同编译器/平台的**对齐规则可能不同** |
> | 3 | **字节序**不同（x86 小端，某些平台大端） |
>
> **正确做法：逐字段序列化**（用 `writeInt` / `writeFloat` 这类 API）。
>
> 它们会**明确指定字节序**（通常是网络序/小端），跨平台一致。

## 三、什么时候会被调用

> [!important] 这两个函数**不在音频线程**
> | 函数 | 线程 | 能分配吗 |
> |---|---|---|
> | `getStateInformation` | **消息线程** | ✅ 能 |
> | `setStateInformation` | **消息线程** | ✅ 能 |
>
> **所以这里可以放心分配内存、用 `std::vector`、拼字符串。**
>
> ⚠️ 但要**确认**——不同宿主的调用时机可能不同。

> [!danger] 但恢复后要**平滑过渡**
> `setStateInformation` 改完参数后：
> - 参数可能**突变**（从旧值跳到新值）
> - 平滑器（`SmoothedValue`）里还是旧值
>
> **正确做法**：
> ```cpp
> // 恢复后，让平滑器直接跳到新值（不要"滑过去"）
> smoothedGain.setCurrentAndTargetValue (gain);
> ```
> 否则重开工程时会有**短暂的参数滑动**（甚至爆音）。
>
> 见 [[参数平滑 parameter smoothing]]。

## 四、常见错误

> [!danger] 本库清单

| # | 错误 | 后果 |
|---|---|---|
| 1 | **忘了保存某个参数** | 用户设置丢失 |
| 2 | **没版本号** | 加字段后旧工程崩溃 |
| 3 | **不处理旧版本** | 旧工程读错 |
| 4 | **`memcpy` 整个 struct** | 跨平台不一致 |
| 5 | **保存了 DSP 内部状态** | 体积大 + 恢复时爆音 |
| 6 | **恢复后不平滑** | 参数突变/爆音 |
| 7 | **在音频线程调这两个函数** | 爆音（虽然通常不会） |
| 8 | **用文本保存浮点** | 精度损失 |
| 9 | **没测试往返** | 保存→恢复后不一致 |
| 10 | **改了参数范围但不处理旧值** | 旧工程的值超出新范围 |

> [!tip] 第 1 条怎么防
> **对比参数列表和 `getStateInformation`**：
> ```bash
> # 列出所有参数
> grep -n "addParameter" Source/PluginProcessor.cpp
> # 对比 getStateInformation 里写了几个
> ```
> 本库的审查清单里有这一条（见 [[AI 生成代码的审查清单]]）。

## 五、AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **忘保存某些参数** | 设置丢失 | 对比参数列表 |
| 2 | **不写版本号** | 加字段后旧工程崩 | 检查第一项 |
| 3 | **不处理旧版本** | 旧工程读错 | 检查 `if (version >= N)` |
| 4 | **`memcpy` struct** | 跨平台不一致 | 改逐字段 |
| 5 | **保存 DSP 状态** | 体积大/爆音 | 只存参数 |
| 6 | **恢复后不重置平滑器** | 参数滑动 | `setCurrentAndTargetValue` |
| 7 | **空实现**（`{}`） | 完全不保存 | 检查函数体 |
| 8 | **用 `std::string` 拼二进制** | 截断（遇到 `\0`） | 用 `MemoryBlock` |
| 9 | **不做往返测试** | 隐性不一致 | 加测试 |
| 10 | **参数范围变了不钳制旧值** | 异常行为 | 恢复时 clamp |

> [!danger] 第 7 条是最常见的"AI 骨架"
> AI 生成的 `AudioProcessor` 骨架里，这两个函数常是**空的**：
> ```cpp
> void getStateInformation (juce::MemoryBlock&) override {}
> void setStateInformation (const void*, int) override {}
> ```
> **它能编译、能跑，但用户的所有设置都不会保存。**
>
> **判据**：函数体是否为空。

> [!important] ⭐ 实测：JUCE 官方模板**就是空实现**
> JUCE 8.0.4 的 `examples/CMake/AudioPlugin/PluginProcessor.cpp` 原文：
> ```cpp
> void AudioPluginAudioProcessor::getStateInformation (juce::MemoryBlock& destData)
> {
>     // You should use this method to store your parameters in the memory block.
>     // ...
>     juce::ignoreUnused (destData);
> }
> ```
> **官方示例只留注释、不做实现。** 所以 AI 照着它生成空函数
> 完全"合理"——但**你必须自己补上**。

> [!important] ⭐ 官方真实插件（AudioPluginDemo）的做法
> `examples/Plugins/AudioPluginDemo.h` 用的是
> `AudioProcessorValueTreeState` + XML：
> ```cpp
> void getStateInformation (MemoryBlock& destData) override
> {
>     if (auto xmlState = state.copyState().createXml())
>         copyXmlToBinary (*xmlState, destData);
> }
>
> void setStateInformation (const void* data, int sizeInBytes) override
> {
>     if (auto xmlState = getXmlFromBinary (data, sizeInBytes))
>         state.replaceState (ValueTree::fromXml (*xmlState));
> }
> ```
> ⚠️ 这条路把序列化**委托给 `AudioProcessorValueTreeState`**——
> 所以本页讲的"版本号/逐字段序列化"是**手写方案**的做法；
> 用 `ValueTree` 时版本兼容由 XML 结构承担。
>
> **两条路都对，但要明确选哪条。**

> [!danger] 第 8 条很隐蔽
> ```cpp
> std::string s;
> s.push_back ((char) 0x00);      // ❌ 二进制数据里有 \0
> // 后面按 C 字符串处理时被截断
> ```
> **二进制数据必须用 `MemoryBlock`**（它带长度）。

## 六、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 重开工程参数复位 | 没保存 | 检查函数体 |
| 某个参数总是默认值 | 漏了那个参数 | 对比参数列表 |
| 旧工程打不开 | 没版本号/没兼容处理 | 加版本 + `if` |
| 恢复后爆音 | DSP 状态被恢复 | 只存参数 |
| 恢复后参数滑动 | 平滑器没重置 | `setCurrentAndTargetValue` |
| 跨平台不一致 | `memcpy` struct | 逐字段 |
| 长字符串被截断 | 二进制里有 `\0` | 用 `MemoryBlock` |
| 旧工程值异常 | 参数范围变了 | 恢复时 clamp |

## 七、怎么验证

**三个必做测试**：

| # | 测试 | 判据 |
|---|---|---|
| 1 | **往返一致性** | 保存 → 恢复 → 所有参数相同 ⭐ |
| 2 | **旧版本兼容** | 用旧版保存的工程能打开 |
| 3 | **空状态** | 传入空/错误数据不崩 |

```cpp
// ⭐ 往返测试（最实用）
void testRoundTrip()
{
    // ① 设置一组非默认值
    proc.setGain (0.73f);
    proc.setCutoff (2345.0f);
    proc.setFilterType (2);
    proc.setBypassed (true);

    // ② 保存
    juce::MemoryBlock saved;
    proc.getStateInformation (saved);

    // ③ 复位到默认
    proc.resetToDefaults();

    // ④ 恢复
    proc.setStateInformation (saved.getData(), (int) saved.getSize());

    // ⑤ 断言每个参数都恢复
    assert (proc.getGain()       == 0.73f);
    assert (proc.getCutoff()     == 2345.0f);
    assert (proc.getFilterType() == 2);
    assert (proc.getBypassed()   == true);
}
```

> [!important] 第 1 条能抓住 90% 的问题
> **"设置一组非默认值 → 保存 → 复位 → 恢复 → 断言"**
>
> 本库推荐**用非默认值**——如果用默认值测，漏保存也测不出来。

**旧版本兼容的测试**：

```
① 用旧版本插件保存一个工程
② 用新版本打开
③ 检查所有参数是否正确
```
> ⚠️ 这需要**保留旧版本的构建产物**。
