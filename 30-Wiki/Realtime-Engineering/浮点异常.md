# 浮点异常

> [!important] 一句话
> **NaN 和 Inf 一旦进入反馈环，就永远出不来**（实测证明）。
> 而它们在音频链里**必然**会出现。所以你必须主动防护。

> [!note] 注意"异常"这个词
> 这里的"浮点异常"**不是 C++ 异常**（`try/catch` 抓不到）。
> IEEE 754 的"异常"指的是**标志位**（`fenv.h` 里的 `FE_*`）。
>
> 默认情况下它们**不中断执行**，只设置标志。

---

## 一、实测：什么运算产生什么（本库验证）

| 运算 | IEEE 标志 | 结果 |
|---|---|---|
| `1.0 / 0.0` | **DIVBYZERO** | `+inf` |
| `0.0 / 0.0` | **INVALID** | `nan` |
| `1e308 * 10` | **OVERFLOW** + INEXACT | `+inf` |
| `1e-308 / 1e10` | **UNDERFLOW** + INEXACT | denormal/0 |
| `sqrt(-1)` | **INVALID** | `nan` |
| `log(0)` | **DIVBYZERO** | `-inf` |

> [!tip] 可以用 `fenv.h` 检测
> ```cpp
> #include <cfenv>
> std::feclearexcept (FE_ALL_EXCEPT);
> // ... 运算 ...
> if (std::fetestexcept (FE_INVALID)) { /* 有 NaN 产生 */ }
> ```
>
> ⚠️ 但这**不适合音频线程**（每次检查有开销，而且会阻碍优化）。
> 它更适合**测试和调试**。

---

## 二、⚠️ 核心问题：NaN 无法自愈（实测）

**测试**：一个一阶 IIR `y[n] = x[n] + 0.9·y[n-1]`，在第 100 个样本注入一次异常值。

| 注入 | 第 101 个样本 | 第 200 个 | 第 10000 个 |
|---|---|---|---|
| **无** | 0.0000 | 0.0000 | 0.0000 |
| **NaN** | `nan` | `nan` | **`nan`** ⚠️ |
| **Inf** | `inf` | `inf` | **`inf`** ⚠️ |

> [!danger] 一次注入，永久污染
> **原因**：`0 × NaN = NaN`，`NaN + 任何数 = NaN`。
> 反馈环会把这个 NaN **无限循环下去**。
>
> **这不是"会慢慢恢复"，是"永远不恢复"。**

**对比 FIR（无反馈）**：

| 结构 | 注入 NaN 后 |
|---|---|
| **IIR**（有反馈） | **永久 `nan`** |
| **FIR**（无反馈） | **0.0000**（NaN 被冲出去了）✅ |

> [!important] 这解释了两件事
> 1. **为什么 IIR 滤波器必须防 NaN**——它没有"自愈"能力
> 2. **为什么 FIR 更"安全"**——有限记忆，坏数据会自然流走
>
> 见 [[FIR 滤波器]]、[[IIR 滤波器]]。

## 三、NaN / Inf 的传播规则（实测）

| 表达式 | 结果 | 说明 |
|---|---|---|
| `NaN + 1` | `nan` | 传染 |
| **`NaN * 0`** | **`nan`** | ⚠️ **不会变回 0** |
| `Inf - Inf` | `nan` | 产生新 NaN |
| `Inf * 0` | `nan` | 产生新 NaN |
| `1 / Inf` | `0` | ✅ 唯一"安全"的 |
| `NaN > 0` | **`false`** | ⚠️ 任何比较都是 false |
| `NaN != NaN` | **`true`** | ⚠️ 用 `==` 判不出 NaN |

> [!danger] 两条最危险的
> 1. **`NaN * 0 = NaN`**——所以"乘以 0 让它消失"**不成立**
> 2. **`NaN > 0` 是 false**——所以 `if (x > 0)` 这类**保护逻辑会失效**！
>
> 第 2 条特别阴：你写 `if (level > threshold) applyGain();`
> NaN 会让这个条件**静默地不成立**，而不是报错。

## 四、怎么防护

### 方法 1：`isfinite` 检查（最直接）

**实测效果**：

| 处理 | 最终结果 | 修复次数 |
|---|---|---|
| **不防护** | `nan` | 0 |
| **`isfinite` 检查并清零** | **0.0000** ✅ | **1** |

> [!important] 只需修复一次
> 因为 NaN 只在**注入那一刻**存在——清掉它，反馈环就干净了。
> **所以每次检查的开销，换来的是"永绝后患"。**

```cpp
// 在关键位置检查（如每个 block 的输出）
for (int i = 0; i < numSamples; ++i)
{
    float y = process (data[i]);

    // ⭐ 防护：非有限值清零
    if (!std::isfinite (y))
        y = 0.0f;

    data[i] = y;
}
```

> [!warning] 检查频率的取舍
> | 位置 | 开销 | 覆盖 |
> |---|---|---|
> | **每采样** | 高 | 最全 |
> | **每 block 边界** | 低 | 能拦住"持续 NaN" |
> | **只在输入** | 最低 | 拦不住内部产生的 |
>
> **推荐**：**每 block 检查一次输出**——性价比最高。
> 因为 NaN 一旦出现就会持续，block 级检查足以发现。

### 方法 2：从源头防止

| 源头 | 防护 |
|---|---|
| **除以可能为 0 的值** | `denom = std::max(denom, 1e-20f)` |
| `sqrt` 负数 | `sqrt(std::max(0.0f, x))` |
| `log(0)` | `log(std::max(x, 1e-20f))` |
| 参数极端值 | **钳制**（见下） |
| 用户输入 | 校验 + 钳制 |

```cpp
// ⭐ 参数钳制是最有效的前置防护
cutoff = std::clamp (cutoff, 20.0f, sampleRate * 0.45f);
Q      = std::clamp (Q, 0.05f, 20.0f);
gain   = std::clamp (gain, 0.0f, 2.0f);
```

### 方法 3：`ScopedNoDenormals`（相关但不同）

```cpp
juce::ScopedNoDenormals noDenormals;   // 每个 processBlock 开头
```
⚠️ 它处理的是 **denormal**（性能问题），不是 NaN。
见 [[denormal 数处理]]。

## 五、AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **以为 `x * 0` 能清掉 NaN** | ❌ 结果仍是 NaN | 用 `isfinite` |
| 2 | **用 `if (x > 0)` 做保护** | NaN 时条件为 false，保护失效 | 先 `isfinite` |
| 3 | **用 `x == x` 判 NaN** | 能判但意图不清晰 | 用 `std::isnan` |
| 4 | **不钳制参数** | 极端值产生 NaN | `std::clamp` |
| 5 | **除以未保护的变量** | DIVBYZERO | 分母加保护 |
| 6 | **`try/catch` 抓浮点异常** | ❌ 抓不到（不是 C++ 异常） | 用 `fenv` 或 `isfinite` |
| 7 | **只在输入检查** | 内部产生的 NaN 漏掉 | 也检查输出 |
| 8 | **以为 NaN 会"自己消失"** | 反馈环里永不消失 | 主动清零 |
| 9 | **用 `-ffast-math`** | 假定无 NaN → 检测失效 | 见 [[浮点确定性与可复现性]] |
| 10 | **不做任何防护** | 用户遇到静音/爆音 | 加 block 级检查 |

> [!danger] 第 6 条是概念错误
> ```cpp
> try { y = a / b; }        // ❌ 抓不到除零
> catch (...) { }           // 浮点除零不抛异常
> ```
> IEEE 754 的"异常"是**标志位**，不是 C++ 异常。
>
> **要 `#include <cfenv>` 用 `fetestexcept`**，或者直接用 `isfinite`。

> [!danger] 第 9 条会让防护完全失效
> `-ffast-math` **假定不存在 NaN**——编译器可以优化掉你的 `isfinite` 检查。
> **防护代码会被静默删除。**
>
> 见 [[浮点确定性与可复现性]]。

## 六、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 插件突然静音 | NaN 进了反馈环 | `isfinite` 清零 |
| 输出持续爆音 | Inf 在反馈环里 | 同上 |
| 保护逻辑失效 | `NaN > 0` 是 false | 先 `isfinite` |
| 用户极端参数下崩溃 | 参数没钳制 | `std::clamp` |
| `try/catch` 抓不到 | 概念错 | 用 `fenv` / `isfinite` |
| 加了防护仍失效 | 用了 `-ffast-math` | 去掉它 |
| 只在输入检查漏掉 | 内部产生 NaN | 也检查输出 |

## 七、怎么验证

**四个必做测试**：

| # | 测试 | 判据 |
|---|---|---|
| 1 | **注入 NaN 到输入** | 输出不持续 NaN |
| 2 | **注入 Inf** | 同上 |
| 3 | **极端参数** | 不产生 NaN |
| 4 | **长时间运行** | 输出始终有限 |

```cpp
// ⭐ 注入测试（本库推荐）
const float edgeCases[] = {
    std::numeric_limits<float>::quiet_NaN(),
    std::numeric_limits<float>::infinity(),
    -std::numeric_limits<float>::infinity(),
    0.0f, -0.0f, 1e30f, -1e30f,
    std::numeric_limits<float>::denorm_min(),
};

for (float v : edgeCases) {
    // 重置插件状态，喂一个 v，然后跑 1 秒
    // 断言：输出最终应该恢复有限值
    assert (std::isfinite (outputAfter1Second));
}
```

> [!important] 关键断言
> **"注入 NaN 后，1 秒内输出应恢复有限值"**——
> 这一条能同时抓住"没防护"和"防护失效"。

**配合 sanitizer**：

```bash
clang++ -std=c++17 -O1 -g -fsanitize=float-divide-by-zero \
    -fsanitize=undefined -fno-sanitize-recover=all \
    test.cpp -o test
```
> ⚠️ `-fsanitize=float-divide-by-zero` 的可用性需确认（见 [[UndefinedBehaviorSanitizer]]）。
