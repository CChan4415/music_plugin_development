# 合成原理与 DSP 拓扑

> [!important] 这一页解决什么问题
> 你玩过加法、减法、粒子、模块合成器——你**知道它们听起来是什么样**。
> 但你不知道的是：**每一种"听起来是什么样"背后是一个具体的 DSP 结构，
> 而这个结构决定了它必然好听在哪、必然难做在哪。**
>
> 这一页是一张地图：**你拧过的每一个旋钮 → 代码里的一段结构 → 你会撞上的那堵墙。**
> 它不教你"什么是 FM"，它告诉你"FM 为什么必然混叠，所以你必然要写过采样"。

## 总览：一条主线

所有合成器都是同一个东西：

```
        ┌───────────────────────────────────────────┐
        │  ① 声源         ② 塑形        ③ 时变控制   │
        │  振荡器/采样  →  滤波器/包络  →  LFO/调制   │
        └───────────────────────────────────────────┘
```

**"哪种合成方式"这个问题，问的其实是第 ① 步用什么。**
而第 ② ③ 步的难点（滤波器建模、包络曲线、调制深度）对所有合成方式都一样。

> [!note] 这张地图怎么用
> 下面每一节的结构都是：**你熟悉的声音 → DSP 结构 → 主要难点 → 常见坑**。
> 如果你要做的是**减法合成器**，重点读 §1、§8；
> 如果是**粒子**，重点读 §5；如果是**物理建模**，重点读 §6。
> 但**§7（噪声）和 §8（包络/LFO）每一节都要读**——它们是所有合成器的公共部件。

## 1. 减法合成 → 振荡器 + 滤波器

```
[ 振荡器：产生富含谐波的波形 ] → [ 滤波器：减掉不要的谐波 ] → [ 包络/LFO：让它们动起来 ]
```

**为什么叫"减法"**：振荡器产生的是一个**已经富含谐波**的波形（锯齿、方波），
滤波器做的是**减掉**其中一部分。所以"音色设计"= 选择减掉什么。

### 难点 A：抗混叠振荡器

一个理想的锯齿波包含**无限多个**谐波。在采样率 48 kHz 下，奈奎斯特频率是 24 kHz。
一个 1000 Hz 的锯齿波，它的第 25 次以上谐波全部超过奈奎斯特频率——
**它们不会消失，它们会折叠回可听频段**，变成和基频**不成谐波关系**的成分。

| 波形 | 谐波衰减 | 混叠的听感 |
|---|---|---|
| 正弦 | 只有一个谐波 | 无混叠 |
| 三角 | −12 dB/oct | 轻微，混叠成分很弱 |
| 方波 | −6 dB/oct（奇次） | 明显，"沙沙"的金属声 |
| 锯齿 | −6 dB/oct（全谐波） | **最严重**，高频有"脏"感 |

**高音区最严重**：基频越高，超过奈奎斯特的谐波越多，折叠回来的成分也越靠近可听区。
一个 5 kHz 的锯齿波，只有不到 5 个谐波是"合法"的。

**四类解法**（详见 [[抗混叠振荡器]]）：

| 方法 | 思路 | 代价 |
|---|---|---|
| **过采样（oversampling）** | 在更高采样率下生成，再滤掉带外成分降采样 | CPU；需要好的抗混叠滤波器。见 [[过采样 oversampling]] |
| **BLEP / BLIT / MinBLEP** | 在波形的不连续点处**修正**，加一个带限的阶跃 | 需要对不连续点定位；实现繁琐但高效 |
| **DPW（differentiated polynomial waveform）** | 用多项式波形，差分后自然带限 | 只适合特定波形；有轻微的高频损失 |
| **波表 + mipmap** | 预计算好带限的波形 | 见 §4；需要内存 |

> [!warning] 混叠是不可逆的
> 一旦折叠回可听频段，**它就和合法信号完全无法区分**——你无法在输出端把它滤掉。
> 这就是为什么抗混叠必须**在生成时**做，而不是"输出加个低通"。
> 这也是 [[从音乐制作人到插件开发者]] 里"数字味重 = 混叠"那一条的具体含义。
> 见 [[混叠 aliasing]]。

### 难点 B：模拟滤波器模型

你在硬件合成器上拧的那种"肥"、"有性格"的滤波器，在数字域里**很难复刻**。原因有两层：

**第一层：模拟滤波器是非线性的。**
Moog ladder 滤波器的核心是晶体管/二极管的**饱和**，这带来了：
- 输入电平越大，截止频率和 Q 会**漂移**（不是理想线性滤波器）
- 谐振时的自限幅（不会无限尖）
- 轻微的谐波失真

一个"数学上正确"的 biquad 完全没这些——**所以它听起来"干净但死板"。**
见 [[非线性失真感知]]。

**第二层：零延迟反馈（ZDF）问题。**
Moog ladder 是**四级一阶低通串成一个反馈环**。在数字域里直接实现：

```cpp
// ❌ 朴素做法：反馈环里插入一个采样延迟（unit delay）
// 结果：谐振频率不准，高 Q 时音高偏移，自激行为完全不对
float y = lp4.process (input - k * yPrev);
yPrev = y;
```

这个"单位延迟"改变了反馈环的相位，导致**谐振频率随截止频率变化而偏移**——
而你正是要**扫**这个截止频率，所以问题在扫频时最明显。

**解法**：把反馈环看作一个**代数方程**，直接解出 $y[n]$（而不是用 $y[n-1]$）：

$$y[n] = \frac{H_{\text{forward}}(x[n])}{1 + k \cdot H_{\text{feedback}}}$$

这需要知道每一级的**瞬时**响应（而不是延迟一拍的响应），这就是 ZDF / TPT（topology-preserving transform）的核心思想。

> [!important] 为什么这值得单独一页
> [[虚拟模拟滤波器]] 和 [[状态变量滤波器 SVF]] 之所以重要，
> 是因为它们的**系数与参数近似线性**，所以：
> - 可以被 LFO 快速调制而不产生伪影（见 [[参数平滑 parameter smoothing]]）
> - 可以做 ZDF 拓扑
> - 扫频时不会"阶梯感"
>
> 一个用 Biquad 级联做的 ladder 模型，在**静态**下可能听不出问题，
> 一旦你扫截止频率就会暴露。**这正是"这个插件听起来像玩具"的常见原因。**

## 2. 加法合成 → 正弦叠加 + 包络

$$y(t) = \sum_{k=1}^{N} a_k \sin\!\big(2\pi k f_0 t + \varphi_k\big)$$

**最直白的合成方式**：你直接指定每一个谐波的幅度（$a_k$）和相位（$\varphi_k$）。
傅里叶级数就是这个公式，所以加法合成是"频谱的直接翻译"。

### 难点：计算成本

| 部分数 | 复音数 | 需要的振荡器数 | 说明 |
|---|---|---|---|
| 32 | 1 | 32 | 单音色尚可 |
| 32 | 8 | **256** | 每个采样 256 次正弦计算 → 灾难 |
| 128 | 8 | **1024** | 实时不可能 |

**解法**：

| 方法 | 思路 | 代价 |
|---|---|---|
| 查表（wavetable lookup）+ 线性插值 | 一个正弦周期存 2048 点，查表 + 插值 | 精度受表长限制；插值引入误差 |
| **相位累加器共享** | 所有谐波的相位都是基频相位的整数倍 → 只累加一次 | **这是关键优化**：$N$ 个谐波只需 1 个相位累加器 |
| SIMD 批量计算 | 一次算 4/8 个谐波 | 需要数据布局配合 |
| **逆 FFT（inverse FFT）** | 一个 IFFT 一次性产生**整个 block** 的所有谐波 | **现代加法合成器的标准做法**；复杂度从 $O(N)$ 每采样降到 $O(\log N)$ 每采样 |

> [!tip] 逆 FFT 是加法合成的关键洞察
> 加法合成在**时域**上很贵（N 个振荡器），但在**频域**上极其便宜——
> 你只需要把 $a_k$ 填进一个频谱数组，做一次 IFFT，就得到了一个 block 的波形。
> 代价是**分块处理**（block size 的延迟）和**相位连续性**问题（块与块之间要对齐相位，见 [[重叠相加 overlap-add]]）。
> 见 [[FFT 与 STFT]]。

### 为什么加法合成听起来"电子"

这是[[MOC - Music & Acoustics]]里点名的问题。答案是**四个具体的缺失**：

| 缺失 | 真实乐器有什么 | 纯加法有什么 | 听起来 |
|---|---|---|---|
| **相位关系** | 各谐波的相位由振动模式和激励位置决定，且随时间演化 | 通常是零相位（全部余弦从 0 开始）或固定相位 | 零相位会造成**起音处一个巨大的脉冲峰**，然后才进入稳态 → 听成"咔"的一声 |
| **噪声成分** | 呼吸声、弓毛摩擦、按键声、指甲声、气声 | 只有谐波，没有噪声 | 过分干净、"塑料" |
| **时变频谱** | 谐波幅度随时间和力度**持续变化**（比如钢琴高次谐波先衰减） | 通常每个音符一个固定频谱 | 静态、像风琴 |
| **非谐性（inharmonicity）** | 真实弦的谐波略微偏离整数倍：$f_k \approx k f_0\sqrt{1 + Bk^2}$ | 严格整数倍 | 严格谐波听起来"电子/管风琴" |

> [!important] 这张表就是"如何让加法合成不那么电子"的待办清单
> 1. 给每个谐波一个**随机的、缓慢演化的**初始相位（不要全零）
> 2. 加一层**噪声成分**（滤波后的白噪声，跟随包络）
> 3. 让谐波幅度有**各自的包络**（高次谐波衰减更快）
> 4. 引入**轻微非谐性**（把 $k f_0$ 换成 $k f_0\sqrt{1+Bk^2}$）
>
> **四条全做，加法合成就能听起来像真实乐器。** 这不是玄学，是四个可实现的改动。
> 见 [[谐波与泛音列]]、[[音高感知]]。

## 3. FM 合成 → 相位调制

### 公式，以及"相位"和"频率"的区别

**相位调制（PM）**：

$$y[n] = \sin\!\Big(\underbrace{\phi_c[n]}_{\text{载波相位}} + I \cdot \sin\big(\phi_m[n]\big)\Big)$$

**频率调制（FM）**：

$$f(t) = f_c + \Delta f \sin(2\pi f_m t) \quad\Longrightarrow\quad \phi(t) = 2\pi f_c t + \frac{\Delta f}{f_m}\big(1 - \cos(2\pi f_m t)\big)$$

两者**在数学上可以互相转换**，关系是：

$$\boxed{I = \frac{\Delta f}{f_m}}$$

**但它们的"旋钮语义"完全不同**：

| | 相位调制（PM） | 频率调制（FM） |
|---|---|---|
| 调制深度参数 | 调制指数 $I$ | 频偏 $\Delta f$（Hz） |
| 提高调制器频率 $f_m$ 时 | $I$ 不变 → 音色**保持同一性格**，只是变宽 | $I = \Delta f / f_m$ 下降 → 音色**变简单、变暗** |
| 低 $f_m$ 时 | 正常 | $I = \Delta f/f_m$ 变得极大 → 音色爆炸 |
| 实现 | **累加器直接相加**，无需积分 | 需要对调制信号积分（或除以 $f_m$） |
| 数值稳定性 | 好 | $f_m \to 0$ 时 $\Delta f/f_m \to \infty$ |

> [!important] 所以"FM 合成器"其实都是 PM
> 商业上叫 FM 的合成器，实现上几乎都是**相位调制**。原因就是上表：
> PM 的调制指数与 $f_m$ 无关，所以"亮度"和"音高"是两个独立的旋钮；
> 而真正的 FM 会让这两个旋钮互相干扰，用户根本没法调。
>
> **这就是"数学上等价但实现和音色不同"的准确含义**——
> 等价性只在"给定 $I$ 和 $f_m$、求 $\Delta f$"这个换算关系上成立，
> 而**参数化的方式**决定了这个合成方式好不好用。

```cpp
// 一个最简的两算子 FM（相位调制）实现
struct FmOperator
{
    void prepare (double sr) { sampleRate = sr; phase = 0.0; }

    // phaseMod: 来自调制器的相位偏移（弧度）
    float process (float freqHz, float phaseMod)
    {
        const double inc = 2.0 * double_Pi * (double) freqHz / sampleRate;
        phase += inc;
        if (phase > 2.0 * double_Pi) phase -= 2.0 * double_Pi;   // 防精度损失

        return std::sin ((float) phase + phaseMod);               // ← 注意是 + 不是 ×
    }

    double phase = 0.0, sampleRate = 48000.0;
};

// 载波 + 调制器
float fmSample (float carrierHz, float modHz, float index)
{
    const float mod = modulator.process (modHz, 0.0f);
    return carrier.process (carrierHz, index * mod);   // index 就是调制指数 I
}
```

### 难点：FM 极易混叠

**Carson 带宽法则**：PM 信号的近似带宽是

$$\text{BW} \approx 2(I + 1) f_m$$

原因：PM 会产生**边带**，位于 $f_c \pm n f_m$，幅度由贝塞尔函数 $J_n(I)$ 决定。
$I$ 越大，能量散布到的边带越多。

**后果**：一个 $f_c = 2000$ Hz、$f_m = 1000$ Hz、$I = 10$ 的 FM 音色，
带宽约 $2 \times 11 \times 1000 = 22$ kHz——**已经接近奈奎斯特频率**。
再高一点，边带就折叠回来了。

| 场景 | 混叠风险 |
|---|---|
| 低 $I$、低 $f_m$ | 低 |
| 高 $I$（"金属"音色） | **高** |
| 高 $f_m$（"铃声"音色） | **高** |
| 高音区演奏 | **最高**——基频已经很高，边带立刻越界 |

**解法**：

| 方法 | 说明 |
|---|---|
| 过采样（2×–8×） | 最通用。FM 是**非线性**过程，必然产生新频率成分，所以过采样是必需品 |
| 限制 $I$ 随音高下降 | 高音区自动降低调制指数（很多经典 FM 合成器就是这么做的） |
| 用带限的调制器波形 | 调制器本身如果是锯齿波，它自己的混叠会加倍 |
| 反馈 FM | 算子自我调制会产生**噪声状**的宽带谱——几乎必然混叠，必须过采样 |

> [!warning] FM 的混叠听起来不像"混叠"
> 减法合成的混叠是"沙沙的脏高频"。而 FM 的混叠产生的是**非谐波成分**，
> 听起来像"音不准"、"有奇怪的铃声"、"这个音色很脏但说不上哪脏"。
> **用户不会说"你混叠了"，他会说"这个音色听起来不对"。**
> 见 [[混叠 aliasing]]、[[过采样 oversampling]]。

## 4. 波表合成 → 采样 + 插值 + 抗混叠

**结构**：把**一个周期**的波形存成表格，用一个相位累加器循环读取。

```
相位累加器（phase accumulator）
   ↓  phase += f0 / fs
   ↓  取小数部分
   ↓  乘以表长 → 表内索引
   ↓  插值读出 → 输出
```

**关键洞察**：**表格里存的是"一个周期"，但你播放它的速率决定了基频。**
同一个表，低音播放时它的谐波都在带内；高音播放时，表里那些高次谐波就**超出奈奎斯特频率了**。

### 难点：同一个表不能用于所有音高

假设表里含有 128 个谐波：

| 播放基频 | 第 128 次谐波 | 结果 |
|---|---|---|
| 100 Hz | 12.8 kHz | ✅ 在带内 |
| 500 Hz | 64 kHz | ❌ 远超奈奎斯特 → 混叠 |

**解法：mipmap（多级渐远纹理）思路**

预先计算**同一波形的一组带限版本**，每个版本限制的谐波数不同：

```
mip 0: 完整表（限制到 20 Hz 时所需的谐波数）
mip 1: 限制到  40 Hz 所需的谐波数
mip 2: 限制到  80 Hz 所需的谐波数
...
mip N: 限制到 20 kHz 所需的谐波数（可能只有几个谐波）
```

播放时**根据当前基频选择对应的 mip 层**：

```cpp
// 选择 mip 层：保证最高谐波不超过奈奎斯特频率
// 每一层覆盖一个八度，所以用 log2 索引
int selectMip (float freqHz, double sampleRate)
{
    const float maxHarmonicFreq = (float) (sampleRate * 0.5);
    // 第 k 层保证：最高谐波 <= maxHarmonicFreq
    const float ratio = maxHarmonicFreq / std::max (freqHz, 1.0f);
    const int   mip   = (int) std::floor (std::log2 (std::max (ratio, 1.0f)));
    return std::clamp (mip, 0, numMips - 1);
}
```

> [!important] 这就是图形学里的 mipmap
> 思路完全一样：**为不同的缩放级别预计算不同细节层次的版本，运行时按需选择。**
> 代价是内存（所有层加起来约是单层的 2 倍，因为是几何级数）和**切换时的突变**——
> 跨八度时换层会产生音色跳变，需要**交叉淡化**或让相邻层的差异足够小。

### 插值：决定"干净"还是"毛糙"

| 插值方式 | 质量 | 代价 | 说明 |
|---|---|---|---|
| 无（取最近点） | 很差 | 0 | 严重量化噪声，只在极低要求下用 |
| **线性** | 可用 | 1 次乘法 | **本身是一个低通**——音越高越暗；同时引入少量混叠 |
| **三次（cubic / Hermite）** | 好 | 3–4 次乘法 | 常用默认值 |
| **sinc / 窗化 sinc** | 最好 | 很贵 | 需要多个点；母带级重采样才用 |
| **全通插值** | 幅频平坦 | 中等 | 常用于分数延迟（[[插值]]），但瞬态有 pre-ringing |

> [!warning] 线性插值不是"够用就行"
> 用线性插值读波表，会在**高音区**明显损失高频（因为插值器的频响随频率下降），
> 而且损失的程度**随音高变化**——于是同一个音色在不同音区听起来不一样。
> **用户会说"你这个合成器高音区很闷"。** 这就是原因。
> 至少用三次插值，或者**按音高选择插值方式**（低音区用线性，高音区用三次）。

## 5. 粒子合成 → 窗口化采样 + 重叠相加

**结构**：

```
从源采样中取出很多个短"粒子"（grain）
   ↓ 每个粒子乘以一个窗函数（避免咔哒声）
   ↓ 每个粒子按自己的速率播放（决定音高）
   ↓ 全部叠加（overlap-add）
   ↓ 输出
```

$$\text{out}[n] = \sum_{i} w[n - n_i] \cdot x\big[\,r_i (n - n_i) + p_i\,\big]$$

$w$ = 窗函数，$n_i$ = 第 $i$ 个粒子的起始时刻，$r_i$ = 播放速率（音高），$p_i$ = 读取位置。

### 参数翻译表

| 音乐人拧的旋钮 | 数学符号 | 听感作用 | 工程注意 |
|---|---|---|---|
| **Grain Size（粒子大小）** | 窗长 $L$ | 短（< 20 ms）= 颗粒感、金属感；长（> 100 ms）= 平滑、接近时间拉伸 | 决定了频谱扩散：每个粒子在频域上被展宽约 $1/L$ |
| **Density（密度）** | 每秒粒子数 $D$ | 稀疏 = 听得见单个粒子；密集 = 连续的音墙 | $D \times L$ = 重叠因子。重叠不足会有**振幅起伏（AM）** |
| **Position（位置）** | $p_i$ 的中心 | 在源素材里"扫描" | 必须做**分数延迟**读取，见 [[插值]] |
| **Spray / Jitter（散布）** | $p_i$ 的随机量 | 0 = 干净、有音高；大 = 云雾状、失去音高感 | 随机化位置 → 粒子间**相位不连续** |
| **Pitch / Speed** | $r_i$ | 变调 / 时间拉伸 | $r \ne 1$ 时是**重采样** → 会混叠，见下 |
| **Window Shape** | $w$ | Hann 最平滑；矩形最"硬"（有咔哒声） | 见下 |
| **Stereo Spread** | 每粒子的声像 | 宽度 | 每声道独立随机 → 单声道兼容性下降 |
| **Grain Rate 同步** | $D$ 与 BPM 的关系 | 让颗粒感和节拍对齐 | 需要从宿主取 transport，见 [[延迟与回声的原理]] |

### 窗函数与重叠相加的数学

用 **Hann 窗**，50% 重叠（hop = 窗长的一半）时：

$$w[n] + w\!\left[n + \tfrac{L}{2}\right] = 1.0 \quad \text{（对所有 } n \text{）}$$

即**重叠相加恰好等于 1**，输出幅度恒定，不会起伏。
这是 [[重叠相加 overlap-add]] 里的 COLA（constant overlap-add）条件。

```cpp
// Hann 窗（周期性定义，用于 OLA）
inline float hann (int i, int L)
{
    return 0.5f * (1.0f - std::cos (2.0f * float_Pi * (float) i / (float) L));
}

// 检查你的重叠因子是否满足 COLA
// 重叠因子 = density * grainDuration
// Hann 窗：hop = L/2 时 COLA 成立，此时 overlap factor = 2.0
```

> [!warning] 重叠因子不匹配 → 振幅起伏
> 如果 density 和 grain size 是**独立可调**的，用户就能调出 $D \times L < 1$ 的组合——
> 此时粒子之间有空隙，输出会有**周期性的音量起伏**（频率 = $D$）。
> 当 $D$ 落在音频频段（比如用户设了 50 个粒子/秒）时，你会听到一个 **50 Hz 的嗡声**。
>
> **设计决策**：要么把 density 和 grain size 绑定（保证重叠 ≥ 2），
> 要么在重叠不足时自动补偿增益，要么明确告诉用户这是"颗粒感"特性。

### 为什么粒子合成特别容易出问题

| 问题 | 原因 | 后果 |
|---|---|---|
| **混叠** | 用 $r \ne 1$ 播放粒子 = 重采样；源素材的高频会被折叠 | 高音区"沙沙"声 |
| **混叠（第二来源）** | 粒子窗本身是**快速幅度调制** → 产生边带，边带可以超出奈奎斯特 | 密集粒子时的高频"脏"感 |
| **相位不连续** | 相邻粒子从源素材的**不同位置**取，接缝处相位随机 | 音色"云雾状"，失去音高感（**这通常是特性，不是 bug**） |
| **峰值堆积** | 多个粒子的波峰可能同时出现，重叠相加后的峰值远高于平均电平 | 输出削波。**必须留 headroom 或加限制器** |
| **DC / 低频** | 窗函数不对称或位置随机化引入低频能量 | 需要 DC blocker |
| **CPU** | 每个粒子都要独立的读取 + 窗 + 插值 | 粒子数多时线性增长，是 CPU 大户 |

> [!important] "失去音高感"在粒子合成里是特性
> 位置随机化（spray）破坏了粒子间的相位关系，而**相位关系是音高感知的基础之一**。
> 所以你拧大 spray，声音就从"有音高的音"变成"音云"。
> **这正是粒子合成最独特的音乐价值**——它给你一个"在音高和噪声之间连续移动"的旋钮。
> 见 [[音高感知]]。

## 6. 物理建模 → 波导 / Karplus-Strong

**Karplus-Strong 的核心只有三行**：

```cpp
// 环路：延迟线 + 低通
// N = 采样率 / 基频（延迟线长度）
float karplusStrong (float excitation, float feedback, float damping)
{
    const float delayed = delayLine.read (delaySamples);

    // 环路低通：经典的"两点平均"（一个一阶 FIR 低通）
    const float filtered = 0.5f * (delayed + lastDelayed) * damping;
    lastDelayed = delayed;

    delayLine.write (excitation + filtered);
    return delayed;
}
```

- **延迟线长度** $N$ → 决定**基频**
- **环路低通** → 决定**衰减速度**和**衰减时的亮度变化**
- **激励信号**（一次噪声脉冲 / 拨片噪声） → 决定**起音的性格**

**为什么它"真实"**：因为它模拟的是**物理过程本身**——波在介质中传播、在端点反射、
每次往返损失一点能量（高频损失更多）。真实弦就是这样衰减的。

**这带来三个"免费"的真实感**（其他合成方式需要手动伪造）：

| 现象 | 物理建模里怎么来的 | 其他合成方式 |
|---|---|---|
| **高音衰减更快** | 环路往返更频繁 → 单位时间损失更多能量 | 需要手动为每个音高设不同的包络 |
| **衰减时高频先消失** | 环路低通每次往返都削高频 | 需要手动为每个谐波设包络 |
| **非谐性** | 加入刚度（色散）项，波速随频率变化 | 需要手动把 $k f_0$ 改成 $k f_0\sqrt{1+Bk^2}$ |

> [!important] 这就是"物理建模最真实"的准确含义
> 不是"它的算法更高级"，而是**它的结构里天然包含了真实乐器的因果链**。
> 你调的不是"谐波幅度"，而是"弦的阻尼"和"长度"——**音乐人能理解的物理量**。
> 这也是 [[物理建模]] 页要展开的内容。

### 难点：延迟线长度 ≠ 音高周期

**这是 Karplus-Strong 最常见的实现 bug。**

真实的环路周期 = 延迟线长度 **+ 环路滤波器的相位延迟**：

$$f_0 = \frac{f_s}{N + \phi_{\text{filter}}(f_0)}$$

环路里那个"两点平均"低通在低频处的相位延迟约 **0.5 个采样**。
所以如果你设 $N = f_s / f_0$，实际音高会**偏低**——而且**不同音高偏低的比例不同**。

| 症状 | 原因 | 解法 |
|---|---|---|
| 音不准，且高音偏低更多 | 没补偿环路滤波器的相位延迟 | 用**全通滤波器**调音（allpass tuning filter），或解上述方程求 $N$ |
| 扫阻尼时音高跟着变 | 阻尼改变了环路滤波器的相位延迟 | 同上；调音滤波器必须与阻尼解耦 |
| 高音区音高跳变 | 用整数 $N$ | 用**分数延迟**（见 [[插值]]） |

> [!warning] 这个坑极难自己发现
> 因为你听到的只是"音有点不准"。你可能会去查 MIDI 音高换算、查采样率、查 A4=440 还是 432——
> **全都是对的，问题在环路滤波器的相位延迟上。**
> 验证方法：用 FFT 测实际输出的基频，对比 $f_s / N$。差值就是相位延迟。

### 延伸：数字波导

Karplus-Strong 是**数字波导（digital waveguide）**的最简形式。
完整的波导用**两条延迟线**表示**两个方向传播的波**：

```
        向右传播的波 ──►
   ┌──────────────────────────┐
   │                          │  ← 端点反射（滤波 + 反相）
   └──────────────────────────┘
         ◄── 向左传播的波
```

这个结构可以模拟：管的开孔（在特定位置接一个分支）、吹奏（加入非线性激励）、
鼓面（二维网格）、甚至人声（波导 + 共振峰）。**它是物理建模的通用语言。**

## 7. 噪声与随机

**噪声是合成器的另一半。** 没有噪声，你无法做：气声、镲片、风声、起音的"毛刺"、
以及**抖晃（dither）和去相关**。

### 三种噪声的数学定义

| 类型 | 功率谱密度 | 幅度谱斜率 | 别名 | 听感 |
|---|---|---|---|---|
| **白噪声（white）** | 平坦（$1/f^0$） | 0 dB/oct | — | "嘶——"，明亮、刺耳 |
| **粉噪声（pink）** | $1/f$ | **−3 dB/oct（功率）** | — | "沙——"，平衡、自然 |
| **布朗噪声（brown / red）** | $1/f^2$ | **−6 dB/oct（功率）** | 随机游走 | "轰——"，低沉、像瀑布/雷声 |

> [!warning] −3 dB/oct 说的是功率，不是幅度
> 这是极常见的混淆。**功率**谱密度按 −3 dB/oct 下降，
> 对应的**幅度**谱按 **−1.5 dB/oct** 下降（因为功率 $\propto$ 幅度²）。
> 如果你在代码里按 −3 dB/oct 去衰减幅度，你得到的不是粉噪声，是"更红的噪声"。

### 为什么粉噪声听起来"更自然"

**人耳分析频率的方式是对数的**（临界频带，见[[临界频带与 Bark 尺度]]）——
每个八度占的"听觉空间"大致相同。

- **白噪声**：每个八度的能量**翻倍**。所以最高的那个八度，
  能量等于**它下面所有八度加起来的总和**。听感上就是"只有高频，很刺"。
- **粉噪声**：每个八度的能量**相等**。听感上"每个频段都差不多响" → 平衡、自然。

**这就是"粉噪声更自然"的全部原因**：它不是更"物理"，而是**更匹配听觉的频率分辨率**。

```cpp
// 公共前提：随机数生成器必须是**成员**，在 prepareToPlay 里构造/播种。
// ❌ 不要用 std::random_device（系统调用，会阻塞音频线程）
// ❌ 不要把分布对象写成函数内 static（有初始化检查，且不利于实时性）

// 1. 白噪声：直接取均匀分布
class WhiteNoise
{
public:
    void prepare (std::uint32_t seed) { rng.seed (seed); }
    float process() { return dist (rng); }        // [-1, 1)
private:
    std::mt19937 rng;
    std::uniform_real_distribution<float> dist { -1.0f, 1.0f };
};

// 2. 粉噪声：Voss-McCartney 算法（近似 -3 dB/oct）
//    原理：叠加多行白噪声。第 k 行每 2^k 个采样才更新一次 ——
//    更新越慢的行，能量越集中在低频，加起来就得到近似的 1/f 谱。
class PinkNoise
{
public:
    void prepare (std::uint32_t seed)
    {
        rng.seed (seed);
        rows.fill (0.0f);
        counter = 0;
    }

    float process()
    {
        ++counter;
        // counter 递增时，第 k 位每 2^k 个采样翻转一次。
        // 找到最低的 0 位 → 决定这一采样该更新哪一行。
        std::uint32_t mask = 1;
        int row = 0;
        while (row < numRows - 1 && (counter & mask) != 0) { mask <<= 1; ++row; }
        rows[row] = dist (rng);

        float sum = 0.0f;
        for (float r : rows) sum += r;
        return sum * (1.0f / numRows);       // 归一化
    }

private:
    static constexpr int numRows = 16;
    std::array<float, numRows> rows {};
    std::uint32_t counter = 0;
    std::mt19937 rng;
    std::uniform_real_distribution<float> dist { -1.0f, 1.0f };
};

// 3. 布朗噪声：对白噪声做有泄漏的积分（漏积分器）
class BrownNoise
{
public:
    void prepare (std::uint32_t seed) { white.prepare (seed); state = 0.0f; }

    float process()
    {
        // leak 略小于 1：防止直流漂移无限累积（否则会慢慢跑到满刻度）
        state = 0.99f * state + 0.05f * white.process();
        return state * 4.0f;                  // 补偿幅度损失
    }
private:
    WhiteNoise white;
    float state = 0.0f;
};
```

> [!note] 一个更省 CPU 的粉噪声做法
> 用白噪声过一个近似 −3 dB/oct 的**滤波器**（几个极零点的组合），
> 比 Voss-McCartney 更便宜，但精度略差。
> 网上流传的系数版本很多，**请自己用 FFT 测一遍频谱斜率再采用**——
> 这是"不要照抄"的典型场景，因为不同版本的归一化和精度差别很大。
> 验证方法见文末「怎么验证」。

### 音乐用途

| 噪声 | 用途 |
|---|---|
| 白噪声 | 镲片 / 军鼓的"沙"成分；**抖动（dither）**；测试信号（测频响、测混响 IR） |
| 粉噪声 | **混响 / 空间感的参考信号**；风的底噪；"自然的"背景层；测房间声学 |
| 布朗噪声 | 雷声、瀑布、低频隆隆声；电影音效；**LFO 的随机源** |
| 采样保持随机（S&H） | 阶梯状的随机 LFO → "随机步进"的调制感 |
| 平滑随机（interpolated random） | 缓慢漂移 → 模拟"元件容差"、模拟味 |

> [!tip] 噪声是"模拟味"的廉价来源
> [[从音乐制作人到插件开发者]] 里说"很模拟 = 轻微噪声 + 偶次谐波 + 元件容差"。
> **具体做法**：在反馈环或增益级里加入**极低电平**（−90 dB 量级）的噪声。
> 它有三个作用：① 听感上"活"了 ② 打破数字的完美静音 ③ **顺便解决 denormal 问题**
> （见 [[denormal 数处理]]）。**一个操作解决三个问题。**

## 8. 包络与 LFO

### ADSR：线性 vs 指数

**线性包络**：每段是直线斜坡。

**指数包络**：每段是一阶低通的充放电曲线。

$$y(t) = y_{\text{target}} + (y_{\text{start}} - y_{\text{target}}) \cdot e^{-t/\tau}$$

> [!important] 为什么模拟包络是指数的
> 因为模拟包络就是**RC 电路**：一个电容通过一个电阻充放电。
> 电容电压天然服从上式。**这不是设计选择，是物理必然。**
>
> 所以"模拟味包络" = "指数包络"，而且**上升段也是指数的**（线性包络的上升段是直线）。

**哪个更好听？** 对**幅度**而言，指数更自然，原因是：
- 指数衰减在**幅度**上是指数，在 **dB** 上是**直线** → 符合听感上的"均匀衰减"
- 真实乐器的自然衰减（拨弦、击键）都是指数衰减

```cpp
// 线性 ADSR（简单，但"数字味"）
// 每段用固定增量推进

// 指数 ADSR：用一阶低通 + 过冲目标
// 关键技巧：内部目标值要**超过**最终值，才能在指定时间内到达
class ExpEnvelope
{
public:
    void prepare (double sr) { sampleRate = (float) sr; }

    // 启动一段：从 start 到 final，用时 timeSec
    void startSegment (float start, float final, float timeSec, float curve)
    {
        current = start;
        // 一阶低通的时间常数
        const float tau = timeSec / curve;              // curve ≈ 4.6 时接近"4.6τ 到达"
        coeff = 1.0f - std::exp (-1.0f / (sampleRate * tau));

        // 计算"过冲目标"，使 y 在 timeSec 后恰好等于 final
        // y(t) = target + (start - target) * k,  k = exp(-T/tau)
        const float k = std::exp (-timeSec / tau);
        target = (k < 0.9999f) ? (final - k * start) / (1.0f - k) : final;
    }

    float next()
    {
        current += (target - current) * coeff;
        return current;
    }

private:
    float current = 0.0f, target = 0.0f, coeff = 0.01f, sampleRate = 48000.0f;
};
```

> [!warning] 指数包络的"永远到不了"
> 一阶低通**永远不会精确等于**目标值。上面的"过冲目标"技巧解决了这个问题，
> 但引入了另一个问题：**极短的包络时间（比如 0.1 ms）会让过冲目标变得极大**，
> 数值上可能溢出或产生爆音。
> **做法**：给时间设下限（比如 0.5 ms），并钳制 `target` 的范围。

### 包络的常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 松键后有"咔"声 | release 太短，波形被突然截断 | release 下限设 5–20 ms |
| 连奏时前后音符"叠"在一起 | 没有做 voice stealing / 包络重触发 | 见 [[MOC - DSP]] 复音管理 |
| 快速连奏时有爆音 | 新音符在旧音符的包络非零处开始 | 包络**重触发**时从当前值开始，不要从 0 跳 |
| 包络有"阶梯" | 每个 block 只更新一次 | 每采样更新，或 block 内插值 |
| 短包络听起来比设定的长 | 一阶低通的时间常数定义 | 用上面"过冲目标"的技巧，或改 UI 标注 |

### LFO：波形、速率、相位

| LFO 波形 | 调制什么 | 典型用途 |
|---|---|---|
| 正弦 | 平滑、无棱角 | vibrato、滤波扫频、混响去相关 |
| 三角 | 线性升降，比正弦"更均匀" | 音高调制、tremolo |
| 锯齿（上/下） | 单向扫描，有跳变 | 节奏性的上升/下降 |
| 方波 | 只有两个状态 | trill、八度跳变、硬切换 |
| 采样保持（S&H） | 阶梯随机 | "随机步进"，复古感 |
| 平滑随机 | 缓慢漂移 | 模拟漂移、自然感、**去相关** |

**速率范围的经验划分**：

| 速率 | 名称 | 听感 |
|---|---|---|
| < 0.1 Hz | 超慢 | 听成"参数慢慢变了"，不是"调制" |
| 0.1–5 Hz | 慢 | vibrato 的下限、混响的"活"感 |
| 5–8 Hz | 中 | **vibrato 的常用区**（人声、弦乐） |
| 8–20 Hz | 快 | tremolo、音高抖动（flutter） |
| > 20 Hz | 音频速率 | 进入"调制产生新边带"的领域 → 变成 FM/AM 音色 |

> [!important] LFO 相位在多声道里是"宽度旋钮"
> 如果左右声道用**同一个** LFO（相位相同），声像不会变。
> 如果左右用**相位差 90°–180°** 的 LFO，声音会变宽。
> 这就是 chorus 变宽的原理（见 [[调制效果]]、[[拍频与失谐]]）。
>
> **但代价是单声道兼容性**——见 [[立体声感知]]。
> **设计决策**：给用户一个"stereo width"参数，默认不要拉满。

> [!warning] LFO 不能直接加到参数上（除非你确定）
> 如果 LFO 直接改变延迟时间或滤波器系数，会产生**参数跳变**问题。
> - 加到**延迟时间**上 → 故意要的多普勒（chorus 就是靠这个）
> - 加到**滤波器系数**上 → 需要每采样更新系数，否则有"阶梯感"
> - 加到**增益**上 → 相对安全
>
> 见 [[参数平滑 parameter smoothing]]。

## 总表：合成方式 → DSP 拓扑 → 难点 → 合成器类型

| 合成方式 | 核心 DSP 结构 | 主要难点 | 你熟悉的那类合成器 |
|---|---|---|---|
| **减法** | 振荡器 + 滤波器 + 包络 | **抗混叠振荡器**；模拟滤波器的非线性与 ZDF 拓扑 | 经典模拟建模合成器、模块合成器 |
| **加法** | N 个正弦（或逆 FFT）+ 每谐波包络 | 计算成本；**"电子味"来自缺失的噪声/时变/非谐性** | 经典加法合成器、谐波编辑器 |
| **FM / PM** | 相位累加器 + 算子串联/并联 | **必然混叠**（边带随 $I$ 展宽）；调制指数随音高的管理 | 经典 FM 合成器、算子式合成器 |
| **波表** | 单周期表 + 相位累加器 + mipmap + 插值 | 每个音高需要不同的带限版本；插值质量随音高变化 | 波表合成器、扫描式合成器 |
| **粒子** | 加窗采样 + 重叠相加 + 随机化 | **混叠（重采样 + 快速幅度调制）**；相位不连续；峰值堆积 | 粒子合成器、音云/纹理工具 |
| **物理建模** | 延迟线 + 环路滤波（+ 非线性激励） | **环路相位延迟导致音高不准**；环路稳定性；激励建模 | Karplus-Strong 类、波导类、物理建模合成器 |
| **采样回放** | 采样 + 变调重采样 + 包络 | 重采样抗混叠；多采样层（velocity layer）的组织 | 采样器、rompler |
| **相位失真 / 其他** | 波形整形 + 滤波 | 非线性必然混叠（同 FM） | 相位失真合成器 |
| **噪声源** | 随机数 + 滤波 | 频谱斜率要**实测**验证；随机数质量 | 所有合成器的公共部件 |
| **包络 / LFO** | 一阶低通 / 相位累加器 / 查表 | 指数到达时间；LFO 相位与多声道；调制目标的选择 | 所有合成器的公共部件 |

> [!note] 关于这张表
> 它是**结构映射**，不是分类学。真实的合成器都是混合的——
> 一个"波表合成器"里也有滤波器（减法）和包络；一个"物理建模"引擎里也有噪声激励。
> **表的用法是**：当你要做一个音色时，先问"这个声音的**核心结构**是什么"，
> 然后去查对应的"主要难点"那一列——**那就是你会撞上的墙。**

## 常见坑（跨合成方式）

| 症状 | 原因 | 解法 |
|---|---|---|
| 高音区"沙沙"的脏高频 | 混叠（振荡器 / FM 边带 / 重采样） | 过采样 / BLEP / mipmap；见 [[混叠 aliasing]] |
| 同一个音色在不同音区不一样 | 插值质量随音高变化；或 mipmap 切换没淡化 | 用三次插值；mipmap 层间交叉淡化 |
| 扫截止频率时有"阶梯感" | 滤波器系数每 block 只更新一次 | 每采样更新，或用 [[状态变量滤波器 SVF]] |
| 滤波器扫频时音高会偏 | 朴素 ladder 实现的单位延迟 | ZDF / TPT 拓扑；见 [[虚拟模拟滤波器]] |
| Karplus-Strong 音不准 | 环路滤波器相位延迟未补偿 | 全通调音滤波器；见 §6 |
| 粒子合成输出削波 | 粒子峰值堆积 | 留 headroom、加限制器、按重叠因子补偿增益 |
| 粒子稀疏时有"嗡"声 | 重叠不足，密度本身成了音频速率 AM | 绑定 density 与 grain size，保证重叠 ≥ 2 |
| 包络松键时"咔" | release 太短 | release 下限 5–20 ms |
| 快速连奏爆音 | 包络重触发从 0 开始 | 从当前值重触发 |
| 粉噪声听起来不对 | 把 −3 dB/oct 当成了幅度斜率 | 功率 −3 dB/oct = 幅度 −1.5 dB/oct |
| 噪声在静音时 CPU 高 | 随机数生成器太贵（如 `std::random_device`） | 用 `std::mt19937` + 分布对象，**在 `prepareToPlay` 里构造** |
| 音频线程里分配内存 | 每次音符触发 `new` 一个 voice | 预分配 voice pool；见 [[实时音频线程契约]] |
| 静音后 CPU 飙升 | 反馈环路的 denormal | 见 [[denormal 数处理]] |
| 立体声变宽后 mono 塌掉 | LFO 左右相位差过大 | 提供 width 参数；检查 mono 兼容性 |

> [!warning] 最后三条是"合成器插件崩溃/卡顿"的常见真凶
> 它们和合成算法完全无关，但会让你的插件在用户机器上不能用。
> **音频线程契约适用于所有插件，合成器尤其容易违反**——因为合成器有"事件"（音符开/关），
> 而事件最容易诱导你在音频线程里做分配。

## 怎么验证

### 听感测试

1. **混叠测试**：把所有调制关掉，从最低音滑到最高音。
   **高音区不应该出现"沙沙"的、和基频不成谐波关系的成分。**
   把音高固定在高音区，用 FFT 看有没有非谐波峰。
2. **扫频测试**：滤波器截止频率从 20 Hz 扫到 20 kHz，同时播放一个持续音。
   应该听到**平滑**的扫频，没有"台阶"、没有"咔咔"声。
3. **音准测试**：弹一个八度内的所有半音，用调音器逐个测。
   **Karplus-Strong 和 FM 音色最容易在这里出问题。**
4. **包络测试**：把 attack 和 release 都设到最短，快速连奏。
   不应该有"咔"声或爆音。
5. **粒子测试**：把 density 拧到最低，应该听到**清晰的单个粒子**；
   拧到最高，应该是**连续的音墙**，没有音量起伏（如果有 → 重叠因子问题）。

### 数值测试

```cpp
// 测试 1：振荡器抗混叠 —— 最重要的一个
// 生成一个高音（如 5 kHz 锯齿），做 FFT
// 断言：所有非谐波峰（不属于 k*f0 的峰）都比基频低 > 60 dB
// 这是唯一能客观判断"抗混叠做对了没"的方法

// 测试 2：调音精度
// 生成每个 MIDI 音符，用 FFT 测基频（或用自相关）
// 断言：|实测 - 理论| / 理论 < 0.1%（约 1.7 cent）
// 这一条能抓出 Karplus-Strong 的相位延迟 bug

// 测试 3：噪声频谱斜率
// 生成 10 秒粉噪声，做长 FFT（或 Welch 平均）
// 断言：在 20 Hz - 20 kHz 范围内，功率谱按 -3 dB/oct 下降（±0.5 dB/oct）
// 白噪声：0 dB/oct（±0.2）
// 布朗噪声：-6 dB/oct（±0.5）

// 测试 4：重叠相加的 COLA 条件
// 对 Hann 窗，hop = L/2
// 断言：对任意 n，所有覆盖 n 的窗之和 == 1.0（±1e-6）
// 这一条能在写粒子引擎之前就验证你的窗函数定义对不对

// 测试 5：包络到达时间
// 触发一个 attack = 100 ms 的包络
// 断言：包络达到最终值的 99% 所用的时间在 100 ms ± 10% 内

// 测试 6：稳定性（物理建模 / 反馈结构）
// 喂一个脉冲，跑 10 秒
// 断言：输出不发散（max |y| 有界），且最终衰减到 < -80 dBFS
```

> [!tip] 测试 1 和 2 是合成器开发的两根支柱
> - **测试 1（抗混叠）** 决定了你的合成器"听起来专不专业"
> - **测试 2（音准）** 决定了它"能不能用"
>
> 这两条都是**自动化可测的**，而且都能在几秒内跑完。
> 先写这两个测试，再写振荡器。见 [[AI 生成音频测试]]。
