# Biquad 滤波器

> [!note] 一句话
> **二阶 IIR 滤波器**。音频里 90% 的 EQ、滤波器、音色塑形都是它。
> 叫 "biquad" 是因为它的传递函数是**双二次**（两个二次多项式之比）。

## 为什么它这么重要

- 一个 biquad 提供 **2 个极点 + 2 个零点** → 足够做出低通、高通、带通、峰值、搁架
- 更高阶的滤波器（4 阶、8 阶）**级联多个 biquad** 即可
- 计算量极小：每个采样 5 次乘法 + 4 次加法
- 数值行为可控，稳定条件明确

> [!important] 你的经验对应
> 你在 EQ 上拧的 **Freq / Q / Gain**，就是 biquad 的三个参数。
> "Q 值高了会 ringing"——那是极点在靠近单位圆。
> "这个 EQ 扫频有颗粒感"——那是系数更新不平滑，见 [[参数平滑 parameter smoothing]]。

## 差分方程

```
y[n] = b0·x[n] + b1·x[n-1] + b2·x[n-2] - a1·y[n-1] - a2·y[n-2]
```

传递函数：

$$H(z) = \frac{b_0 + b_1 z^{-1} + b_2 z^{-2}}{1 + a_1 z^{-1} + a_2 z^{-2}}$$

> [!warning] 符号约定不统一
> 有的书用 `+a1·y[n-1]`，有的用 `-a1·y[n-1]`。
> **抄公式前先确认符号约定**，否则你会得到一个发散（爆炸）的滤波器。
> 本页统一用上式（分母系数带负号进差分方程）。

## 直接 I 型实现（最直白）

```cpp
class Biquad
{
public:
    void reset() { x1 = x2 = y1 = y2 = 0.0f; }

    void setCoeffs (float nb0, float nb1, float nb2, float na1, float na2)
    {
        b0 = nb0; b1 = nb1; b2 = nb2; a1 = na1; a2 = na2;
    }

    float process (float x)
    {
        const float y = b0*x + b1*x1 + b2*x2 - a1*y1 - a2*y2;
        x2 = x1; x1 = x;
        y2 = y1; y1 = y;
        return y;
    }

private:
    float b0 = 1, b1 = 0, b2 = 0, a1 = 0, a2 = 0;
    float x1 = 0, x2 = 0, y1 = 0, y2 = 0;
};
```

> [!tip] 性能优化（后面再说）
> 音频里通常把 `b` 系数**归一化**（除以 a0），然后用 **Direct Form II Transposed**：
> 状态变量少 2 个，数值性能更好，且便于 SIMD。
> 但**先用 Direct Form I 把逻辑跑通**，别一上来就优化。

## 系数怎么算（RBJ Cookbook）

Robert Bristow-Johnson 的 "Audio EQ Cookbook" 是行业标准参考。
下面给出**核心公式**，其中：

```
ω = 2π · f0 / fs        （角频率）
α = sin(ω) / (2·Q)      （Q 定义）
```

> [!note] α 的三种定义
> `α = sin(ω)/(2Q)` 是最常用的。
> 也有用带宽（BW）或斜率（S）定义的版本，用于搁架滤波器。
> **不同定义给出不同的曲线形状**——这是"为什么两个 EQ 听起来不一样"的原因之一。

### 归一化系数

```
a0 = 1 + α
a1 = -2·cos(ω) / a0
a2 = (1 - α) / a0
```

### Lowpass

```
b0 = (1 - cos(ω)) / 2 / a0
b1 = (1 - cos(ω))     / a0
b2 = (1 - cos(ω)) / 2 / a0
```

### Highpass

```
b0 =  (1 + cos(ω)) / 2 / a0
b1 = -(1 + cos(ω))     / a0
b2 =  (1 + cos(ω)) / 2 / a0
```

### Peaking EQ（EQ 里最常用的）

```
A  = 10^(dBgain / 40)

b0 = (1 + α·A) / a0
b1 = (-2·cos(ω)) / a0
b2 = (1 - α·A) / a0
```

> [!warning] `A` 用 dBgain/40，不是 /20
> 因为它是**幅度平方**意义下的增益。
> 写成 `/20` 是一个极常见的 bug——滤波器的实际增益会是你想要的两倍（dB）。
> **验证方法**：设 dBgain = 6，在中心频率处测增益，应该正好是 +6 dB。

### 其他类型

- **Low shelf / High shelf**：见 Cookbook 原文
- **Bandpass / Notch / Allpass**：见 Cookbook 原文
- **Linkwitz-Riley（LR4）**：两个 Butterworth biquad 级联，用于分频

> [!tip] 不要背公式
> **记不住是正常的。** 把 RBJ Cookbook 存进 `10-Sources/standards/`，
> 需要时查。真正要记住的是：
> 1. `ω = 2πf/fs`
> 2. `α` 控制带宽
> 3. `cos(ω)` 决定中心频率
> 4. 系数必须归一化（除以 a0）

## 稳定性

极点必须在单位圆内。对二阶系统：

```
|a2| < 1        且        |a1| < 1 + a2
```

> [!warning] 参数极端值会让滤波器爆炸
> - `f0` 接近 0 或 `fs/2` 时，`cos(ω)` 逼近 ±1，可能失稳
> - `Q` 极大（如 100+）时，α 极小，极点贴近单位圆，ringing 极长
> - `f0 > fs/2` 时公式直接失效（混叠）
>
> **必须钳制参数范围**。这是插件里最常见的"用户调出爆炸声"的原因。

```cpp
f0 = std::clamp (f0, 20.0f, sampleRate * 0.45f);   // 留余量
Q  = std::clamp (Q, 0.1f, 20.0f);
```

## 常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 滤波器"爆炸"（输出发散到 inf/nan） | 参数超范围、系数未归一化、符号约定错 | 钳制参数；检查 a0 除法 |
| 扫频有"阶梯感" | 系数每 block 只更新一次 | 每 sample 或每 32 samples 更新，见 [[参数平滑 parameter smoothing]] |
| 高频有"沙沙"声 | 系数突变导致的状态不连续 | 平滑参数而非系数 |
| 静音时 CPU 飙升 | denormal 数 | 见 [[denormal 数处理]] |
| 低频听起来"糊" | 高通滤波器的相位失真 | 用线性相位 FIR，或接受它 |
| 改变参数时有"咔哒"声 | 系数跳变 | 平滑频率/Q，不是平滑系数 |
| 立体声左右不一致 | 两个声道共用一个滤波器状态 | **每个声道独立的滤波器实例** |

> [!warning] 最后一个坑最隐蔽
> 立体声处理时，如果左右声道共用一组 `x1/x2/y1/y2`，
> 会产生**串音**和不可预测的行为。
> **一个声道一个 Biquad 对象**，别图省事。

## 怎么验证你的实现是对的

> [!tip] 三个必做的测试
> 1. **脉冲响应**：喂一个单位脉冲，输出应该衰减到 0（稳定）
> 2. **频率响应**：喂对数扫频，用 FFT 看幅频曲线是否符合预期（低通应该 -12dB/oct）
> 3. **直流增益**：喂直流 1.0，低通输出应为 1.0，高通输出应为 0.0

这三个测试应该写成自动化脚本，放在 `50-Playground/tools/`。
**这是 AI 最适合帮你写的部分**——见 [[AI 生成音频测试]]。

## AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **`A = 10^(dB/20)`**（应为 `/40`） | 实际增益**翻倍**（dB） | 设 dBgain=6，测中心频率增益应正好 +6 dB |
| 2 | **忘了除以 a0 归一化** | 增益不对、可能发散 | 检查所有系数是否都除以了 a0 |
| 3 | **差分方程符号约定混用** | 滤波器发散（爆炸） | 分母系数在差分方程里是**减号** |
| 4 | **α 用错定义**（Q / BW / S 混用） | 曲线形状不对 | 见 [[RBJ Audio EQ Cookbook]] |
| 5 | **参数不钳制** | 用户能调出爆炸 | 检查 `f0 < fs*0.45`、`Q` 有上限 |
| 6 | **在构造函数里算系数** | 采样率还没确定 → 错 | 必须在 `prepareToPlay` 里算 |
| 7 | **每 block 只更新一次系数** | 扫频有"阶梯感" | 每 sample 或每 32 samples 更新 |
| 8 | **直接平滑系数** | 中间状态可能不稳定 | 平滑**参数**（f0、Q），不是系数 |
| 9 | **立体声左右共用一个 Biquad** | 串音、行为异常 | 每声道独立实例 |
| 10 | **反馈路径无 denormal 处理** | 安静时 CPU 飙升 | 见 [[denormal 数处理]] |

> [!tip] 最快的一次核对
> 让 AI 写完 Biquad 后，**先做这三个测试**：
> 1. 脉冲响应是否衰减到 0（稳定性）
> 2. 直流增益是否符合预期（低通=1，高通=0）
> 3. 截止频率处是否 -3 dB（Q=0.707 时）
>
> 三个都过，再谈听感。**本库的 `exp-002` 做到了 0.0021 dB 的精度。**
