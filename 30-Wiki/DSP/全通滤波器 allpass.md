# 全通滤波器 allpass

> [!important] 一句话
> **全通滤波器对所有频率的幅度增益恒为 1，只改变相位。**
> "不染色但改变时间特性"——这使它成为混响扩散器、分数延迟、相位对齐的核心构件。

## 为什么这一页重要

| 用途 | 依赖全通的哪个性质 |
|---|---|
| **混响扩散器** | 幅度平坦 → 串联任意多个都不染色 |
| **分数延迟** | 幅度平坦 → 延迟不改变音色（见 [[插值]]） |
| **相位对齐** | 可以把某个频段的相位"转"过去 |
| **IIR 相位补偿** | 抵消另一滤波器的相位失真 |

> [!tip] 核心心智模型
> 普通滤波器改变"**多少**"（幅度），全通改变"**什么时候**"（相位/时间）。
> 两者独立——你可以要其中一个而不要另一个。

---

## 一、实测验证：幅度恒为 1

一阶全通的传递函数：

$$H(z) = \frac{g + z^{-1}}{1 + g\,z^{-1}}$$

**实测**（48kHz，四种 g 值，六个频点）：

| g | 20 Hz | 100 Hz | 1 kHz | 5 kHz | 10 kHz | 20 kHz |
|---|---|---|---|---|---|---|
| 0.5 | 1.0000 | 1.0000 | 1.0000 | 1.0000 | 1.0000 | 1.0000 |
| 0.7 | 1.0000 | 1.0000 | 1.0000 | 1.0000 | 1.0000 | 1.0000 |
| 0.9 | 1.0000 | 1.0000 | 1.0000 | 1.0000 | 1.0000 | 1.0000 |
| -0.5 | 1.0000 | 1.0000 | 1.0000 | 1.0000 | 1.0000 | 1.0000 |

> [!important] 这就是"全通"的全部含义
> **无论 g 是多少、频率是多少，幅度都是 1。**
> 它改变的一切都在**相位**里。

**为什么数学上必然如此**：分子和分母是"镜像多项式"——
分子的根（零点）在 $z = -1/g$，分母的根（极点）在 $z = -g$。
两者互为倒数：$|z_{zero}| \cdot |z_{pole}| = 1$。
倒数位置的一对零极点，幅度贡献恰好抵消。

## 二、两种全通（别混淆）

### 1. 一阶全通（分数延迟用）

$$H(z) = \frac{g + z^{-1}}{1 + g\,z^{-1}}, \qquad g = \frac{1-\phi}{1+\phi}$$

- **1 个采样以内**的分数延迟
- 用于 [[插值]]（替代线性插值）
- ⚠️ $\phi \to 0$ 时 $g \to 1$，极点趋于单位圆 → **不稳定**，需切换保护

### 2. Schroeder 全通（混响扩散器用）

$$y[n] = -g\,x[n] + x[n-D] + g\,y[n-D]$$

$$H(z) = \frac{-g + z^{-D}}{1 - g\,z^{-D}}$$

- **D 个采样**的延迟（D 通常是几毫秒）
- 用于 [[Schroeder 混响]] 的扩散级
- D 越大、g 越大 → 回声越"糊"

> [!warning] 两者的 g 含义不同
> 一阶全通的 g 控制的是**分数延迟位置**；
> Schroeder 全通的 g 控制的是**回声衰减速度**。
> **同一个字母，两回事。** 抄公式前先确认是哪一种。

## 三、实现

```cpp
// Schroeder 全通（混响扩散器用）
class Allpass
{
public:
    void prepare (int sizeSamples, float feedback)
    {
        buffer.assign ((size_t) sizeSamples, 0.0f);
        idx = 0;
        g = feedback;                     // 典型值 0.5 ~ 0.7
    }

    float process (float x)
    {
        const float bufOut = buffer[(size_t) idx];   // 这是上一轮的 y[n-D]
        const float y = -g * x + bufOut;             // 前馈(-g·x) + 延迟项
        buffer[(size_t) idx] = x + g * y;            // ⚠️ 存的是 x + g·y（用输出！）
        if (++idx >= (int) buffer.size()) idx = 0;
        return y;
    }

private:
    std::vector<float> buffer;
    int idx = 0;
    float g = 0.5f;
};
```

```python
# Python 参考实现（用于验证 C++ 版本）
def allpass(x, D, g):
    buf = [0.0] * D
    idx = 0
    y = [0.0] * len(x)
    for n in range(len(x)):
        bufOut = buf[idx]              # 上一轮的 y[n-D]
        y[n] = -g * x[n] + bufOut
        buf[idx] = x[n] + g * y[n]     # ⚠️ 存 x + g·y（用输出）
        idx = (idx + 1) % D
    return y
```

## 四、在混响里怎么用

### Schroeder 结构里的位置

```
输入 → [梳状1] ┐
       [梳状2] ├→ Σ → [全通1] → [全通2] → 输出
       [梳状3] │      ↑ 只在这里串联
       [梳状4] ┘
```

**为什么串联全通而不是别的**：

| 性质 | 全通 | 普通滤波器 |
|---|---|---|
| 改变回声密度 | ✅（靠相位旋转） | ✅ |
| 染色（改频响） | ❌ **不会** | ✅ 会 |
| 能串联很多级 | ✅ 可以 | ❌ 频响会失控 |

### Luff 的改进：不用 IIR 全通

[[Luff - Let's Write A Reverb]] 指出串联 Schroeder 全通的问题：

> "确实扩散了，但**带有轻微的金属边缘**。"

他的替代方案：用**无反馈**的多声道构件（延迟 → 置换 → Hadamard 矩阵）串联。
优点：没有反馈 → 不会发散；金属味更少。见 [[反馈延迟网络 FDN]]。

> [!tip] 什么时候还用 Schroeder 全通
> - 单声道混响、CPU 极紧
> - 需要经典"plate"味道
> - 教学目的（理解扩散的原理）
>
> 多声道场景优先考虑 Luff 的方案。

## 五、参数与听感

| 参数 | 典型范围 | 太小 | 太大 |
|---|---|---|---|
| 延迟 D | 1–50 ms | 扩散不足，听得出回声 | 尾巴出现可闻的"重复感" |
| 反馈 g | 0.3–0.7 | 扩散很快但很浅 | 相位旋转过度，"镶边"感 |

**Freeverb 的取值**：4 个全通，延迟 556/441/341/225 样本，g = 0.5。

> [!note] 为什么 g=0.5 是常见默认
> g 越大，单个全通引入的"相位摆动"越大，扩散越快，
> 但过多的级联高 g 全通会产生可闻的金属 ringing。
> **0.5 是"够糊且不难听"的经验平衡点。**

## 六、AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **把一阶全通和 Schroeder 全通的公式混用** | 延迟时间错、扩散行为错 | 确认 D 是多少（1 还是几毫秒） |
| 2 | **前馈系数符号写错**（`+g·x` 而非 `-g·x`） | 不是全通了，会染色 | **实测幅度是否恒为 1** |
| 3 | **g 接近 1 不保护**（一阶全通） | 极点在单位圆上 → 自激 | 检查 frac 很小时是否切换 |
| 4 | **忘记缓冲区取模** | 越界崩溃 | 同 [[延迟线 delay line]] 的负数取模陷阱 |
| 5 | **串联时共用缓冲区** | 级与级互相干扰 | 每级独立的 Allpass 实例 |
| 6 | **在音频线程分配** | 违反实时契约 | prepare 里分配 |
| 7 | **以为全通"没有声音变化"就忽略它** | 混响尾巴不对 | 全通影响的是**时间结构**，听感上是"糊"和"密" |

> [!danger] 本页的 C++ 实现曾经就有这个 bug（2026-10-14 抓到）
> 我最初把缓冲区更新写成了 `buffer[idx] = x + g * bufOut`（用了**读出值**），
> 而正确是 `buffer[idx] = x + g * y`（用**输出值**）。
>
> 实测后果（g=0.7）：1kHz 处增益 **2.49 倍**（理论 2.63 倍）——
> 不是全通了，而是个会谐振的滤波器。**它能跑、能出声、扩散也有效果**，
> 凭耳朵根本发现不了。
>
> 抓住它的正是"幅度恒为 1"这个断言。**这就是为什么每页都要有「怎么验证」。**

> [!warning] 第 2 条最常见也最隐蔽
> 全通的**定义**就要求前馈系数是 **-g**。
> 写成 +g 之后，幅度不再恒为 1，滤波器变成一个普通的梳状滤波器——
> **但它仍然能跑、仍然出声**，只是混响听起来"有点染色"。
> 你很难凭耳朵发现，**必须实测幅度**。

## 七、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 串联后声音变色 | 前馈符号写错，不是全通了 | 实测 |H(f)| 是否恒为 1 |
| 扩散不足 | D 太短或 g 太小 | 加大 D 或 g |
| 有金属 ringing | g 太大或级数太多 | 降 g，或改用多声道扩散器 |
| 自激 | 一阶全通 frac→0 没保护 | 切换到整数读取 |
| 尾巴有周期性 | 单个全通 D 固定 | 多级不同 D，或加调制 |
| 安静时 CPU 飙升 | denormal | 见 [[denormal 数处理]] |

## 八、怎么验证

| 测试 | 方法 | 期望 |
|---|---|---|
| **幅度恒为 1** | 喂扫频，FFT 看频谱 | 全频段 0 dB（±0.01 dB） |
| **稳定性** | 喂脉冲跑 10 秒 | 衰减到 0 |
| **相位在变** | 对比输入输出的过零点 | 不同频率偏移不同 |
| **扩散有效** | 喝脉冲，看回声密度 | 级联后回声明显变密 |

```python
import numpy as np
def ap1_mag(f, g, fs=48000):
    w = 2*np.pi*f/fs
    return abs((g + np.exp(-1j*w))/(1 + g*np.exp(-1j*w)))

# 全频段验证（这就是全通的定义）
for g in [0.5, 0.9, -0.5]:
    mags = [ap1_mag(f, g) for f in [20,100,1000,5000,10000,20000]]
    assert max(abs(m-1) for m in mags) < 1e-12, f"g={g} 不是全通！"
print("✅ 幅度恒为 1，是真全通")
```

> [!tip] 这一行断言就能抓住 AI 的符号错误
> 如果 AI 把前馈写成了 +g，这个断言立刻失败。
> **比听感可靠得多。**
