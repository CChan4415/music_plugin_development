# 音频回归测试

> [!important] 一句话
> **回归测试 = 把"已知正确的输出"存下来，以后每次改动都比对。**
> 它的价值不在"验证现在对不对"，而在**"发现改动破坏了什么"**。

## 为什么音频特别需要回归测试

| 音频开发的现实 | 后果 |
|---|---|
| 改一行 DSP 代码，"听起来差不多" | 但可能真的变了（6 dB 那种） |
| 优化性能时重构 | 数值行为可能微妙改变 |
| 多个参数组合 | 不可能手动全测 |
| bug 修复后再次引入 | 没有测试就会重犯 |

> [!danger] 本库的真实案例
> 优化 `spectrum()` 时**无意中改掉了相干增益补偿**，
> 导致所有幅度测量**差 6.02 dB**——而这是个"看起来完全合理"的数字，
> 藏了好几天才被发现。
>
> 如果有回归测试，一秒就能发现。
> 见 [[2026-10-14 测量工具会骗你 —— 十一次踩坑记录]]。

## 一、三种回归测试

| 类型 | 判据 | 用途 |
|---|---|---|
| **Bit-exact** | 逐位相同 | 同平台内重构/优化 |
| **数值容差** | 差异 < X dB | 跨平台、跨编译器 |
| **性质回归** | 数学性质不变 | 最稳健（推荐） |

> [!important] 优先用"性质回归"
> **性质测试不怕实现变化。**
> 比如"直流增益必须为 1"——无论你怎么重构，它都成立。
>
> 而 bit-exact 测试会因为无关的改动（如换个求和顺序）而失败，
> 让你花时间在无意义的"修正"上。

## 二、性质回归：存基线指标

**思路**：不存原始音频，而是存**指标**（更小、更稳定、更可读）。

```python
import json
import numpy as np

def compute_metrics (b, a, sr=48000.0):
    """从滤波器系数算出一组稳定的指标"""
    # 脉冲响应
    n = 1 << 14
    y = np.zeros(n); x = np.zeros(n); x[0] = 1.0
    for i in range(n):
        acc  = sum (b[k]*x[i-k] for k in range(len(b)) if i-k >= 0)
        acc -= sum (a[k]*y[i-k] for k in range(1,len(a)) if i-k >= 0)
        y[i] = acc

    H = np.abs (np.fft.rfft (y)); f = np.fft.rfftfreq (n, 1/sr)
    db = 20*np.log10 (H + 1e-20)

    return {
        'dc_gain':        float (np.sum(b) / np.sum(a)),
        'nyquist_gain':   float (np.sum([bi*((-1)**i) for i,bi in enumerate(b)]) /
                                 np.sum([ai*((-1)**i) for i,ai in enumerate(a)])),
        'minus3db_hz':    float (f[np.argmax (db < -3)]),
        'peak_gain_db':   float (db.max()),
        'max_pole_radius':float (np.max (np.abs (np.roots (a))) if len(a) > 1 else 0.0),
        'tail_level':     float (np.max (np.abs (y[n//2:]))),
    }

def save_baseline (metrics, path='baseline.json'):
    with open (path, 'w') as fh:
        json.dump (metrics, fh, indent=2, sort_keys=True)
    print (f"✅ 基线已保存到 {path}")
    for k, v in sorted (metrics.items()):
        print (f"   {k:<20} {v:.6f}")

def check_against_baseline (metrics, path='baseline.json', tol=1e-4):
    """比对基线，返回是否通过"""
    with open (path) as fh:
        base = json.load (fh)

    ok = True
    for k in sorted (base):
        if k not in metrics:
            print (f"   ❌ 缺少指标: {k}"); ok = False; continue
        delta = abs (metrics[k] - base[k])
        scale = max (abs(base[k]), 1.0)
        rel = delta / scale
        status = "✅" if rel < tol else "❌"
        if rel >= tol:
            ok = False
        print (f"   {status} {k:<20} 基线 {base[k]:>12.6f} 现在 {metrics[k]:>12.6f} "
               f"(相对变化 {rel:.2e})")
    return ok
```

**用法**：

```bash
# 第一次：存基线
python3 test_baseline.py --save

# 以后每次改动：比对
python3 test_baseline.py --check
```

> [!tip] 为什么存指标而不是存音频
> | | 存音频 | 存指标 |
> |---|---|---|
> | 文件大小 | 大（MB 级） | 小（几百字节） |
> | 可读性 | 二进制 | ✅ JSON，人可读 |
> | 跨平台 | 数值会变 | ✅ 性质不变 |
> | diff 友好 | ❌ | ✅ git diff 能看懂 |

## 三、Bit-exact 回归

**适合**：同一平台内的重构/优化验证。

```python
import numpy as np

def save_bitexact (signal, path='baseline.npy'):
    """存 WAV 或 npy"""
    np.save (path, np.asarray (signal, np.float32))

def check_bitexact (signal, path='baseline.npy'):
    base = np.load (path)
    cur  = np.asarray (signal, np.float32)
    n = min (len(base), len(cur))

    if len(base) != len(cur):
        print (f"   ❌ 长度不同: {len(base)} vs {len(cur)}")
        return False

    # ⚠️ 用 view(uint32) 比较位模式（不用 ==）
    same = np.array_equal (base[:n].view(np.uint32), cur[:n].view(np.uint32))
    print (f"   {'✅ bit-exact' if same else '❌ 有位差异'}")

    if not same:
        diff = np.flatnonzero (base[:n].view(np.uint32) != cur[:n].view(np.uint32))
        print (f"   首个差异在样本 {diff[0]}，共 {len(diff)} 个不同")
    return same
```

> [!danger] 跨平台**不要**要求 bit-exact
> FMA 指令、优化重排、FTZ 模式、向量化顺序都会导致差异。
> 跨平台应该用**数值容差**（< -100 dB）。
>
> 见 [[Null Test 与 bit-exact 对比]]。

## 四、NULL 回归

**思路**：存基线音频，新版本和它做 null test。

```python
import numpy as np

def null_regression (current, baseline_path='baseline.npy', threshold_db=-100):
    base = np.load (baseline_path)
    n = min (len(base), len(current))
    d = np.asarray (current[:n], float) - base[:n]

    peak = 20*np.log10 (np.max (np.abs (d)) + 1e-300)
    ref  = 20*np.log10 (np.max (np.abs (base[:n])) + 1e-300)
    rel  = peak - ref

    ok = rel < threshold_db
    print (f"   {'✅' if ok else '❌'} null 差异 {rel:>8.1f} dB (阈值 {threshold_db} dB)")
    return ok
```

> [!warning] 注意对齐
> 如果新版本改变了延迟，null test 会得到 **-17 dB**（1 采样差）。
> **先测延迟，对齐后再比。**
>
> 见 [[Null Test 与 bit-exact 对比]]。

## 六、AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **存音频而不是存指标** | 仓库变大、跨平台失败 | 存指标 JSON |
| 2 | **跨平台要求 bit-exact** | 永远失败 | 用容差 |
| 3 | **不检查延迟就 null test** | 得到 -17 dB 假差异 | 先对齐 |
| 4 | **用 `==` 比浮点** | NaN/-0.0 判定错 | 用 `view(uint32)` |
| 5 | **基线用随机信号** | 不可复现 | 固定种子 |
| 6 | **不固定依赖版本** | numpy 升级后基线失效 | 固定版本 |
| 7 | **测试太慢** | 没人跑 | 用短信号 |
| 8 | **只存"最终输出"** | 中间环节坏了测不出 | 存多个环节的指标 |
| 9 | **基线跟着代码一起改** | 回归测试失效 | 基线改动要 code review |

> [!danger] 第 9 条是最隐蔽的"测试失效"
> 如果开发者发现"测试失败"就直接更新基线文件，
> **回归测试就完全失去意义了**——它只会永远通过。
>
> **防线**：基线文件的改动必须走 code review，
> 并且要求说明"为什么这个变化是预期的"。

## 七、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 测试总是失败 | 跨平台要求 bit-exact | 用容差 |
| 测试从不失败 | 基线被随手更新 | 基线改动要 review |
| 差异总是 -17 dB | 延迟变了没对齐 | 先测延迟 |
| 差异总是 -90 dB | 1 LSB 取整差异 | 比浮点 |
| 每次结果不同 | 随机种子未固定 | 固定种子 |
| CI 上失败本地通过 | 依赖版本不同 | 固定版本 |
| 基线文件巨大 | 存了原始音频 | 存指标 |

## 八、怎么验证（回归测试自身的验收）

> [!important] 回归测试也要被测试
> 用**变异测试**确认它能抓到变化。

```python
def verify_regression_catches_changes():
    """确认回归测试真的能抓到变化"""
    b, a = biquad_lowpass (1000.0, 0.707)
    base = compute_metrics (b, a)

    # 变异 1：直流增益 ×1.01
    b2 = np.array(b) * 1.01
    m2 = compute_metrics (b2, a)
    delta = abs (m2['dc_gain'] - base['dc_gain'])
    assert delta > 1e-3, "回归测试抓不到 1% 的增益变化！"
    print ("✅ 能抓到 1% 增益变化")

    # 变异 2：Q 变化 10%
    b3, a3 = biquad_lowpass (1000.0, 0.707*1.1)
    m3 = compute_metrics (b3, a3)
    assert abs (m3['minus3db_hz'] - base['minus3db_hz']) > 1.0, "抓不到 Q 变化"
    print ("✅ 能抓到 Q 变化")

    # 变异 3：不稳定（Q 符号写错 —— 真实 bug 模式）
    b4, a4 = biquad_lowpass (1000.0, -0.707)     # Q 为负！
    m4 = compute_metrics (b4, a4)
    assert m4['max_pole_radius'] > 1.0, "抓不到不稳定"
    print (f"✅ 能抓到不稳定（极点半径 {m4['max_pole_radius']:.4f} > 1）")
```

> [!danger] 变异测试本身也会写错（本库的真实经历）
> 我最初写的变异是：
> ```python
> a_unstable = np.array(a) * 1.001      # ❌ 无效变异！
> ```
> **这个变异什么也没改变。**
>
> 因为多项式 $a_0 + a_1z^{-1} + a_2z^{-2}$ 的根只取决于系数的**比值**。
> 所有系数同比例放大 = 整体缩放 = **根完全相同**。
>
> 实测：
> ```
> 原 a          = [1.0, -1.81531792, 0.83098222]  → 极点半径 0.911582
> a * 1.001     = [1.001, -1.81713323, 0.8318132] → 极点半径 0.911582  ← 完全不变！
> ```
>
> **有效的变异**（实测能让极点出圆）：
> | 变异 | 极点半径 |
> |---|---|
> | $a_2 = 1.05$ | **1.024695** ❌ |
> | **Q = −0.707**（符号写错） | **1.096994** ❌ |
> | $f_c$ = 24kHz, Q = 50 | **1.000000** ❌ |
>
> **教训**：变异测试失败时，先确认**变异真的改变了行为**，
> 再怀疑回归测试没牙。

> [!tip] 这个测试建立信心
> 如果回归测试**抓不到**故意的变化，那它就没有价值。
> **先证明它有牙，再依赖它。**
