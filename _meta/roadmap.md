# 路线图

> [!warning] 这是**假设性**路线图
> 它基于 [[_meta/open-questions|待确认清单]] 里的假设 A1–A6。
> 你的回答会改写它。**在 Q1–Q4 回答之前，把它当作草案。**

## 设计原则

1. **第一个插件必须能出声**，哪怕只有 20 行 DSP。成就感 > 完整性。
2. **每个阶段产出可验证的东西**，不是"学完 XX 再说"。
3. **先做效果器，后做合成器**。效果器的正确性容易验证（输入输出对比），合成器难。
4. **AI 从第一天就介入**，但只做"助手 + 测量"，不做"代笔"。

---

## 阶段 0：环境（1–2 天）

**目标**：能在 DAW 里加载一个能出声的插件。

- [ ] 安装 CMake（`brew install cmake`）
- [ ] 安装 Xcode Command Line Tools
- [ ] 跑通 JUCE 官方示例（`git clone juce`，用 CMake 构建 AudioPluginDemo）
- [ ] 在 DAW 里加载它，确认能出声
- [ ] 建立 `50-Playground/` 的第一个实验目录

**产出**：`20-Notes/YYYY-MM-DD 环境搭建记录.md`（记录踩的坑）
**验证**：DAW 里能看到插件，能调参数，能听到声音变化

> [!tip] 这一步的坑最多
> CMake 版本、Xcode 路径、插件扫描失败、AU 验证不过……每个坑都值得写进笔记并打 `#gotcha` 标签。
> **这是你知识库里最值钱的一类内容**——官方文档不会写"我在 macOS 14 上遇到 X 报错怎么解决"。

## 阶段 1：DSP 地基（2–4 周）

**目标**：不依赖框架，纯 C++ 写出正确的 DSP 模块。

- [ ] 增益 / 淡入淡出 / 参数平滑（对抗 zipper noise）
- [ ] 一阶低通、高通（RC 数字等价）
- [ ] Biquad（lowpass / highpass / peaking / shelf），会算系数
- [ ] 延迟线（带线性插值 + 分数延迟）
- [ ] 简单压缩器（peak detector + 软膝 + attack/release）
- [ ] 每个模块写**离线测试**：喂正弦/脉冲/白噪声，输出到文件，用 Python 画图验证

**关键**：这一阶段**不要碰 JUCE**。用纯 C++ + Python 分析。
理由：JUCE 会掩盖你对信号流的理解，而信号流是后面一切的基础。

**产出**：`50-Playground/dsp-basics/` + 每个模块一个 Wiki 页
**验证**：用 [[Biquad 滤波器]] 页里的公式手算系数，和代码输出对比一致

> [!note] AI 在这一阶段的最佳用法
> 让 Agent 帮你**写测试和绘图脚本**，而不是写 DSP。
> DSP 你自己写，才会形成直觉。测试脚本让 AI 写，省 80% 时间。

## 阶段 2：第一个真插件（2–4 周）

**目标**：一个能给别人用的效果器。

选题建议（按难度）：
1. **增益 / 工具类** — 最简单，但没人下载
2. **滤波器（自动哇音）** — 有听觉反馈，适合入门
3. **压缩器** — 经典，且你懂听感，能做出差异化
4. **饱和 / 失真** — 需要过采样，难度上一个台阶
5. **延迟 / 混响** — 需要延迟线和反馈网络，最出效果

- [ ] JUCE 项目骨架 + CMake
- [ ] 参数系统（AudioProcessorValueTreeState）
- [ ] 基本 GUI（几个旋钮）
- [ ] 状态保存/恢复（关掉 DAW 再打开参数还在）
- [ ] 过 pluginval / auval
- [ ] 在 3 个不同宿主里测试

**产出**：`40-Projects/我的第一个插件.md`
**验证**：发给一个朋友，他能装上并用起来

## 阶段 3：实时工程硬功（持续）

**目标**：不再写出会爆音的插件。

- [ ] 理解并遵守 [[实时音频线程契约]]
- [ ] 参数平滑 / 无锁参数传递
- [ ] 性能剖析，找出 CPU 热点
- [ ] SIMD 优化（可选）
- [ ] 不同采样率 / block size / 声道数下的正确性
- [ ] 内存与启动时间

---

## 阶段 4：AI 分支（择一深入）

| 分支 | 内容 | 难度 |
|---|---|---|
| **A. AI 辅助开发** | Agent 工作流、代码审查、自动化测试、音色参数探索 | ⭐ |
| **B. 神经网络音频** | 实时推理、模型量化、延迟预算、ONNX Runtime / RTNeural | ⭐⭐⭐⭐ |
| **C. 可微 DSP** | 用梯度下降优化效果器参数（DDSP 思路） | ⭐⭐⭐⭐⭐ |
| **D. 智能音乐工具** | 自动混音、智能 EQ、音源分离辅助 | ⭐⭐⭐ |

> [!tip] 建议
> **A 立刻做，B 作为长期目标。**
> C 和 D 更接近研究，除非你要读博，否则先别碰。
> B 的现实门槛是**延迟**：神经网络推理要跑在音频线程的实时预算内（如 64 samples @ 48kHz = 1.3ms），这决定了模型大小和架构选择。

## 时间预算对照

| 每周投入 | 到阶段 2 完成 | 说明 |
|---|---|---|
| 3 小时 | 4–6 个月 | 兴趣节奏，正常 |
| 8 小时 | 2–3 个月 | 稳定推进 |
| 20 小时 | 3–5 周 | 接近全职 |

> [!warning] 别用"学完再开始"的路线
> DSP 教材（如 Zölzer、Pirkle、Smith）加起来几千页。
> 读完再动手 = 永远不动手。
> **正确做法：需要什么查什么，边做边补，把补的过程写进这个知识库。**
