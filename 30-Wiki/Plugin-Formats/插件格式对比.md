# 插件格式对比

> [!warning] 本页需要核实
> 格式的支持情况、SDK 许可证条款会变化。**发布前必须回官方文档确认**。
> 标 ⚠️ 的地方是我信心不足的，需要你或 Agent 验证。

## 一句话结论

**先做 VST3，同时用 JUCE 顺手产出 AU，等有用户要求再加 CLAP。**

理由：JUCE 一套代码同时构建多种格式，边际成本很低。但**测试成本**不低——每种格式都要在每个宿主里测。

## 对比表

| | VST3 | AU (Audio Units) | CLAP | AAX | LV2 |
|---|---|---|---|---|---|
| 厂商 | Steinberg | Apple | Bitwig + u-he 等 | Avid | 社区 |
| 平台 | macOS / Win / Linux | macOS / iOS | 全平台 | macOS / Win | Linux 为主 |
| 开源 | **是（MIT，3.8 起）** ✅ | 框架闭源，接口公开 | 是（MIT） | 否 | 是 |
| 宿主支持 | 最广 | macOS 上除少数外都支持 | Bitwig / Reaper / 部分支持 | 仅 Pro Tools | Linux 宿主 |
| 上手难度 | 中（SDK 冗长） | 中 | 低（API 干净） | 高（+ PACE 签名） | 中 |
| 主要优势 | 事实标准；**MIT 许可** | macOS 原生，Logic 必需 | 现代设计：线程池、参数调制 | Pro Tools 用户 | 自由 |
| 主要劣势 | API 陈旧 | 仅 Apple 平台 | 宿主支持仍在增长 | 门槛高、成本高 | 生态小 |

> [!important] 关于 VST3 SDK 许可证 —— 已更新（2026-10-14 核实）
> **自 VST 3.8 起，VST3 采用 MIT 许可证。**
> 免费、无需会员、无需签署文件、永久有效、可用于闭源商业产品。
> **GPLv3 和 Steinberg 专有许可均已取消。**
>
> 所以"VST3 许可证麻烦"这个说法**已经过时了**。
> 现在真正的许可证风险在**开发框架**（JUCE 的 AGPLv3）和**第三方库**上。
> 详见 [[开源与商业的许可证陷阱]]。
> 详见 [[开源与商业的许可证陷阱]]。

## 格式选择决策树

以你的情况（macOS 为主、想发布、可能商业化）为例：

```
你要发布吗？
├─ 不发布，自己用
│   └─ ✅ 用 JUCE 的 Standalone 模式，最快，不用管格式
│
└─ 要发布
    ├─ 目标用户主要是 Logic 用户？
    │   └─ ✅ 必须做 AU（Logic 只认 AU）
    │
    ├─ 要覆盖大多数 DAW？
    │   └─ ✅ VST3 + AU（JUCE 一次构建两个）
    │
    ├─ 要支持 Pro Tools 用户？
    │   └─ ⚠️ 需要 AAX + PACE 签名，成本与复杂度显著上升
    │      除非有明确需求，先跳过
    │
    └─ 你的用户里有 Bitwig / Reaper 极客？
        └─ ✅ 加一个 CLAP（JUCE 支持，增量成本低）
```

**给你的建议**：`VST3 + AU`，用 JUCE，先跑通全流程（含签名公证），再考虑扩展。

## 宿主兼容性矩阵

> ⚠️ **本表需要实测填充**。发布前你应该亲手在每个宿主里加载测试。

| 宿主 | VST3 | AU | CLAP | 备注 |
|---|---|---|---|---|
| Ableton Live | ✅ | ✅ (macOS) | ❌ ⚠️ | |
| Logic Pro | ❌ | ✅ | ❌ | 只支持 AU |
| Reaper | ✅ | ✅ | ✅ | 兼容性最好，适合测试 |
| Bitwig | ✅ | ✅ | ✅ | CLAP 发源地 |
| FL Studio | ✅ | ✅ (macOS) | ❌ ⚠️ | |
| Cubase / Nuendo | ✅ | ❌ | ❌ | Steinberg 自家 |
| Studio One | ✅ | ✅ | ✅ ⚠️ | |
| Pro Tools | ❌ | ❌ | ❌ | 只支持 AAX |
| GarageBand | ❌ | ✅ | ❌ | |

> [!tip] 测试策略
> **Reaper 是最宽容的测试宿主**（支持所有格式、报错信息清晰）。
> **Logic 是最挑剔的**（AU 验证严格）。
> 用 Reaper 做日常开发，用 Logic 做发布前验证。

## 插件类别

| 类别 | 说明 | 例子 |
|---|---|---|
| Effect | 处理音频输入 | 压缩器、混响 |
| Instrument | 生成音频，接收 MIDI | 合成器、采样器 |
| Analyzer | 只读音频，不改变 | 频谱仪、响度表 |
| MIDI Effect | 只处理 MIDI | 琶音器、和弦器 |
| Note Effect | 类似 MIDI Effect 但更现代 | CLAP 里的概念 ⚠️ |

> [!warning] Analyzer 类插件的一个坑
> 有些宿主对"不改变音频"的插件会做优化（比如跳过处理）。
> 需要显式声明你有 side effect，或输出静音但仍被调用。
> 具体机制各格式不同，需要实测。

## AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **编造格式的市场份额** | 决策错误 | 标需核实 |
| 2 | **以为 AU 能在 Windows 用** | 配置错误 | AU 只在 macOS |
| 3 | **混淆 VST2 和 VST3** | API 完全不同 | 明确版本 |
| 4 | **忘了四字符代码** | 宿主认不出 | 见 [[版本号与更新分发]] |
| 5 | **以为 AAX 随便就能做** | 需 Avid 审批 | 查官方流程 |
| 6 | **说"VST3 支持所有宿主"** | 事实错误 | 逐个核实 |
| 7 | **忽略格式对延迟报告的要求** | 多轨错位 | 见 [[延迟报告 latency reporting]] |

> [!warning] 这一页最容易出现"编造的数值"
> 格式的市场份额、各宿主的支持情况**会变**。
> 本页**不给具体百分比**——需要时查官方文档。

## 怎么验证

> [!important] 格式相关的"验证"主要是**实际构建 + 验证工具**

| # | 检查 | 命令/工具 |
|---|---|---|
| 1 | **能构建出目标格式** | `cmake --build build` |
| 2 | **AU 验证** | `auval -a` / `auval -v` |
| 3 | **VST3 验证** | `pluginval` |
| 4 | **宿主能扫描到** | 见 [[插件扫描机制]] |
| 5 | **四字符代码正确** | 检查 CMake 配置 |

```bash
# macOS 上验证 AU（本机有 auval）
auval -a                                   # 列出所有 AU
auval -v aufx Mypl Yrnm                    # 验证特定 AU

# VST3 合规性（需安装 pluginval）
pluginval --strictness-level 10 --validate MyPlugin.vst3
```

> [!warning] ⚠️ 本机没有 JUCE / pluginval
> 上面的命令**未在本机实测**（除了 `auval` 存在性）。
> 见 [[插件合规性测试：pluginval]]、[[auval 与 AU 验证]]。
