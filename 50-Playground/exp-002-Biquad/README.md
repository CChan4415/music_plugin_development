# exp-002: Biquad 滤波器

> [!important] 这是音频里最重要的一个 DSP 模块
> 90% 的 EQ、滤波器、音色塑形都是它。
> 这个实验做完，你就能看懂大部分 EQ 插件的核心。

## 运行

```bash
python3 biquad.py --no-play
```

## 验证结果

| 检查项 | 结果 | 说明 |
|---|---|---|
| 频率响应 vs 解析解 | **最大偏差 0.0021 dB** | ✅ 系数计算正确 |
| 截止频率处增益 | **-3.01 dB** | Butterworth Q=0.707 的理论值 |
| 滚降斜率 | -13.3 dB/oct | 二阶渐近 -12；fc×4 处尚未完全渐近，正常 |
| 确定性 | 同输入两次结果 **bit-exact** | 可做 null test 的前提 |

## 学到的关键点

1. **`A = 10^(dB/40)` 不是 `/20`** —— 峰值 EQ 的常见 bug，增益会差一倍
2. **符号约定** —— 分母系数 `a1/a2` 在差分方程里是减号，抄公式前必须确认
3. **Q 值 ↔ ringing**：Q=0.707 → 1.8ms，Q=30 → 66ms，Q=100 → 221ms
4. **参数必须钳制**：`f0 < fs*0.45`，否则接近 Nyquist 时公式失效
5. **系数更新率**：每 256 样本更新一次是实践中的平衡点

## 踩到的坑（两次都是**测量方法**错，不是代码错）

| 现象 | 我以为是 | 实际是 |
|---|---|---|
| 滚降斜率 -13.3 而非 -12 | 系数算错了 | `fc*4` 处还没进入渐近区，正常 |
| Q=30 的 ringing 比 Q=5 短 | 实现有 bug | **测量方法错**：用绝对阈值 → 高 Q 峰值大，误判为衰减快 |
| 修正后又变成 0.25ms | —— | **还是测量错**：找"峰值后第一次低于阈值"，振荡信号会立刻穿过去 |

**正确做法**：找**最后一次**高于阈值（峰值 -60dB）的位置。

> [!tip] 这个模式值得记住
> **测量工具的 bug 会伪装成被测对象的 bug。**
> 遇到"结果不对"，先怀疑你的验证脚本。
> 完整归纳见 [[2026-10-14 测量工具会骗你 —— 七次踩坑记录]]

## 下一步

把 `biquad.py` 翻译成 C++，然后用 `null_test` 对比两边输出。
这是 [[C++ 零基础到音频 DSP 路线]] 阶段 3 的核心练习。

> [!warning] 做 null test 前必须知道：取整方式会让差异停在 -90dB
> 实测对比 Python 与 C 写 WAV 的方式：
>
> | 输入 | Python `astype(int16)`（截断） | C `lround`（四舍五入） | 差 |
> |---|---|---|---|
> | 0.5 | 16383 | 16384 | -1 LSB |
> | 0.25 | 8191 | 8192 | -1 LSB |
> | 1.0 | 32767 | 32767 | 0 |
>
> **最多差 1 LSB，听感上完全无关**，但它会让 null test 结果停在 **-90dB 左右**，
> 而不是你以为的 -inf。
>
> **两种做法**：
> 1. **比浮点**（推荐）：两边都在内存里用 `float` 比较，不经过 WAV 编解码
> 2. **统一取整**：如果必须比 WAV，两边用同一种取整方式
>
> ⚠️ 否则你会花几个小时找"为什么不是 -inf"——**而代码其实完全正确**。
> 这又是一次「测量/比较方法」问题，见 [[2026-10-14 测量工具会骗你 —— 七次踩坑记录]]。
