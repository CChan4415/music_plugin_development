# 调制效果

> [!important] 一句话
> **调制效果 = 用低频信号（LFO）去改变某个参数。**
> Chorus / Flanger / Phaser / Tremolo / Vibrato 都是这个模式的变体——
> **区别只在"调制什么"和"调制多深"**。

## 五种效果的统一视角

| 效果 | 调制什么 | 典型速率 | 典型深度 |
|---|---|---|---|
| **Tremolo** | **幅度** | 4–8 Hz | 20–50% |
| **Vibrato** | **延迟时间**（→音高） | 4–7 Hz | 1–5 ms |
| **Chorus** | **延迟时间**（小） | 0.1–2 Hz | 1–15 ms |
| **Flanger** | **延迟时间**（带反馈） | 0.05–5 Hz | 0.5–10 ms |
| **Phaser** | **全通的中心频率** | 0.05–5 Hz | 扫频范围 |

> [!important] 核心洞察
> **Vibrato / Chorus / Flanger 都是"调制延迟时间"**——
> 区别在于**延迟长度**和**是否有反馈**：
>
> | | 延迟长度 | 反馈 |
> |---|---|---|
> | Vibrato | 短（1–5 ms） | 无 |
> | **Chorus** | 中（1–15 ms） | 无或很少 |
> | **Flanger** | 短（0.5–10 ms） | **有**（这是关键） |
>
> **Flanger 的"喷气声"来自梳状滤波的反馈**（见 [[梳状滤波器 comb filter]]）。

## 一、LFO：调制的驱动源

**基本形式**：

$$m[n] = \text{depth} \cdot \sin\!\left(2\pi \frac{f_{\text{LFO}}}{f_s} n + \phi\right)$$

| 波形 | 听感 |
|---|---|
| **正弦** | 平滑、自然（最常用） |
| **三角** | 线性扫动，比正弦"均匀" |
| **方波** | 突变（很少用于延迟调制） |
| **随机/采样保持** | 阶梯感（用于特殊效果） |

```cpp
class Lfo
{
public:
    void prepare (double sampleRate) { sr = sampleRate; phase = 0.0; }

    void setRate (float hz) { rate = std::max (0.0f, hz); }

    // 返回 [-1, 1]
    float process() noexcept
    {
        const float v = std::sin (2.0f * juce::MathConstants<float>::pi * (float) phase);
        phase += rate / sr;
        if (phase >= 1.0) phase -= 1.0;
        return v;
    }

private:
    double sr = 48000.0, phase = 0.0;
    float rate = 1.0f;
};
```

> [!warning] 相位累加要用 `double`
> 用 `float` 累加时，长时间运行会有精度损失
> （LFO 速率很慢，累加次数多）。
> 见 [[抗混叠振荡器]] 的同类建议。

## 二、立体声：相位偏移是关键

> [!important] 单声道调制听起来"单调"，立体声需要**左右不同的相位**

| 方式 | 效果 |
|---|---|
| **左右 LFO 反相（180°）** | 最宽（但单声道兼容性差） |
| **左右相位差 90°** | 宽且较自然 ✅ |
| 左右同相 | ❌ 无立体感（等于单声道调制） |

```cpp
// 左右反相（最简单）
const float m = lfo.process();
leftDelay  = baseDelay * (1.0f + depth * m);
rightDelay = baseDelay * (1.0f - depth * m);      // ← 反相

// 或者用相位偏移的 LFO（更灵活）
const float ml = lfoL.process();      // 相位 0°
const float mr = lfoR.process();      // 相位 90° 或 180°
```

> [!danger] 立体声调制的**相位问题**
> 左右反相时，两个声道相加会**部分抵消**（单声道兼容性差）。
> 如果你的效果在单声道系统上播放时会"变小声"或"消失"，就是这个原因。
>
> **检验方法**：把左右相加（mono 混合），听是否有明显衰减或梳状滤波。
> 见 [[立体声感知]]。

## 三、Chorus 的实现

**核心结构**：

```
输入 ──┬────────────────────→ 干声 ──┬──→ 输出
       │                             │
       └─→ 延迟线(被 LFO 调制) ──→ 湿声 ┘
```

> [!important] Chorus 需要**多个**延迟线
> 单个调制延迟线听起来像"飘忽"而不是"合唱"。
> **真正的合唱感来自多个略微不同的延迟同时叠加。**

| 配置 | 听感 |
|---|---|
| 1 条延迟线 | 飘忽（更像 flanger） |
| **2–4 条，不同相位** | ✅ 合唱 |
| 更多 | 更厚，但 CPU 增加 |

```cpp
class Chorus
{
public:
    void prepare (double sampleRate, int maxDelaySamples)
    {
        sr = sampleRate;
        for (auto& v : voices)
        {
            v.delay.prepare (maxDelaySamples);
            v.phaseOffset = 0.0;          // 每个 voice 不同
        }
        // 相位偏移：让多个 voice 不同步
        voices[0].phaseOffset = 0.0;
        voices[1].phaseOffset = 0.25;     // 90°
        voices[2].phaseOffset = 0.5;      // 180°
        voices[3].phaseOffset = 0.75;     // 270°
        lfo.prepare (sampleRate);
    }

    float process (float x) noexcept
    {
        const float m = lfo.process();

        float wet = 0.0f;
        for (auto& v : voices)
            wet += v.delay.process (x, baseDelayMs, depthMs, m + v.phaseOffset);

        return x * (1.0f - mix) + (wet / (float) voices.size()) * mix;
    }

private:
    struct Voice { ModulatedDelay delay; double phaseOffset = 0.0; };
    std::array<Voice, 4> voices;
    Lfo lfo;
    double sr = 48000.0;
    float baseDelayMs = 15.0f, depthMs = 5.0f, mix = 0.5f;
};
```

> [!danger] 调制延迟必须用**插值**
> 延迟时间连续变化时，**读取位置落在样本之间**。
> 必须用分数延迟插值（见 [[插值]]）。
>
> 用线性插值会导致**高频衰减**（而且衰减量随调制变化 → "音色在动"）。

## 四、Flanger vs Chorus：只差一个反馈

> [!important] 关键区别
> **Flanger 有反馈**，产生**尖锐的梳状峰**（"喷气声"）。
> **Chorus 没有反馈**（或很少），声音更"柔和/自然"。

| | Chorus | Flanger |
|---|---|---|
| 延迟 | 1–15 ms | **0.5–10 ms** |
| **反馈** | 0（或很小） | **有（可达 0.9）** |
| 梳状峰 | 缓 | **尖锐** |
| 听感 | 厚、宽、自然 | 喷气、扫频感强 |
| 单声道兼容 | 较好 | 差（梳状滤波） |

**Flanger 的反馈**：

```cpp
float y = delay.readFractional (delaySamples);
delay.write (x + y * feedback);        // ← 反馈（Chorus 没有这个）
return x * (1.0f - mix) + y * mix;
```

> [!warning] 反馈增益必须钳制
> `feedback >= 1` 会导致**发散**（无限增长）。
> **钳制到 0.95 以下**，并检查稳定性。
>
> 见 [[延迟线 delay line]] 的同类建议。

## 五、Phaser：调制的是全通滤波器

> [!important] Phaser 不调制延迟，而是**全通滤波器的中心频率**

**结构**：

```
输入 ──┬────────────────────────→ 干声 ──┬──→ 输出
       │                                 │
       └─→ [全通1]→[全通2]→...→[全通N] ──┤
              ↑ LFO 调制中心频率          │
              └──────── 反馈 ────────────┘
```

| 参数 | 作用 |
|---|---|
| **级数**（N） | 每级产生一个陷波；N 级 = N 个陷波 |
| 中心频率 | LFO 扫描的范围 |
| 反馈 | 加深陷波（"更明显"） |

> [!note] Phaser vs Flanger 的听感差异
> - **Flanger**：陷波是**谐波关系**（等间隔）→ "金属/喷气"
> - **Phaser**：陷波是**非谐波关系**（全通相位决定）→ "扫过"感更柔和
>
> **这就是为什么两者听起来不同**，尽管原理类似。

见 [[全通滤波器 allpass]]。

## 六、AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **调制延迟不用插值** | 高频衰减 + 咔哒 | 检查是否有分数延迟 |
| 2 | **用线性插值当"够好"** | 音色随调制变化 | 用全通/三次插值 |
| 3 | **反馈不钳制** | 发散 | `clamp(fb, 0, 0.95)` |
| 4 | **立体声 LFO 同相** | 无立体感 | 加相位偏移 |
| 5 | **Chorus 只用一条延迟线** | 听起来像 flanger | 用 2–4 条 |
| 6 | **LFO 用 float 累加相位** | 长时间精度损失 | 用 double |
| 7 | **在音频线程重建延迟线** | 违反实时契约 | prepare 里分配 |
| 8 | **干湿混合不做等功率** | 混合时音量变化 | 用等功率交叉淡化 |
| 9 | **忘了 denormal** | 安静时 CPU 高 | 见 [[denormal 数处理]] |
| 10 | **参数没平滑** | 调节时有咔哒 | 见 [[参数平滑 parameter smoothing]] |

> [!danger] 第 1 条是调制效果最常见的 bug
> AI 会写"延迟时间 = base + depth * lfo"，
> 然后**直接用整数索引读取**——这在延迟时间变化时会产生**咔哒声**。
>
> **判据**：调制深度 > 0 时，输出不应有周期性的咔哒。

> [!warning] 第 2 条的隐藏代价
> 线性插值本身"能用"，但它在高频有衰减，
> 而且**衰减量随分数位置变化**——
> 所以你会听到"音色在随 LFO 动"。
>
> 对 Chorus 这种"温和"的效果可能可接受；
> 对 Vibrato（要纯净的音高调制）**不可接受**。

## 七、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 调制时有咔哒声 | 延迟读取没用插值 | 加分数延迟插值 |
| 音色随 LFO 变化 | 线性插值的高频衰减 | 用全通/三次插值 |
| 单声道播放时消失 | 立体声反相抵消 | 减小相位差，或检查兼容性 |
| 反馈发散 | 反馈 ≥ 1 | 钳制到 0.95 |
| 没有"合唱感" | 只用了一条延迟线 | 用多条不同相位 |
| 立体声没宽度 | LFO 同相 | 加相位偏移 |
| 长时间播放有漂移 | LFO 相位用 float | 用 double |
| 调节参数有咔哒 | 参数没平滑 | 加平滑 |
| 安静时 CPU 高 | denormal | 加偏置/FTZ |

## 八、怎么验证

**五个必做测试**：

| # | 测试 | 判据 |
|---|---|---|
| 1 | **深度 = 0 时透明** | null test ≈ 0（干湿 = 全干时） |
| 2 | **无咔哒声** | 深度 > 0 时输出连续 |
| 3 | **稳定性**（有反馈时） | 脉冲跑 10 秒衰减 |
| 4 | **调制速率正确** | 输出包络的周期 = 1/LFO 速率 |
| 5 | **立体声兼容** | 左右相加不消失 |

```python
import numpy as np
SR = 48000

def modulated_delay (x, base_ms, depth_ms, rate_hz, sr=SR, interp='linear'):
    """调制延迟（对比不同插值方式）"""
    base = base_ms * 0.001 * sr
    depth = depth_ms * 0.001 * sr
    buf = np.zeros (int (base + depth) + 4)
    w = 0; out = np.zeros (len(x))

    for i, v in enumerate(x):
        m = np.sin (2*np.pi*rate_hz*i/sr)
        d = base + depth * m                     # 延迟（采样，浮点）

        # 分数延迟读取
        if interp == 'linear':
            rp = w - d
            while rp < 0: rp += len(buf)
            i0 = int(np.floor(rp)); frac = rp - i0
            i1 = (i0 + 1) % len(buf)
            out[i] = buf[i0]*(1-frac) + buf[i1]*frac
        elif interp == 'nearest':
            rp = int(round(w - d)) % len(buf)
            out[i] = buf[rp]

        buf[w] = v
        w = (w + 1) % len(buf)
    return out

# 测试：调制深度大时，检测插值质量
x = np.sin (2*np.pi*1000*np.arange(SR)/SR) * 0.5
for mode in ['nearest', 'linear']:
    y = modulated_delay (x, 10.0, 5.0, 1.0, interp=mode)
    # 测量的"杂散"（不是 1kHz 也不是其谐波的能量）
    w = np.hanning (len(y)); X = np.abs (np.fft.rfft (y*w))**2
    fr = np.fft.rfftfreq (len(y), 1/SR)
    signal = (np.abs(fr - 1000) < 200)
    spur = 10*np.log10 (np.sum(X[~signal]) / (np.sum(X[signal]) + 1e-30))
    print (f"  {mode:<8} 杂散/信号 = {spur:>7.1f} dB")

# 期望：nearest 的杂散明显更高（质量差）
```

> [!important] 这个测试的价值
> 它把"插值质量"变成了**可测量的数字**（杂散/信号比）。
> **听感"有点脏"是主观的；-40 dB 是客观的。**

> [!important] 实测数字（本库验证）
> 参数：1kHz 正弦，base = 10ms，depth = 5ms，rate = 1Hz @48kHz
>
> | 插值方式 | 杂散/信号 |
> |---|---|
> | **最近邻（不插值）** | **-28.7 dB** ❌ |
> | **线性插值** | **-64.0 dB** ✅ |
>
> **差 35 dB。** 最近邻的杂散在 -29 dB——这是**明显可闻**的。
>
> ⚠️ 但注意：这个数字**依赖调制深度和速率**。
> 深度越大、速率越快，杂散越严重。
> **用你自己的实际参数跑一遍**。
>
> 另外：线性插值虽然在 -64 dB，但它有**高频衰减**
> （见 [[插值]]）——对 Chorus 可接受，对 Vibrato 不可接受。
