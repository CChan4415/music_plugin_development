## 先说结论：这条路有多长

| 目标 | 每周 5 小时 | 每周 10 小时 | 每周 20 小时 |
|---|---|---|---|
| **能听到自己写的 DSP**（Python） | 3–5 天 | 2–3 天 | 1 天 |
| **能用 C++ 处理音频文件** | 2–3 个月 | 1–1.5 个月 | 3–4 周 |
| **能在 DAW 里加载自己的插件** | 6–9 个月 | 3–5 个月 | 2–3 个月 |
| **能发布一个给别人用的插件** | 10–14 个月 | 6–8 个月 | 4–6 个月 |

> [!warning] 这是诚实的估算，不是劝退
> 网上"两周做出你的第一个插件"的教程，前提是作者已经会 C++。
> 你不会。**把语言和 DSP 同时从零学，是两条线并行**，所以比教程慢是正常的。
>
> 但注意第一行：**"能听到自己写的 DSP"只要几天**。这是这份路线图的设计核心。

## 设计原则

1. **先听到，再搞懂原理，最后才学 C++。** 顺序反了就会放弃。
2. **Python 是你的加速器，不是绕路。** 你会 Python，用它建立 DSP 直觉比用 C++ 快 5 倍。
3. **每个阶段都有可验证的产出。** 不允许出现"先学三个月基础"这种阶段。
4. **C++ 只学音频需要的那一小片。** 不要从"什么是变量"学起，也不要学模板元编程。
5. **AI 写测试和工具，你写 DSP 核心。** 理由见下。

> [!important] 为什么 Python 优先，而不是直接上 C++
> 你的瓶颈**不是语言，是"我不知道我的算法对不对"**。
> Python + numpy 让你在 10 行代码里写出一个滤波器，画图看频响，立刻知道对错。
> 同样的事在 C++ 里要写 200 行 + 配 CMake + 调编译器，**而你会把 90% 的时间花在语法错误上，不是 DSP 上**。
>
> 等你的 DSP 直觉建立了，再学 C++ —— 那时你是在"翻译我已经懂的东西"，
> 而不是"同时猜语法和猜算法"。

## 阶段 1：用 Python 建立 DSP 直觉（1–3 周）⭐ 最重要

**目标**：**听到自己写的声音**，并且能用图验证对错。

**为什么从 Python 开始**：你会 Python。不需要同时学新语言和新数学。

**学什么**：
- numpy 数组就是音频缓冲区（这个概念直接迁移到 C++）
- 采样率、时长、样本数的关系
- 用 `wave` 模块读写 WAV（标准库，不用装东西）
- 用 matplotlib 画波形和频谱

**产出（按顺序，每个都要能听/能看）**：

| # | 做什么 | 验证什么 |
|---|---|---|
| 1 | 生成 440Hz 正弦，存成 WAV，播放 | 你听到了自己算出来的采样点 |
| 2 | 生成白噪声、粉噪声，对比听感 | 理解频谱形状与听感的关系 |
| 3 | 把正弦的音量减半，验证是 -6dB | 理解 dB 与线性增益 |
| 4 | 实现一阶低通，扫截止频率听 | 第一次听到"滤波器在动" |
| 5 | 实现 Biquad 低通，画频响曲线 | 验证系数算对了（[[Biquad 滤波器]]） |
| 6 | 实现延迟线，做 1/8 拍回声 | 第一次做出"效果器" |
| 7 | 实现梳状滤波器 + 全通，串成简易混响 | 第一次做出"空间感" |
| 8 | 实现一个压缩器，看增益衰减曲线 | 理解动态处理 |
| 9 | 参数不平滑 vs 平滑，对比听 zipper noise | **亲耳听到 bug 长什么样** |
| 10 | 故意不过采样做失真，听混叠 | 理解为什么需要过采样 |

**验证方式**：每个都用 matplotlib 画图 + 用耳朵听。两个都对才算过。

> [!tip] 这一步的隐藏收益
> 你写的这些 Python 脚本（画频谱、算 THD、A/B 对比、生成测试信号）
> **以后每个 C++ 插件都能复用**。它们是你终身的测试工具箱。
> 放在 `50-Playground/tools/`。

**卡点**：数学。见下面的「数学怎么补」。

## 阶段 2：C++ 的最小可用子集（3–6 周）

**目标**：能读写 C++ 代码，理解内存。

**只学这些**（够用了）：
- 编译运行流程（源文件 → 编译 → 可执行文件）
- 基本类型、`float` vs `double`（音频里都用 `float`）
- 函数、`const`、引用 `&`
- `std::vector`（音频缓冲区就用它）
- 类的最基本用法（构造函数、成员变量、方法）
- **指针与内存**（栈 vs 堆）—— 这是真正的门槛
- 头文件与实现分离

**明确不用学**（现在学是浪费时间）：
- ❌ 模板元编程
- ❌ 多重继承、虚继承
- ❌ 异常安全
- ❌ 移动语义的细节
- ❌ `constexpr` / `consteval`
- ❌ 智能指针的各种细节（知道 `unique_ptr` 存在就够）

**产出**：
1. 一个能编译运行、打印"Hello"的程序（1 天）
2. 自己实现一个环形缓冲区（ring buffer）类（1 周）
3. **一个能读 WAV、改增益、写回 WAV 的命令行程序**（1–2 周）⭐ 关键里程碑
4. 用 Python 脚本验证输出文件的峰值确实变了（复用阶段 1 的工具）

> [!important] 第 3 项是关键里程碑
> 它意味着：**你的 C++ 程序能产出你能听的音频了**。
> 从这里开始，后面所有 C++ DSP 都可以用同样的方式验证——写文件、听、画图。
> **这就是把 Python 阶段的方法论平移到 C++。**

**卡点**：编译错误看不懂、段错误、`std::vector` 越界。
**解法**：把完整报错贴给 AI 让它解释——**这是 AI 最划算的用法**。

## 阶段 3：C++ 写 DSP（4–8 周）

**目标**：把阶段 1 在 Python 里写过的 DSP，用 C++ 重写一遍。

- [ ] 增益、淡入淡出、参数平滑
- [ ] 一阶低通
- [ ] Biquad（低通/高通/峰值）
- [ ] 延迟线（带线性插值）
- [ ] 压缩器
- [ ] 混响（Schroeder 或简易 FDN）

**方法**：**逐个移植，用 Python 脚本对比两边输出**。
如果 C++ 的输出和 Python 的输出在数值上一致（或差异 < -100dB），说明你写对了。

> [!tip] 这个"双实现对照"方法非常强
> 它把"我觉得应该对"变成了"两个独立实现给出相同结果"。
> 而且 Python 那边容易改、容易画图，C++ 那边容易出性能问题——**各自发挥优势**。

## 数学怎么补：用到再学，不要提前学

> [!important] 这是本路线图最重要的一节
> 做**效果器**需要的数学是**很窄的一片**。不要去买《信号与系统》从头读。
> **每学一个 DSP 主题，只补它需要的那一点数学。**

| DSP 主题 | 需要的数学 | 什么时候补 |
|---|---|---|
| 增益、dB、动态处理 | 对数（`log`/`exp`） | 阶段 1 第 3 项 |
| 一阶低通/高通 | 一点代数、指数衰减 | 阶段 1 第 4 项 |
| **Biquad 滤波器** | **复数、三角函数、z 变换（看懂 H(z) 即可，不用会推导）** | 阶段 1 第 5 项 |
| 频域分析、频谱仪 | 傅里叶变换（理解"时域↔频域"即可） | 阶段 1 画频谱时 |
| 卷积混响 | 卷积的概念（不用会证明） | 阶段 3 |
| 混响、FDN | 线性代数（矩阵） | 阶段 3 |
| 物理建模 | 微分方程、数值积分 | 阶段 5+ |
| 空间音频、神经网络 | 线性代数（矩阵运算） | 以后 |

> [!tip] 你的线性代数没问题，这是好消息
> 混响（FDN 本质是矩阵运算）、多声道处理、空间音频、以及你以后想做的**神经网络音频**，
> 全都吃线性代数。**这块地基是好的，别低估它。**

**补数学的方法**：
1. 不要读教材的前三章（那是给考试用的）
2. 在 Python 里**把公式画出来**——`cos` 是什么样、`e^(-x)` 是什么样、极点在单位圆内外有什么区别
3. 用具体数字代入，看结果怎么变
4. 卡住了就问 AI："用音乐人的语言解释 z 变换，不要用工程术语"

## 关于 AI 辅助：什么让它做，什么必须自己做

| 让 AI 做 ✅ | 自己做 ❌ |
|---|---|
| 解释编译错误、链接错误 | **DSP 核心算法** |
| 写 Python 分析/绘图脚本 | 滤波器的系数计算 |
| 写测试用例 | 参数范围与默认值的选择 |
| 解释不熟悉的 C++ 语法 | 任何"听起来对不对"的判断 |
| 写样板代码（CMake、JUCE 骨架） | 性能关键路径 |
| 查文档、找 API 用法 | 实时线程里的代码 |

> [!warning] 为什么 DSP 核心必须自己写
> 因为**你无法调试你不理解的东西**。
> AI 写的 DSP 代码"能编译、能出声"，但在特定参数下会爆音、失真、发散。
> 如果你不懂原理，你连"它错了"都判断不出来——**而你有耳朵，这是你的优势，别放弃它。**
>
> 更现实的理由：音频 bug 极其隐蔽。一个符号写反的滤波器，
> 在 90% 的参数范围内听起来"差不多"，只在极端值爆炸。
> AI 不会告诉你这一点，因为它自己也不知道。
