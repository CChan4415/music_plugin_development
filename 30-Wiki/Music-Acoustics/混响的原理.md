# 混响的原理

> [!important] 一句话
> **混响 = 一个声音在房间里反射很多次的结果。**
> 工程上，它就是**一堆不同延迟的叠加 + 反馈**。
> 你在插件上拧的所有混响参数（size / decay / damping / pre-delay / diffusion），
> 每一个都对应一个具体的算法选择。

> [!note] 你点名的例子
> 你提到"比如混响的原理什么的"——这一页就是为这个写的。
> 它不讲"混响是什么"（你知道），而讲**"你听到的那个感觉，代码上是怎么做出来的"**。

---

## 一、从物理到算法：混响的四个阶段

一个脉冲在房间里发生了什么，按时间顺序：

```
直达声 (direct)
   ↓ 几毫秒
早期反射 (early reflections)   ← 几个离散的回声，决定"房间大小感"
   ↓ 几十毫秒
晚期混响 (late reverb)         ← 密集的、统计上平滑的衰减
   ↓
衰减到听不见
```

| 阶段 | 时间尺度 | 听感作用 | 算法对应 |
|---|---|---|---|
| 直达声 | 0 | 声源位置 | 干信号 |
| Pre-delay | 0–100ms | 声源到墙的距离感 | 一个纯延迟 |
| 早期反射 | 5–80ms | **房间大小、形状** | 几个稀疏的抽头延迟线（tapped delay） |
| 晚期混响 | 80ms–数秒 | **空间感、尾巴** | 反馈网络 / 卷积 |

> [!tip] 关键洞察
> **早期反射决定"这是多大的房间"，晚期混响决定"这个房间什么样"。**
> 这就是为什么很多混响插件把这两部分分开处理——
> 只改晚期混响，房间大小的感觉不会变。

## 二、混响时间的数学：RT60

**RT60** = 声音衰减 60dB 所需的时间。

对最简单的情况（一个反馈延迟）：

```
每次循环，信号乘以 g（反馈增益）
n 次循环后，幅度 = g^n

衰减 60dB 意味着 g^n = 10^(-60/20) = 0.001
所以 n = log(0.001) / log(g)

RT60 = n * (延迟时间)
```

**代码**：

```python
def feedback_for_rt60(rt60, delay_time):
    """给定想要的 RT60 和延迟时间，算反馈增益。"""
    n = rt60 / delay_time          # 需要循环多少次
    return 10 ** (-3.0 / n)        # 每次循环的增益

# 例：延迟 50ms，想要 RT60 = 2 秒
g = feedback_for_rt60(2.0, 0.05)   # → 0.933
```

> [!warning] 反馈接近 1 时会失控
> `g = 0.999` 时，混响尾巴几乎不衰减，且**极易发散**（浮点误差累积）。
> **必须钳制**，通常上限 `g < 0.999`，并在反馈路径加 denormal 处理
> （见 [[denormal 数处理]]）。

> [!tip] 这个公式已实测验证（2026-10-14）
> 用单个梳状滤波器（延迟 1117 样本 = 23.27ms）实测衰减到 -60dB 的时间：
>
> | feedback | 理论 RT60 | 实测 RT60 | 偏差 |
> |---|---|---|---|
> | 0.8 | 0.72s | 0.74s | +3.4% |
> | 0.9 | 1.53s | 1.56s | +2.2% |
> | 0.95 | 3.13s | 3.16s | +1.0% |
> | 0.99 | 15.99s | 16.03s | +0.2% |
> | 0.999 | 160.67s | 160.71s | +0.0% |
>
> 偏差来自"衰减到 1e-3 的那一次循环"是离散的，符合预期。
> **结论：这个公式可以直接用在插件里。**

**不同房间的 RT60 参考**：

| 空间 | RT60 |
|---|---|
| 录音棚（强吸音） | 0.2–0.4 s |
| 客厅 | 0.4–0.6 s |
| 教堂 | 2–8 s |
| 大教堂 / 洞穴 | 8 s+ |

## 三、四种混响算法

### 1. Schroeder（最简单，1960s）

```
输入 → [4 个并联的梳状滤波器] → [2 个串联的全通滤波器] → 输出
```

- **梳状滤波器（comb filter）** 提供回声 → 反馈延迟
- **全通滤波器（allpass）** 打散回声、增加密度 → 不改变频响但改变相位

> [!warning] Schroeder 的问题：金属味（metallic）
> 因为并联的梳状滤波器延迟时间是**固定比例**的，
> 它们的回声会周期性重合，产生明显的"金属"共振。
>
> **解法**：用**互质**（mutually prime）的延迟时间，例如 1117, 1277, 1423, 1523 样本。
> 不要用 1000, 2000, 3000 这种整数倍关系——那会产生强烈的音高感。

### 2. Freeverb（Schroeder 的改良，开源经典）

在 Schroeder 基础上加了：
- 8 个并联梳状滤波器（而非 4 个）→ 更密
- 每个梳状滤波器内部有**阻尼低通** → 高频衰减更快（更自然）
- 4 个串联全通滤波器

```cpp
// Freeverb 的核心：带阻尼的梳状滤波器
float process(float input) {
    float output = buffer[index];
    filterStore = output * (1 - damp) + filterStore * damp;  // 阻尼低通
    buffer[index] = input + filterStore * feedback;
    if (++index >= size) index = 0;
    return output;
}
```

> [!tip] 阻尼（damping）为什么重要
> 真实房间里，**高频被空气和软表面吸收得更快**。
> 所以混响尾巴听起来应该越来越"暗"。
> 没有阻尼的混响，尾巴会一直很亮 → 听起来"假"、"金属"。
> **这就是你以前说的"数字味混响"的一个主要来源。**

### 3. FDN（Feedback Delay Network，反馈延迟网络）

```
输入 → [N 个延迟线] → [混合矩阵] → 反馈回延迟线
```

**关键**：用一个**正交矩阵**（如 Hadamard）混合各延迟线的输出再反馈。

- 用矩阵混合代替固定连接 → 密度高得多
- 衰减时间可以**每个频段不同**（加滤波器）
- 可以做成**多声道**（矩阵直接处理声道间关系）

> [!important] 为什么 FDN 好
> 因为**线性代数**在这里直接变成音质。
> 正交矩阵保证能量守恒（不发散），同时最大化回声的"去相关"。
> 你的线性代数没忘，这里就是它派上用场的地方。

### 4. 卷积混响（Convolution Reverb）

**原理**：拿到真实空间的**脉冲响应（IR）**，和你的音频做**卷积**。

```
y[n] = Σ x[k] · h[n-k]
```

- **优点**：真实度最高，直接"复制"一个真实空间
- **缺点**：不能实时改参数（改了要重新卷积）；长 IR 计算量大

**实时实现**：用 **FFT 的分段卷积**（overlap-add / overlap-save）
- 直接卷积 O(N·M) 太慢
- FFT 卷积降到 O(N log N)

> [!warning] 卷积混响的"不能调参数"问题
> 用户想调 decay？只能：
> - 对 IR 做时变包络（会引入伪影）
> - 或者准备多个 IR 交叉淡化
> 这是卷积混响相对算法混响的根本劣势。

## 四、参数 → 算法映射表

**这一节是这一页最重要的部分。** 音乐人拧的每个旋钮，背后是什么。

| 插件上的参数 | 你听到的 | 算法上要实现 |
|---|---|---|
| **Size / Room Size** | 房间变大 | 延迟线长度变长（早期反射的间隔 + 晚期混响的基延迟） |
| **Decay / Time** | 尾巴变长 | 反馈增益变大（见 RT60 公式） |
| **Pre-delay** | 声源离墙更远 | 干信号前的纯延迟，通常 0–100ms |
| **Damping / HF Damp** | 尾巴变暗 | 反馈路径里加低通滤波器，截止频率随 damping 降低 |
| **Diffusion** | 回声更"糊"/更密 | 全通滤波器的系数，或矩阵混合的强度 |
| **Width / Stereo** | 变宽 | 左右声道用不同的延迟时间（去相关） |
| **Low Cut / HF Cut** | 去掉低频轰鸣 | 反馈路径里加高通/低通 |
| **Modulation / Chorus** | 尾巴"活"起来 | 用 LFO 调制延迟线长度（几 ms 级别） |
| **Mix / Dry-Wet** | 干湿比 | 直接混合 |
| **Early / Late 平衡** | 房间大小 vs 空间感 | 分别调整两部分的增益 |

> [!tip] 这张表就是你的产品差异化来源
> 当你觉得某个混响"不对"时，对着这张表找：
> 是阻尼不够（尾巴太亮）？是扩散不足（听到离散回声）？
> 是缺少调制（尾巴太"死"）？还是早期反射太少（没有房间感）？
>
> **你能听出问题，这张表告诉你改哪个参数。** 这就是你的优势变现的方式。

## 五、为什么"调制"让混响听起来更真

> [!important] 一个反直觉的事实
> **真实的房间不是静止的。** 空气流动、温度变化、人的移动，
> 都会让反射路径发生微小变化。
>
> 更重要的：**固定延迟线会产生驻波**（梳状滤波的峰谷），
> 听起来像"金属管"。
>
> **解法**：用 LFO 轻微调制延迟线长度（±1–3ms，0.1–1Hz）。
> 这会把固定的峰谷"抹开"，尾巴变得平滑、自然。

**实现**：

```cpp
// 用 LFO 调制延迟线读取位置（需要分数延迟插值）
float modDepth = 2.0f;                       // ±2ms
float mod = lfo.next() * modDepth * sampleRate * 0.001f;
float delaySamples = baseDelay + mod;
float out = delayLine.readInterpolated(delaySamples);   // 线性或全通插值
```

> [!warning] 调制的副作用
> 调制延迟线 = 多普勒效应 = **轻微的音高变化**。
> 少量是"活"，大量就变成"合唱"或"跑调"。
> 而且左右声道用**不同的 LFO 相位**才能产生宽度感。

## 六、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| **金属味 / 铃声感** | 延迟时间成整数倍关系，产生驻波 | 用互质延迟时间；加调制 |
| **尾巴太亮、不自然** | 没有阻尼（高频不衰减） | 反馈路径加低通 |
| **低频轰鸣** | 低频衰减太慢，能量堆积 | 反馈路径加高通（见下） |
| **静音时 CPU 飙升** | denormal 数 | 见 [[denormal 数处理]] |
| **反馈发散（爆炸）** | 反馈增益 ≥ 1，或浮点误差累积 | 钳制 g < 0.999；用正交矩阵 |
| **改参数时爆音** | 延迟时间突变 | 交叉淡化，不要直接平滑（见下） |
| **单声道兼容性差** | 左右完全去相关 | 检查 mono 下的相位抵消 |
| **声音"贴脸"** | 没有 pre-delay | 加 10–30ms pre-delay |

> [!warning] 改混响参数时的爆音
> **延迟时间不能直接平滑**——那会产生多普勒变调。
> 正确做法是**交叉淡化**：旧延迟淡出，新延迟淡入。
> 详见 [[延迟与回声的原理]]。

## 七、怎么验证你的混响是对的

| 测试 | 方法 | 期望结果 |
|---|---|---|
| **稳定性** | 喂脉冲，跑 10 秒 | 输出必须衰减到 0，不能发散 |
| **RT60 准确性** | 喂脉冲，测衰减曲线 | 实测 RT60 应接近设定值（±20% 可接受） |
| **无输入时静音** | 停止输入后等待 | 尾巴结束后应完全静音（不是极小值持续） |
| **频响** | 白噪声输入，看稳态频谱 | 不应有明显的梳状峰谷（除非故意） |
| **单声道兼容** | 左右相加 | 不应有明显抵消 |
| **CPU 占用** | 测最大实例数 | 应该稳定，不随信号衰减而升高（denormal） |

> [!tip] 用 Python 先验证，再写 C++
> 混响的算法复杂度高、bug 隐蔽。
> **先用 numpy 写一个版本，用上面的测试验证，再移植到 C++。**
> 见 [[Python 优先的 DSP 学习路径]]。

## 八、给你的建议路线

```
1. 先做最简单的：单个反馈延迟 (feedback delay)
      → 理解 RT60 与反馈增益的关系

2. 加 4 个并联梳状滤波器 + 2 个全通 = Schroeder
      → 第一次听到"房间"

3. 给每个梳状加阻尼低通 = Freeverb 的核心
      → 第一次听到"自然"的混响

4. 加 LFO 调制
      → 第一次听到"活"的混响

5. 换成 FDN + 正交矩阵
      → 理解线性代数在这里的作用

6. 卷积混响（需要 FFT 分段卷积）
      → 理解"真实空间"的代价
```

> [!note] 为什么这个顺序
> 因为每一步都只加**一个**新概念，而且每一步都能**听出区别**。
> 直接上 FDN 或卷积，你会同时面对"矩阵对不对"、"FFT 写没写错"、
> "为什么听起来还是不对"三个问题。

## AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **把反馈增益设成 ≥1** | 发散（爆音） | 检查 g < 1 |
| 2 | **延迟线长度写死采样数** | 换采样率后时间错 | 按秒定义，见 [[采样率变化处理]] |
| 3 | **不做阻尼** | 高频永不衰减（不真实） | 反馈路径加低通 |
| 4 | **梳状滤波器用质数长度** | 金属感/周期性 | 用互质长度 |
| 5 | **忘了去直流** | 低频嗡声 | 反馈环里加高通 |
| 6 | **参数突变不平滑** | 爆音/zipper | 平滑所有参数 |
| 7 | **在音频线程重建延迟线** | 违反实时契约 | `prepareToPlay` 里分配 |
| 8 | **以为 RT60 与频率无关** | 不真实 | 分频段不同衰减 |

> [!danger] 第 1 条是致命的
> 反馈增益 ≥ 1 → **指数增长** → 输出 `inf` →
> 进入反馈环后**永不恢复**（见 [[浮点异常]]）。
>
> **判据**：所有反馈路径的增益是否严格 < 1？有没有 `isfinite` 防护？
