# 代码签名与公证

> [!important] 一句话
> **macOS 和 Windows 是两套完全不同的流程。**
> 但目的相同：让操作系统相信"这个软件来自已知的开发者，且没被篡改"。

> [!warning] 本页的准确性说明
> - **macOS 侧**：本机实测过（`codesign` / `spctl` / `notarytool` 都在）
> - **Windows 侧**：⚠️ **本机无法实测**，标注了需要你自己核实的地方
> - 证书价格、苹果/微软的政策**会变**，做决策前回官方页面

## 为什么需要

| 平台 | 不签名的后果 |
|---|---|
| **macOS** | Gatekeeper 拦截，用户看到"无法打开，因为无法验证开发者" |
| **Windows** | SmartScreen 警告"未知发布者"，用户需要点"仍要运行" |

> [!note] 对你的实际影响
> 你的用户是**音乐人**，不是开发者。
> 看到"无法验证开发者"他们**不会去查怎么绕过**——他们会直接放弃。

---

## 一、签名 vs 公证（最容易混淆的一对）

> [!danger] 这是本页最重要的概念区分
> **签名（Signing）和公证（Notarization）是两件事。**

| | 签名 | 公证 |
|---|---|---|
| **做什么** | 用你的证书给二进制"盖章" | 把签名后的包**提交给苹果审核** |
| **谁做** | 你本地（`codesign`） | 你提交，**苹果**审核（`notarytool`） |
| **证明什么** | "这是我签的，且没被改过" | "苹果已扫描过，没发现恶意代码" |
| **需要联网** | ❌ 不需要 | ✅ 需要 |
| **耗时** | 秒级 | 分钟级（有时更久） |
| **必须吗** | 要公证就必须先签名 | 要过 Gatekeeper 就必须公证 |

**完整流程（macOS）**：

```
1. codesign      给你的插件签名（本地）
2. notarytool    提交给苹果公证（联网，等几分钟）
3. stapler       把公证票据"钉"到你的包上（本地）
```

> [!tip] 第 3 步为什么必要
> 公证的结果存在苹果服务器上。`stapler` 把票据**存进你的包**，
> 这样用户**离线**也能验证——否则用户断网时 Gatekeeper 可能无法确认。

## 二、真实样本（本机实测）

我检查了本机一个已正确发布的 App（Obsidian），它的签名信息长这样：

```
Executable=/Applications/Obsidian.app/Contents/MacOS/Obsidian
Identifier=md.obsidian
Format=app bundle with Mach-O universal (x86_64 arm64)     ← 双架构
CodeDirectory v=20500 size=631 flags=0x10000(runtime)      ← runtime = Hardened Runtime
Authority=Developer ID Application: Dynalist Inc. (6JSW4SJWN9)   ← 签名证书
Authority=Developer ID Certification Authority
Authority=Apple Root CA                                     ← 证书链完整
Timestamp=Mar 23, 2026 at 23:22:17                          ← 可信时间戳
Notarization Ticket=stapled                                 ← 公证票据已钉入 ✅
TeamIdentifier=6JSW4SJWN9
Runtime Version=26.0.0
Sealed Resources version=2 rules=13 files=22
```

**验证命令与结果**：

```bash
# 1. 签名是否有效
codesign -v --verbose=2 /Applications/Obsidian.app
#   → valid on disk
#   → satisfies its Designated Requirement

# 2. 公证票据是否钉入
xcrun stapler validate /Applications/Obsidian.app
#   → The validate action worked!

# 3. Gatekeeper 是否放行
spctl -a -vv /Applications/Obsidian.app
#   → accepted
#   → source=Notarized Developer ID
```

> [!tip] 这三条命令就是你的"发布前检查清单"
> 把路径换成你的插件，三条都通过才算合格。

## 三、macOS：证书类型

| 证书 | 用途 | 需要付费开发者账号吗 |
|---|---|---|
| **Developer ID Application** | **分发到 App Store 之外**（你要的） | ✅ 需要 |
| Apple Development | 本地开发调试 | ✅ |
| Mac App Store | 上架 App Store | ✅ |
| **自签名（ad-hoc）** | 只能本机用 | ❌ 不需要 |

> [!warning] ⚠️ 需自行核实（本页不写死）
> - 苹果开发者账号的**当前年费**
> - 个人 vs 组织的申请条件
> - 中国区开发者的特殊要求
>
> 去 [developer.apple.com](https://developer.apple.com/) 确认。

**ad-hoc 签名能做什么**：

```bash
codesign -s - --deep MyPlugin.vst3      # "-s -" = ad-hoc
```

| 能做 | 不能做 |
|---|---|
| 本机测试 | 分发给别人（Gatekeeper 会拦） |
| 满足某些本地验证 | 公证 |

> [!tip] 开发阶段用 ad-hoc 就够了
> 只有**发布**才需要真正的证书和公证。

## 四、Hardened Runtime（硬化运行时）

公证要求开启 Hardened Runtime，但它会**限制一些操作**。

```bash
codesign --sign "Developer ID Application: ..." \
         --options runtime \              # ← 开启 Hardened Runtime
         --timestamp \                    # ← 加可信时间戳
         --deep \                         # ← 递归签内部所有组件
         MyPlugin.vst3
```

> [!danger] 音频插件常见的问题：JIT 与动态库
> 如果你的插件用了需要 JIT 或加载未签名动态库的东西，
> Hardened Runtime 会**阻止**它 → 插件崩溃或功能失效。
>
> 解法：加 **entitlements**（权限声明），例如：
> - `com.apple.security.cs.allow-jit`
> - `com.apple.security.cs.disable-library-validation`
>
> ⚠️ **每个 entitlement 都是安全让步**，只加真正需要的。
> 具体该加哪些**需要实测**（本机无插件，无法验证）。

## 五、签名要签"每一层"

> [!warning] 插件是 bundle（目录），不是单个文件
> `codesign --deep` 会递归签内部，但**`--deep` 有已知局限**。
> 更可靠的做法是**从内到外逐层签**。

```
MyPlugin.vst3/
└── Contents/
    ├── MacOS/MyPlugin          ← 1. 先签可执行文件
    ├── Frameworks/*.dylib      ← 2. 再签动态库
    └── (整个 bundle)            ← 3. 最后签 bundle
```

> [!note] `--deep` 的取舍
> - ✅ 简单，一条命令
> - ⚠️ 苹果文档曾建议**不要**依赖 `--deep` 做发布签名
>
> **建议**：先用 `--deep` 跑通流程，发布前查苹果最新文档。

## 六、Windows：完全不同的流程

> [!warning] 本机是 macOS，**以下内容无法实测**，请自行核实

| 项 | 说明 |
|---|---|
| **工具** | `signtool`（Windows SDK 的一部分） |
| **证书格式** | 通常是 `.pfx` 文件 |
| **证书类型** | 标准 vs **EV（扩展验证）** |
| **SmartScreen** | EV 证书**立即获得信誉**；标准证书需要累积下载量 |

**基本命令**（⚠️ 需核实参数）：

```
signtool sign /f cert.pfx /p <password> /tr <timestamp-url> /td sha256 MyPlugin.vst3
```

> [!danger] ⚠️ 需要你自己核实的几点（变化快）
> - **2023 年后的证书存储新规**：私钥必须存在硬件令牌或云 HSM 中
>   （这会影响 CI 怎么做）
> - EV 证书的**当前价格**
> - SmartScreen 信誉的具体机制
> - 时间戳服务器的地址
>
> 见 [[Windows 代码签名]]（待写）和 [[_meta/open-questions]]。

## 七、CI 里怎么做

> [!important] 核心难点：怎么把证书安全地放进 CI

| 步骤 | macOS | Windows |
|---|---|---|
| 1 | 证书导出为 base64，存 CI secrets | `.pfx` 存 secrets |
| 2 | CI 里解码 → 导入临时 keychain | 导入证书存储 |
| 3 | `codesign` + `notarytool` | `signtool` |
| 4 | 用完删除临时 keychain | 清理 |

> [!warning] 不要做的事
> - ❌ 把证书提交进仓库
> - ❌ 把密码写进 CI 配置文件（用 secrets）
> - ❌ 在日志里打印证书内容

**公证需要的凭据**（`notarytool`）：

```bash
# 推荐：用 API Key 而不是 Apple ID 密码
xcrun notarytool submit MyPlugin.zip \
      --keychain-profile "AC_PASSWORD" \
      --wait
```

> [!tip] `--keychain-profile` 是推荐做法
> 凭据存在 keychain 里，命令行不暴露密码。
> 具体配置命令**需查 `notarytool` 文档**。

## 八、AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **混淆签名和公证** | 流程漏一步 | 记住是三步：sign → notarize → staple |
| 2 | **忘记 stapler** | 用户离线时验证失败 | `stapler validate` |
| 3 | **编造证书价格 / 政策** | 决策错误 | 回官方页面 |
| 4 | **`--deep` 当成万能** | 内部组件没签全 | 逐层验证 `codesign -v` |
| 5 | **忘了 `--timestamp`** | 证书过期后签名失效 | 检查命令有没有 `--timestamp` |
| 6 | **Hardened Runtime 缺 entitlement** | 插件崩溃/功能失效 | 实测；看崩溃日志 |
| 7 | **用 Apple ID 密码做公证** | 不安全 | 用 API Key |
| 8 | **把证书写进仓库** | 严重安全事故 | grep 仓库 |

> [!warning] 第 3 条特别常见
> **AI 对证书价格和平台政策的记忆普遍过时且自信。**
> 这类"会变的事实"永远回官方页面确认。

## 九、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 用户看到"无法验证开发者" | 没公证 | 走完 sign → notarize → staple |
| 公证通过了但 Gatekeeper 还是拦 | 没 staple | `xcrun stapler staple` |
| 签名后插件加载失败 | Hardened Runtime 限制 | 加必要的 entitlement |
| 换了机器签名失效 | 缺可信时间戳 | 加 `--timestamp` |
| CI 里签名失败 | 证书没正确导入 | 检查 keychain 设置 |
| 公证被拒 | 包含不允许的内容 | 看 `notarytool` 的日志输出 |
| Windows 用户看到警告 | 没签名或证书信誉不足 | 签名；考虑 EV 证书 |

## 十、怎么验证（发布前清单）

```bash
# macOS 三条验证命令（把路径换成你的插件）
codesign -v --verbose=2 MyPlugin.vst3          # 1. 签名有效
xcrun stapler validate MyPlugin.vst3           # 2. 公证票据已钉入
spctl -a -vv MyPlugin.vst3                     # 3. Gatekeeper 放行
```

- [ ] 签名有效（`codesign -v` 通过）
- [ ] 公证票据已 stapled
- [ ] Gatekeeper 评估为 `accepted`
- [ ] 证书链完整（`Authority` 显示到 Apple Root CA）
- [ ] 有可信时间戳
- [ ] 在**另一台没装过你证书的 Mac** 上测试
- [ ] Windows 侧同理（⚠️ 需自行核实具体命令）

> [!tip] 最可靠的验证：换一台干净的机器
> 你自己的机器上装了证书和信任设置，**测不出真实用户的体验**。
> 找一台从没装过你开发环境的 Mac 试。
