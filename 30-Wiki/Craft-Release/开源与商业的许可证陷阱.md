# 开源与商业的许可证陷阱

> [!important] 一句话
> **做音频插件要用三层东西：插件格式 SDK、开发框架、第三方库。**
> 每层都有自己的许可证，**它们会叠加**。搞错一层，你的闭源商业插件就可能违法。

> [!warning] 本页信息核实于 2026-10-14
> 许可证条款**会变**。做商业决策前**必须**回官方页面确认。
> 本页标注了每条信息的来源和核实日期。

## 三层许可证

```
你的插件
  ├── 插件格式 SDK     ← VST3 / AU / CLAP / AAX
  ├── 开发框架          ← JUCE / iPlug2 / DPF
  └── 第三方库          ← DSP 库、UI 库、JSON 库……
```

**任何一层是 copyleft（如 GPL/AGPL），都可能传染到你的整个插件。**

---

## 一、VST3：2025 年已经变成 MIT ✅

> [!important] 这是最近最重要的变化
> **自 VST 3.8 起，VST3 采用 MIT 许可证。**
>
> 来自 Steinberg 官方开发者门户（核实于 2026-10-14）：
> - ✅ 采用 MIT 许可证，可用于完整开源集成
> - ✅ **不需要费用，不需要会员资格**
> - ✅ **不需要签署任何文件**
> - ✅ 许可证**永久有效，不会过期**
> - ✅ MIT 许可的代码可自由使用、修改、再分发，**包括商业产品**
> - ⚠️ **注意：GPLv3 和 Steinberg 专有许可已不再提供**

**这意味着什么**：

| 以前（VST 3.7 及之前） | 现在（VST 3.8+） |
|---|---|
| 双授权：GPLv3 或 Steinberg 专有 | **只有 MIT** |
| 闭源商业要买专有授权 | **免费，MIT 即可** |
| 许可证复杂，需要法务看 | 一行 MIT，谁都能看懂 |

> [!tip] 对你是好消息
> 你之前担心的"VST3 SDK 双授权麻烦"**已经不存在了**。
> 现在 VST3 是三层里**最没有负担**的一层。

> [!warning] 两个注意点
> 1. **VST 2 不在这个许可范围内**。Steinberg 已停止发放 VST2 授权，且明确说明 "VST 2 API source code is NOT part of this VST 3 license"。**别做 VST2**。
> 2. **商标使用是可选的但受约束**。MIT 下你可以不用 "VST" 名字和 Logo；如果你要用，必须遵守 Steinberg 的商标规范。

**来源**：[VST 3 License — Steinberg 开发者门户](https://steinbergmedia.github.io/vst3_dev_portal/pages/VST+3+Licensing/VST3+License.html)

## 二、JUCE：AGPLv3 或商业授权（双授权）

**JUCE 仍然是双授权**（核实于 2026-10-14）：

> JUCE Framework 模块在 **AGPLv3** 和 **商业 JUCE 许可证**下双授权。

### 商业授权的四档（JUCE 8 EULA）

| 档位 | 年收入/资金上限 | 订阅价（每用户/月） | 永久授权（每用户） |
|---|---|---|---|
| **Starter** | ≤ $20,000 | N/A | **免费** |
| **Indie** | ≤ $300,000 | $40 | $800 |
| **Pro** | 无限制 | $175 | $3,500 |
| **Educational** | 无限制 | N/A | 免费 |

> [!important] 对你最相关的一档：Starter
> **年收入 ≤ $20,000 时，永久授权免费。**
> 你如果只是兴趣项目或刚起步，**大概率就在这一档**。
>
> 但注意：**收入上限是按"你从所有来源获得的总收入"算的**，
> 不是只算插件收入。原文：
> > "如果 License 持有者是个体，适用上限是该个体**从其使用 Framework 的所有来源**获得的全部收入或资金，包括捐赠、赞助、广告以及任何其他间接收入。"
>
> **如果你有全职工作，你的工资算不算？** —— 这是个需要自己判断（或咨询律师）的问题。
> 论坛上对此有争议。**不要想当然。**

### AGPLv3 那一侧

**AGPLv3 是强 copyleft**，而且比 GPL 更严格——**网络服务也算分发**。

对你的实际影响：

| 你的情况 | AGPLv3 下可以吗 |
|---|---|
| 开源你的插件（AGPLv3） | ✅ 可以 |
| 闭源免费发布 | ❌ 不行 |
| 闭源商业销售 | ❌ 不行 |
| 开源但用别的许可证 | ❌ 不行（必须 AGPLv3 兼容） |

> [!danger] 最常见的误解
> **"我只是自己用/免费发布，所以不用管许可证"——这是错的。**
> AGPLv3 要求你**把源代码提供给使用者**，不管你是否收费。
> 免费发布闭源插件 = 违反 AGPLv3。

**来源**：[JUCE 8 EULA](https://juce.com/legal/juce-8-licence/)、[JUCE 官方 Get JUCE 页](https://juce.com/get-juce/)

## 三、CLAP：MIT ✅

CLAP 采用 **MIT 许可证**（核实于 2026-10-14）。

来自官方说明：
> "MIT 许可证意味着你可以在你的软件中使用 CLAP 代码的任何部分，
> **无论是开源、闭源、免费还是商业**。"

**结论**：CLAP 和 VST3 一样，**没有许可证负担**。

**来源**：[CLAP 官网 — An Open License](https://cleveraudio.org/1-feature-overview/_open_licnese/)

## 四、AU（Audio Units）：苹果的框架

Apple 的 Audio Unit 框架是**系统框架**，随 macOS/iOS 提供。

> [!warning] 需要核实
> 苹果对 AU 的使用条款（尤其在 App Store 分发时）有自己的要求。
> 我**没有**找到明确的"AU 插件开发许可证"页面。
> **做商业发布前查 Apple 开发者协议。**

## 五、AAX：Avid 的封闭生态

> [!warning] 需自行核实（本页不写死答案）
> AAX 需要加入 Avid 的开发者计划，**通常涉及审批**，
> 且可能需要 **PACE 签名**（iLok）。
>
> **具体费用与门槛我没有核实**，见 [[_meta/open-questions|open-questions 的 F4]]。
>
> **建议**：除非有明确的 Pro Tools 用户需求，**先跳过 AAX**。

## 六、第三方库的许可证陷阱

| 许可证 | 能用在闭源商业插件吗 | 注意 |
|---|---|---|
| **MIT / BSD / zlib** | ✅ 可以 | 保留版权声明即可 |
| **Apache 2.0** | ✅ 可以 | 有专利条款，需保留 NOTICE |
| **LGPL** | 🟠 有条件 | **动态链接**通常可以；静态链接要提供目标文件 |
| **GPL / AGPL** | ❌ 不行 | 传染整个插件 |
| **无许可证** | ❌ **不能用** | 没有许可证 = 保留所有权利 |

> [!danger] 最后一个是最容易踩的坑
> **GitHub 上很多代码没有 LICENSE 文件。**
> 没有许可证**不等于**公共领域——默认是"保留所有权利"。
> **你不能用。** 想用就得联系作者要授权。

## 七、决策表：你该怎么做

| 你的情况 | 推荐 |
|---|---|
| **自己用 / 学习** | JUCE **Starter**（年收入 ≤ $20k，免费）或 AGPLv3 开源 |
| **免费开源发布** | JUCE + AGPLv3（把源码一起开源） |
| **闭源免费发布** | JUCE 商业授权（Starter 档免费）或改用 **iPlug2** |
| **闭源商业销售** | 看年收入选 JUCE 档位；或用 iPlug2 / DPF（宽松许可） |
| **不想碰许可证问题** | 用 **iPlug2**（zlib-like 许可，闭源友好） |

> [!tip] 一个容易被忽略的替代方案
> **iPlug2** 采用 **zlib-like 许可证**：
> 可以自由用于闭源项目，没有 JUCE 的收入门槛。
>
> 代价：社区小、文档少、**AI 训练数据远少于 JUCE**
> （这对"主要让 AI 写代码"的你是实际损失）。
>
> 见 [[ADR-002 选择框架]]。

## 八、AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **说"VST3 是 GPLv3 或专有双授权"** | 过时信息（3.8 起是 MIT） | 回官方页面确认 |
| 2 | **说"JUCE 是免费开源的"** | 漏掉 AGPL 的传染性 | 明确"双授权" |
| 3 | **编造具体价格/收入门槛** | 记错了有法律后果 | 只用官方页面的数字 + 标注核实日期 |
| 4 | **建议"用 AGPL 代码但闭源发布"** | 违法 | 检查是否 copyleft |
| 5 | **说"没写 LICENSE 就是公共领域"** | 完全错误 | 无许可证 = 保留所有权利 |
| 6 | **忽略 LGPL 的动态/静态链接区别** | 可能违反 | 查具体链接方式 |
| 7 | **把 VST2 和 VST3 的许可证混为一谈** | VST2 不在 MIT 范围内 | 明确区分 |

> [!warning] 这一节的特殊风险
> **AI 对许可证的记忆普遍过时且自信。**
> 训练数据里大量是 2023–2024 年的内容，而 **VST3 改成 MIT 是 2025 年的事**。
>
> **许可证问题永远不要只信 AI。** 回官方页面。

## 九、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 以为 VST3 要付费 | 用了过时信息 | 3.8+ 是 MIT，免费 |
| 闭源发布后被要求开源 | 用了 AGPL 的 JUCE | 买商业授权，或换框架 |
| 收入超了 Starter 档还不知道 | 没跟踪收入 | 超过 $20k 要升级档位 |
| 用了没许可证的 GitHub 代码 | 以为"公开就能用" | 联系作者要授权 |
| 静态链接了 LGPL 库 | 以为 LGPL 随便用 | 改动态链接，或提供目标文件 |
| 想做 VST2 | 以为还能授权 | 已停止，做 VST3 |

## 十、怎么验证（发布前清单）

- [ ] 列出**所有**依赖（SDK / 框架 / 库），逐个查许可证
- [ ] VST3 SDK：确认版本 ≥ 3.8（MIT）
- [ ] JUCE：确认档位与当前年收入匹配
- [ ] 检查每个第三方库**有没有 LICENSE 文件**
- [ ] 检查有没有 copyleft（GPL/AGPL）依赖
- [ ] 如果分发二进制：确认许可证要求的声明都包含在内
- [ ] **回官方页面复核一遍**（不要只信本页或 AI）

```bash
# 快速检查项目依赖的许可证
grep -riE "license|copying" --include="LICENSE*" --include="COPYING*" -l . | head -20
```
