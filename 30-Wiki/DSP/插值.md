# 插值

> [!important] 一句话
> **插值 = 在已知的离散样本之间"猜"出中间值。**
> 在音频里，它几乎总是为了做**分数延迟**（延迟时间不是整数个采样）。

## 为什么音频需要插值

延迟时间很少正好是整数个采样：

| 场景 | 为什么不是整数 |
|---|---|
| **BPM 同步延迟** | 1/8 三连音 @120BPM = 166.67ms = 8000.16 采样 |
| **Chorus / Flanger** | LFO 让延迟连续变化 |
| **混响调制** | 缓慢调制延迟线长度（±1–3ms） |
| **音高变换** | 本质就是变速读取 |
| **采样器** | 音高偏移后读取位置不整 |
| **波表合成** | 相位累加器的小数部分 |

**不用插值（四舍五入到整数）的后果**：
- 单次延迟：几乎听不出
- **调制类效果**：听到"台阶感"（阶梯状的音高变化）

---

## 一、四种方法的实测对比（**本页核心**）

**测试条件**：48kHz，输入 1.0 幅度正弦，frac = 0.5（最坏情况）

| 频率 | 线性插值 | Lagrange 3 阶 | 全通（理论） |
|---|---|---|---|
| 100 Hz | -0.00 dB | -0.00 dB | 0.00 dB |
| 1 kHz | -0.04 | -0.02 | 0.00 |
| 5 kHz | -0.49 | -0.05 | 0.00 |
| 10 kHz | -2.09 | -0.61 | 0.00 |
| 15 kHz | -5.27 | -2.69 | 0.00 |
| **20 kHz** | **-12.04** | **-8.72** | **0.00** |

> [!danger] 这就是"分数延迟听起来发闷"的原因
> **线性插值在 20kHz 处衰减 12 dB。**
>
> 而且注意：**所有方法在低频都很好**，问题全在高频。
> 所以症状是"高频发闷/失去空气感"，而不是"声音不对"。
>
> **Lagrange 3 阶只改善到 -8.72 dB** —— 比线性好，但仍远非完美。
> 这是分数延迟插值的**固有限制**：越接近 Nyquist，越难做对。

> [!note] frac 的影响
> frac = 0（整数延迟）时**所有方法都完美**（0 dB 全频段）。
> frac = 0.5 时最差。frac = 0.25 和 0.75 对称，介于两者之间。

## 二、方法 1：线性插值

```cpp
float readFractional (float d) const
{
    const int i0 = (int) d;
    const float frac = d - (float) i0;
    const float a = readDelayed (i0);
    const float b = readDelayed (i0 + 1);
    return a + frac * (b - a);
}
```

**频率响应**（解析）：

$$H(f) = (1-\phi) + \phi\, e^{-j2\pi f/f_s}$$

**优点**：最简单、最快（1 次乘加）、无稳定性问题。
**缺点**：高频衰减严重（见上表）。

> [!tip] 什么时候线性插值够用
> - 延迟**不调制**（固定分数延迟，只做一次）
> - 调制**幅度很小**（±0.1 采样以内）
> - 混响的**缓慢**调制（高频衰减不易察觉）
> - CPU 预算极紧
>
> **什么时候不够**：Chorus / Flanger（高频衰减会被听出来）、音高变换。

## 三、方法 2：Lagrange 插值（3 阶，4 点）

用 4 个邻近样本做三次多项式拟合。

**系数**（延迟 $\phi \in [0,1)$）：

```
c[-1] = -φ(φ-1)(φ-2)/6
c[ 0] =  (φ+1)(φ-1)(φ-2)/2
c[ 1] = -(φ+1)φ(φ-2)/2
c[ 2] =  (φ+1)φ(φ-1)/6
```

**验证**（系数之和恒为 1，保证直流增益为 1）：

| φ | 系数 | 和 |
|---|---|---|
| 0.00 | [0, 1, 0, 0] | 1.000000 ✅（退化为整数延迟） |
| 0.25 | [-0.0547, 0.8203, 0.2734, -0.0391] | 1.000000 |
| **0.50** | **[-0.0625, 0.5625, 0.5625, -0.0625]** | 1.000000 |
| 0.75 | [-0.0391, 0.2734, 0.8203, -0.0547] | 1.000000 |

> [!note] φ=0 时退化为纯整数延迟
> 这说明公式正确——没有引入任何"额外的"东西。

**实现**：

```cpp
float readLagrange3 (float d) const
{
    const int i0 = (int) d;
    const float f = d - (float) i0;
    const float c0 = -f * (f - 1.0f) * (f - 2.0f) / 6.0f;
    const float c1 =  (f + 1.0f) * (f - 1.0f) * (f - 2.0f) / 2.0f;
    const float c2 = -(f + 1.0f) * f * (f - 2.0f) / 2.0f;
    const float c3 =  (f + 1.0f) * f * (f - 1.0f) / 6.0f;

    return c0 * readDelayed (i0 - 1)
         + c1 * readDelayed (i0)
         + c2 * readDelayed (i0 + 1)
         + c3 * readDelayed (i0 + 2);
}
```

**优点**：明显好于线性（20kHz 从 -12.04 改善到 -8.72 dB）。
**缺点**：4 倍计算量；仍非完美。

> [!tip] Hermite 插值（另一种 4 点方法）
> Hermite 用**函数值和导数**拟合，系数更简单：
> ```cpp
> // 3阶 Hermite（Catmull-Rom 形式）
> float h00 = 2*f*f*f - 3*f*f + 1;
> float h10 = f*f*f - 2*f*f + f;
> float h01 = -2*f*f*f + 3*f*f;
> float h11 = f*f*f - f*f;
> ```
> 质量与 Lagrange 接近，**系数计算更便宜**。实践中常用 Hermite。

## 四、方法 3：全通插值（幅度完美）

**原理**：全通滤波器**幅度响应恒为 1**（这就是"全通"的定义），
但相位响应随频率变化 → 恰好可以当分数延迟用。

**一阶全通分数延迟**（Thiran 近似）：

```cpp
class AllpassInterp
{
public:
    void setFraction (float frac)
    {
        // ⚠️ frac → 0 时 a → 1，极点趋于单位圆 → 不稳定
        eta = (frac > 1e-4f) ? (1.0f - frac) / (1.0f + frac) : 0.0f;
    }
    float process (float x)
    {
        const float y = eta * (x - yPrev) + xPrev;
        xPrev = x;  yPrev = y;
        return y;
    }
private:
    float eta = 0.0f, xPrev = 0.0f, yPrev = 0.0f;
};
```

| 优点 | 缺点 |
|---|---|
| **幅度全频段完美平坦** | 相位非线性（有轻微相位失真） |
| 计算量小（1 乘 2 加） | **frac → 0 时数值不稳定**，需切换到整数读取 |
| 有反馈 → 需要状态管理 | 只能做 **1 个采样以内**的分数延迟 |

> [!warning] 全通插值的两个陷阱
> 1. **frac 接近 0 时必须切换**：`eta → 1` 时极点在单位圆上，会自激
> 2. **它是有状态的**：改变 frac 会改变滤波器状态 → 调制时可能有瞬态
>
> 所以实践中常看到：**frac 小的时候用线性，大的时候用全通**。

## 五、方法 4：窗化 Sinc（质量最高）

**理论上完美的插值**是 Sinc 插值：

$$x(t) = \sum_{n} x[n] \cdot \mathrm{sinc}\!\left(\frac{t - nT}{T}\right)$$

**问题**：Sinc 无限长。实际做法是**加窗截断**（如 Blackman 窗 + 8–32 个点）。

| 点数 | 质量 | CPU |
|---|---|---|
| 4（Lagrange/Hermite） | 好 | 低 |
| 8 | 很好 | 中 |
| 16–32 | 接近完美 | 高 |

> [!tip] 什么时候需要窗化 Sinc
> - **音高变换**（质量要求最高，误差会被放大）
> - **高质量采样器**（多采样层、极端音高偏移）
> - **离线渲染**（不在乎 CPU）
>
> 实时调制效果通常**不需要**——Lagrange/Hermite 够了。

## 六、选择决策表

| 场景 | 推荐 | 理由 |
|---|---|---|
| 固定延迟（BPM 同步） | **整数**（如果可能） | 零成本、完全透明 |
| 固定分数延迟 | 线性 | 只衰减一次，听不出 |
| **Chorus / Flanger** | **全通** 或 **Hermite** | 高频衰减会被听出来 |
| 混响的缓慢调制 | 线性（可接受） | 衰减不易察觉 |
| **音高变换** | **窗化 Sinc（16+ 点）** | 质量要求最高 |
| 波表合成 | 线性 或 Hermite | 取决于质量要求 |
| CPU 极紧 | 线性 | — |

## 七、AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **完全不做插值**（直接取整） | 调制时有台阶感 | 检查 `(int)d` 后有没有用小数部分 |
| 2 | **`(int)` 对负数截断方向错** | 负延迟时索引错 | C++ 的 `(int)` 是**向零截断**，不是向下取整 |
| 3 | **全通插值不处理 frac→0** | 自激/爆炸 | 检查有没有 `if (frac < eps)` |
| 4 | **插值用了未来的样本**（非因果） | 延迟少一个采样 | 检查索引方向 |
| 5 | **线性插值做音高变换** | 高频严重衰减 | 换窗化 Sinc |
| 6 | **Lagrange 系数公式抄错** | 直流增益不为 1 | 检查系数和是否为 1 |
| 7 | **每样本重算插值系数** | 浪费 CPU（可以增量算） | 看是否有优化空间 |

> [!warning] 第 2 条特别隐蔽
> ```cpp
> (int)(-0.5f)     // C++ 得 0（向零截断）
> std::floor(-0.5f) // 得 -1.0（向下取整）
> ```
> 对负数延迟，这两个**完全不同**。
> 而 C++ 的 `(int)` 是**向零截断**，很多人以为是向下取整。

## 八、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 高频发闷 | 线性插值 | 换全通/Hermite |
| 调制有台阶感 | 没做插值 | 用分数延迟 |
| 自激/爆炸 | 全通插值 frac→0 | 加保护，切换整数读取 |
| 直流增益不是 1 | 插值系数和不等于 1 | 检查系数公式 |
| 延迟量差一个采样 | 索引方向错 | 检查 `(int)` vs `floor` |
| 负延迟时崩 | `(int)` 截断方向 | 用 `std::floor` |
| 音高变换音质差 | 插值阶数不够 | 窗化 Sinc |

## 九、怎么验证

| 测试 | 方法 | 期望 |
|---|---|---|
| **整数延迟透明** | frac=0，喂脉冲 | 输出 = 精确移位 |
| **直流增益** | frac=0.5，喂直流 | 输出 = 输入（系数和为 1） |
| **频率响应** | 解析公式或扫频 | 与本文表格一致 |
| **无台阶** | 慢速调制，听 | 无阶梯感 |
| **稳定性** | frac 从 0 扫到 1 | 不发散 |

```python
import numpy as np
# 线性插值的频率响应（解析）
def mag_linear(f, frac, fs=48000):
    w = 2*np.pi*f/fs
    return abs((1-frac) + frac*np.exp(-1j*w))

# 验证 frac=0 时全频段透明
for f in [100, 1000, 10000, 20000]:
    assert abs(mag_linear(f, 0.0) - 1.0) < 1e-12
print("✅ frac=0 时线性插值完全透明")

# 验证 frac=0.5 时 20kHz 的衰减
d = 20*np.log10(mag_linear(20000, 0.5))
print(f"✅ frac=0.5 @ 20kHz: {d:.2f} dB (期望约 -12 dB)")
```
