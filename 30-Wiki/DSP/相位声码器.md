# 相位声码器

> [!important] 一句话
> **相位声码器 = 在 STFT 域改变时间/音高，靠"推进相位"而不是"插值相位"。**
> 它是**时间拉伸不变调**音质最好的经典方法。

## 和粒子合成的对比

| | 相位声码器 | 粒子合成 |
|---|---|---|
| 域 | **频域**（STFT） | 时域 |
| 音质 | ✅ **干净**（无颗粒感） | 🟠 有颗粒感 |
| "糊"的听感 | 金属感/相位感（phasiness） | 颗粒感 |
| CPU | 中-高（每帧 FFT） | 低 |
| 适合 | **人声、音乐的时间拉伸** | 纹理、pad、实验音色 |
| 延迟 | **较大**（一个窗长+） | 小 |

见 [[粒子合成 granular synthesis]]。

---

## 一、实测：STFT → ISTFT 恒等重建（本库验证）

**测试**（N = 1024，hop = 256，Hann 窗，440 Hz 正弦）：

| 步骤 | 结果 |
|---|---|
| STFT → 修改 → ISTFT | **最大误差 2.776e-16** ✅ |

> [!important] 这说明重建链是**精确**的
> 只要窗满足 COLA（见 [[重叠相加 overlap-add]]），
> 恒等变换能**完美重建**。
>
> **所以任何误差都来自"你对频谱做了什么"，不是重建本身。**

---

## 二、核心：相位要"推进"，不能"插值"

> [!danger] 这是相位声码器最容易写错的地方

**错误做法**（直觉上很自然）：

```python
# ❌ 直接线性插值相位
phase = (1-frac)*np.angle(S[i0]) + frac*np.angle(S[i0+1])
```

**为什么错**：相位是**缠绕**的（在 $[-\pi, \pi]$）。
`-3.1 rad` 和 `+3.1 rad` 实际上**很近**（差 0.08 rad），
但插值会以为它们**相距 6.2 rad**。

**正确做法**：**累积相位**。

```python
# ✅ 相位推进
dphi = 2*np.pi*hop*np.arange(n_bins)/N        # 预期相位增量
for i in range(1, out_frames):
    # 当前帧的**实际**相位差（去掉预期增量，缠绕到 [-pi,pi]）
    dp = np.angle(S[i0+1]) - np.angle(S[i0]) - dphi
    dp = np.mod(dp + np.pi, 2*np.pi) - np.pi
    # 累积相位 += 预期增量 + 偏差
    phase_acc += dphi + dp
    out[i] = mag * np.exp(1j*phase_acc)
```

> [!important] 两个关键点
> | # | 点 |
> |---|---|
> | 1 | **预期相位增量**：$\Delta\phi = 2\pi \cdot \text{hop} \cdot k / N$ |
> | 2 | **偏差要缠绕**到 $[-\pi, \pi]$（否则误差累积） |
>
> 这叫**相位展开（phase unwrapping）**——相位声码器的核心。

## 三、实测：时间拉伸

**测试**（440 Hz 正弦，1 秒）：

| rate | 输出时长 |
|---|---|
| 1.0 | 1.00 s（近似恒等，误差 1.006e-04） |
| **2.0** | **0.51 s**（缩短一半） |

> [!note] rate 的定义
> 这里的 `rate` 是"读取速率"：
> - `rate = 2` → 读得快 → 输出**变短**
> - `rate = 0.5` → 读得慢 → 输出**变长**
>
> ⚠️ 不同文献对 rate/stretch 的定义相反，**看代码确认**。

> [!warning] rate = 1 时仍有 1e-04 的误差
> 这**不是 bug**——相位推进是**近似**（用相邻帧的相位差估计瞬时频率）。
> 对纯正弦，误差小；对复杂信号，误差更明显。
>
> 对比：**恒等 STFT→ISTFT 是 2.776e-16**（精确）。
> 差别就在于**有没有动相位**。

## 四、音高变换

> [!important] 两个方法

| 方法 | 做法 |
|---|---|
| **时间拉伸 + 重采样** | 先拉伸 2×，再按 0.5× 速度播放 → 音高 ×2 |
| **直接频移** | 把频谱整体平移（会有"相位声码器感"） |

**方法 1 是标准做法**：

```
目标：音高 ×2，时长不变
① 用相位声码器把时长拉伸 2×（音高不变）
② 用重采样按 2× 速度播放（时长回到原长，音高 ×2）
```

> [!tip] 为什么这样能得到干净的变调
> 相位声码器保证"拉伸时音高不变"，
> 重采样保证"播放速度与音高联动"。
> 两者组合 → 音高变了、时长没变。

见 [[采样率转换 resampling]]。

## 五、已知问题：phasiness（相位感）

> [!danger] 相位声码器的典型瑕疵
> **听感**：像"金属感"、"水下感"、"混响过多"。
>
> **原因**：
> - 相位推进是**近似**（每帧独立估计瞬时频率）
> - 相邻帧的相位关系被破坏
> - 瞬态被"抹开"（时间分辨率受窗长限制）
>
> **缓解手段**：
> | 手段 | 效果 |
> |---|---|
> | **相位锁定**（phase locking） | 让相邻频段的相位保持一致 |
> | **瞬态检测 + 特殊处理** | 保留打击乐的冲击 |
> | 更短的窗 | 改善瞬态，但频率分辨率下降 |
> | 多分辨率 | 低频用长窗、高频用短窗 |

> [!warning] 这些技术的实现**本页未给出**
> 相位锁定需要理解"相位一致性"的概念，
> 实现也因论文而异。⚠️ 需查专门文献。

## 六、AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **直接插值相位** | 缠绕处错误 → 严重失真 | 用相位推进 |
| 2 | **不缠绕相位偏差** | 误差累积 | `mod(dp+π, 2π)-π` |
| 3 | **忘了预期相位增量** | 音高错 | 检查 `dphi` |
| 4 | **窗口不满足 COLA** | 重建有起伏 | 见 [[重叠相加 overlap-add]] |
| 5 | **不加窗** | 频谱泄漏 | 加 Hann |
| 6 | **相位/幅度插值搞混** | 完全错 | 幅度插值、相位推进 |
| 7 | **rate 定义搞反** | 拉伸变缩短 | 看代码确认 |
| 8 | **忘了输出长度** | 尾部截断 | 计算正确长度 |
| 9 | **ISTFT 不归一化** | 音量不对 | 累积窗平方并相除 |
| 10 | **以为 rate=1 是精确恒等** | 期望值错 | 实测 1e-04 误差正常 |

> [!danger] 第 1 条是最经典的错误
> AI 会写"插值相位"——因为**幅度就是插值的**，
> 直觉上相位也该插值。
>
> **但相位是缠绕的，插值会产生巨大误差。**
>
> **判据**：代码里应该有 `phase_acc +=`（累积），而不是直接对 `angle()` 做插值。

> [!danger] 第 2 条同样常见
> 不缠绕的话，偏差会累积 → 相位越跑越远 → 输出变成噪声。

## 七、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 输出是噪声 | 直接插值相位 | 用相位推进 |
| 音高不对 | 预期增量算错 | 检查 `dphi` |
| 音量起伏 | 窗不满足 COLA | 用周期性 Hann |
| 音量不对 | ISTFT 没归一化 | 累积窗平方 |
| 尾部被截断 | 输出长度算错 | 加窗长余量 |
| 金属感 | 相位声码器固有 | 相位锁定（需专门实现） |
| 瞬态被抹掉 | 窗太长 | 用短窗或多分辨率 |
| CPU 高 | 每帧 FFT | 用 FFT 复用/优化 |

## 八、怎么验证

**三个必做测试**：

| # | 测试 | 判据 |
|---|---|---|
| 1 | **恒等重建** | STFT→ISTFT 误差 < 1e-12 ⭐ |
| 2 | **rate=1 近似恒等** | 误差 ~1e-04（相位推进的近似） |
| 3 | **时长正确** | rate=2 → 时长减半 |

```python
import numpy as np
SR = 48000.0
N, HOP = 1024, 256

def stft (x):
    w = np.hanning (N)
    nf = (len(x)-N)//HOP + 1
    return np.array ([x[i*HOP:i*HOP+N]*w for i in range(nf)]), w

def istft (S, length):
    w = np.hanning (N)
    out = np.zeros ((S.shape[0]-1)*HOP + N)
    wsum = np.zeros_like (out)
    for i in range (S.shape[0]):
        seg = np.fft.irfft (S[i], N)
        out[i*HOP:i*HOP+N] += seg*w
        wsum[i*HOP:i*HOP+N] += w*w
    nz = wsum > 1e-12
    out[nz] /= wsum[nz]
    return out[:length]

# ① 恒等重建（最关键的自检）
t = np.arange (int(SR))/SR
x = 0.5*np.sin (2*np.pi*440*t)
frames, w = stft (x)
S = np.fft.rfft (frames, axis=1)
y = istft (S, len(x))
n = min (len(y), len(x))
err = np.max (np.abs (y[N:n-N] - x[N:n-N]))
print (f"  恒等重建误差: {err:.3e}")
assert err < 1e-12, "STFT/ISTFT 重建有问题！"
print ("  ✅ 重建链精确")

# ② rate=1 的相位声码器应近似恒等（误差 ~1e-4 是正常的）
```

> [!important] 第 1 条是最有价值的自检
> 它把"重建链"和"相位处理"**分开验证**：
> - 重建链坏了 → 误差大（1e-12 断言失败）
> - 重建链好但相位处理错 → 第 2 条能看出来
>
> **先证明重建是精确的，再调相位算法。**
