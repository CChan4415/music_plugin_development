# 反馈延迟网络 FDN

> [!important] 一句话
> **FDN = 多条延迟线 + 一个混合矩阵 + 反馈。**
> 矩阵让各条延迟线"交换"信号，从而用很少的延迟线产生极密集的回声。

## 为什么它比 Schroeder 好

| | Schroeder / Freeverb | FDN |
|---|---|---|
| 结构 | 多个梳状滤波器**并联**（互不干扰） | 多条延迟线**互相混合** |
| 回声密度增长 | 慢（每个梳状只重复自己的回声） | 快（指数级） |
| 金属味 | 明显（固定延迟比产生驻波） | 轻（混合打散了周期性） |
| 参数化 | 难（延迟时间要精心调） | 易（矩阵 + 每线增益） |
| 多声道 | 要额外处理 | **矩阵天然处理声道间关系** |
| 频变衰减 | 每个梳状加滤波器 | 每条线加滤波器 |

> [!note] 你的线性代数在这里直接变成音质
> FDN 的核心就是一个**矩阵**。
> 你在 [[线性代数]] 里学的"正交矩阵""特征值"，在这里决定了
> **混响会不会发散、尾巴平不平滑**。
>
> 这是本知识库里**数学最直接变现**的一页。

---

## 一、基本结构

```
                    ┌──────────────────────────────┐
                    │                              │
  输入 ──┬──────────┼──→ [延迟线 1] ──┐            │
         │          │   [延迟线 2] ──┼→ [矩阵 A] ──┤
         │          │   [延迟线 3] ──┤    ↑         │
         │          │   [延迟线 4] ──┘    │         │
         │          └────────────────────┼─────────┘
         │                               │
         └───────────────────────────────┴──→ 输出
```

**信号流**：
1. 输入加到各延迟线的输入端
2. 延迟线的输出经过**混合矩阵** `A`
3. 矩阵输出**反馈回**延迟线输入
4. 输出从延迟线（或矩阵）取出

> [!important] 为什么矩阵能增加密度
> 没有矩阵时，延迟线 1 的回声**永远只在延迟线 1** 里循环。
> 有了矩阵，延迟线 1 的回声会被**分散到所有延迟线**，
> 下一轮每一条又各自分散一次 → 回声数量**指数增长**。
>
> 这就是 Luff 那篇文章说的"每应用一次扩散步骤，回声数量就翻倍"。

## 二、矩阵必须正交（**这是最关键的一点**）

### 为什么

反馈环路里，如果矩阵**放大**能量，信号会**发散**（爆炸）。
如果矩阵**衰减**能量，尾巴会不正常地短。

**正交矩阵**（$A^T A = I$）满足：

$$\|A\mathbf{x}\|^2 = \|\mathbf{x}\|^2 \quad \text{对所有 } \mathbf{x}$$

**能量完全守恒** → 衰减**只由你显式设置的增益决定**，矩阵本身不引入任何衰减或增益。

### 实测验证

**Hadamard 矩阵**（$n$ 为 2 的幂时可用递归构造）：

$$H_1 = [1], \qquad H_{2n} = \begin{bmatrix} H_n & H_n \\ H_n & -H_n \end{bmatrix}$$

实测 $H H^T = nI$（误差 0）：

| n | $\|H H^T - nI\|$ | 归一化后 $\|H_n H_n^T - I\|$ |
|---|---|---|
| 2 | 0.0 | 2.2e-16 ✅ |
| 4 | 0.0 | 0.0 ✅ |
| 8 | 0.0 | 1.1e-16 ✅ |
| 16 | 0.0 | 0.0 ✅ |

**能量守恒实测**（$H/\sqrt{n}$ 作用在随机向量上）：

| 输入能量 | 输出能量 | 相对误差 |
|---|---|---|
| 8.240821 | 8.240821 | 0.00e+00 |
| 4.338249 | 4.338249 | 0.00e+00 |
| 3.845926 | 3.845926 | 1.15e-16 |
| 5.832148 | 5.832148 | 3.05e-16 |

> [!danger] 反例：非正交矩阵会发散
> 随手写一个矩阵 $M = \begin{bmatrix}1 & 1\\ 1 & 0.5\end{bmatrix}$：
> - 输入能量 2.0000 → 输出能量 **6.2500**（放大 3.12 倍）
> - 反复反馈 → **指数发散** ❌
>
> **所以：绝不要"随手写"一个混合矩阵。**

### 怎么构造正交矩阵

| 方法 | 说明 | 成本 |
|---|---|---|
| **Hadamard** | 递归构造，元素只有 ±1 | **最快**（乘 1 或 -1 就是加减） |
| Householder | $I - 2vv^T/\|v\|^2$ | 中 |
| Givens 旋转 | 两两旋转 | 可做"部分混合" |
| 随机正交（QR 分解） | 任意阶数 | 慢，且不适合实时 |

> [!tip] Hadamard 的巨大优势
> 因为元素只有 **±1**，矩阵乘法**不需要任何乘法**——
> 只是**加减法**。
>
> 对 $n=8$：朴素矩阵乘法要 64 次乘法；
> Hadamard 用快速算法只要 $n\log_2 n = 24$ 次**加减**。
> **这对实时音频是巨大的差别。**

## 三、衰减与 RT60

反馈环路里每条延迟线都有自己的增益 $g_i$。

**均匀衰减**（所有 $g_i$ 相同）：

$$g = 10^{-3 \cdot \bar{d} / \mathrm{RT60}}$$

其中 $\bar{d}$ 是延迟时间的平均值（秒）。

> [!warning] 每条延迟线的 RT60 不同
> 因为每条线延迟时间不同，**同一个 $g$ 会给出不同的衰减时间**。
> 要让所有线**同时**衰减到 -60dB，需要**每条线单独算 $g_i$**：
>
> $$g_i = 10^{-3 \cdot d_i / \mathrm{RT60}}$$
>
> **这是 FDN 实现里最容易忽略的细节。** 忽略了会让某些频率的尾巴比别人长。

---

## 四、频变衰减（让尾巴自然）

真实空间里**高频被吸收得更快**。做法：在每条延迟线的反馈路径里加**低通/搁架滤波器**。

```
[延迟线 i] → [低通滤波器] → [× g_i] → [矩阵] → 回到延迟线
```

> [!tip] 为什么这很重要
> 没有频变衰减 → 尾巴一直很亮 → 听起来"金属""假"。
> 这是 [[混响的原理]] 里"阻尼"那一节的数学实现。

**用搁架滤波器可以做到**：低频衰减慢（长 RT60）、高频衰减快（短 RT60）。
这比单纯低通更接近真实空间。

## 五、延迟时间的选取

> [!important] 这是 FDN 调参的核心
>
> | 规则 | 原因 |
> |---|---|
> | **避免整数倍关系** | 会产生驻波 → 金属味 |
> | **避免过短** | 回声太稀疏，听得出单个回声 |
> | **避免过长** | 回声密度增长慢，起音不自然 |
> | **左右/各线不同** | 去相关 → 宽度感 |
>
> **Luff 的实用技巧**（原文）：
> > "把范围**等分**，每个声道用一个子区间随机取值——
> > 它们会近似均匀分布，同时仍然是随机的。"
>
> 这比纯随机更可控，比等间距更不"金属"。

**典型范围**：20–100ms（用于晚期混响）。

## 六、Luff 的改进：把扩散器移到环路外

> [!important] 这是那篇文章最有价值的洞察
> > "设计一个能产生扩散、持久、无强共振的反馈环路**很难——但我们不必这么做！**"

**传统做法**：让 FDN 环路自己产生密集回声 → 要精心调延迟时间。

**Luff 的做法**：**分离关注点**

```
输入 → [扩散器 diffuser] → [FDN 环路] → 输出
        负责"变糊"           负责"持久"
```

**扩散器**用**无反馈**的多声道构件串联：

| 构件 | 作用 |
|---|---|
| 多声道延迟 | 让同步的回声**去同步** |
| **Hadamard 矩阵** | 把某声道的特征分散到所有声道 |
| 声道置换 / 极性反转 | 技术上也属于全通 |

**"扩散步骤"** = 延迟 → 置换 → Hadamard。

> [!tip] 为什么这样更好
> - 扩散器**没有反馈** → 不会发散，不需要调稳定性
> - FDN 环路**不需要**精心调延迟 → 作者说"可以把随机数扔给延迟时间"
> - 两者可以**独立调**（要更糊？加扩散步骤。要更长？加反馈增益）

**Luff 给出的示例参数**：8 声道、4 个扩散步骤（20/40/80/160ms）、反馈 85%、反馈延迟 100–200ms。

## 七、多声道与降混

FDN 天然适合多声道：矩阵直接处理声道间关系。

> [!warning] 降混时不再是全通
> 把多声道降到立体声，系统**不再是全通**。
> 但只要相位偏移**没有规则到产生可识别的梳状音色**就没问题。
>
> 因为 Hadamard 已经混合过了，**直接取前 1–2 个输出声道**就能得到好结果。

## 八、调制

> [!important] 真实空间不是静止的
> 空气流动、温度变化、人的移动 → 反射路径微小变化。
> 而且**固定延迟线会产生驻波**（金属味）。

**做法**：用 LFO 轻微调制延迟线长度（±1–3ms，0.1–1Hz）。

**需要分数延迟插值** → 见 [[延迟线 delay line]] 和 [[插值]]。

> [!warning] 插值的代价
> 线性插值会衰减高频（frac=0.5 时 20kHz 衰减 -11.74 dB）。
> 对混响的**调制**来说这个衰减会被反复施加 → 尾巴的高频可能被过度削减。
> **考虑用全通或高阶插值。**

## 九、AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **随手写一个混合矩阵** | 能量不守恒 → 发散 | 检查是否正交（`A @ A.T ≈ I`） |
| 2 | **用同一个 $g$ 给所有延迟线** | 各线 RT60 不同 → 尾巴不齐 | 检查 $g_i$ 是否按 $d_i$ 单独算 |
| 3 | **延迟时间是整数倍** | 驻波 → 金属味 | 检查延迟比例 |
| 4 | **没有频变衰减** | 尾巴太亮、不自然 | 检查反馈路径有没有滤波器 |
| 5 | **矩阵每样本重算** | CPU 爆炸（矩阵是常量！） | 矩阵应该**只算一次** |
| 6 | **朴素矩阵乘法** | 浪费 CPU | 用 Hadamard 快速算法（只要加减） |
| 7 | **反馈路径没有 denormal 处理** | 安静时 CPU 飙升 | 见 [[denormal 数处理]] |
| 8 | **调制用线性插值** | 高频被反复衰减 | 换全通/高阶 |

> [!tip] 第 5 条特别常见
> 混合矩阵是**常量**（不随参数变），应该在构造时算好。
> AI 有时会把它写在 `processBlock` 里循环计算——完全没必要。

## 十、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 发散/爆炸 | 矩阵非正交，或反馈 ≥ 1 | 用正交矩阵 + 钳制增益 |
| 金属味/铃声 | 延迟时间成整数比 | 用互质或均匀分布 |
| 尾巴太亮 | 无频变衰减 | 反馈路径加搁架滤波器 |
| 尾巴不平滑 | 回声密度不够 | 加扩散步骤，或增加延迟线数 |
| 各频率衰减不一致 | 所有线用同一个 $g$ | 每条线按自己的 $d_i$ 算 $g_i$ |
| 安静时 CPU 飙升 | denormal | 见 [[denormal 数处理]] |
| CPU 占用高 | 朴素矩阵乘法 | 用 Hadamard 快速算法 |
| 立体声窄 | 各线延迟太接近 | 拉开延迟差异，或用不同矩阵 |

## 十一、怎么验证

| 测试 | 方法 | 期望 |
|---|---|---|
| **矩阵正交** | `max(abs(A @ A.T - I))` | < 1e-12 |
| **能量守恒** | 随机向量过矩阵，比能量 | 完全相等 |
| **稳定性** | 喂脉冲跑 10 秒 | 衰减到 0，不发散 |
| **RT60 准确** | 测衰减曲线 | 接近设定（±20%） |
| **无金属味** | 频谱看有无强共振峰 | 应平滑 |
| **频变衰减** | 分频段测 RT60 | 高频衰减更快 |
| **无 denormal** | 看安静时 CPU | 不升高 |

```python
import numpy as np
def hadamard(n):
    H = np.array([[1.0]])
    while H.shape[0] < n:
        H = np.block([[H, H], [H, -H]])
    return H

# 1. 正交性检查
A = hadamard(8) / np.sqrt(8)
assert np.max(np.abs(A @ A.T - np.eye(8))) < 1e-12, "矩阵不正交！"

# 2. 能量守恒检查
x = np.random.randn(8)
assert abs(np.sum((A@x)**2) - np.sum(x**2)) < 1e-12, "能量不守恒！"
print("✅ 矩阵验证通过")
```
