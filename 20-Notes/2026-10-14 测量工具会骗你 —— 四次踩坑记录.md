# 测量工具会骗你 —— 四次踩坑记录

> [!important] 这是这个知识库目前最重要的一页
> 在写前三个实验的过程中，我**四次**得出"代码有 bug"的结论，
> 而**四次都是我的测量方法错了**。
>
> 这不是巧合，是 DSP 工作的常态。
> **你的 DSP 代码可能是对的，但你的验证方法在骗你。**

## 四次记录

| # | 我在测什么 | 现象 | 我以为是 | 实际是 |
|---|---|---|---|---|
| 1 | 正弦波频率 | 479.8Hz（期望 440） | 生成代码写错了 | **过零计数**被量化产生的 0 值样本骗了 |
| 2 | Biquad 的 Q 与 ringing | Q=30 的 ringing 比 Q=5 **短** | 滤波器实现有 bug | 用了**绝对阈值**；高 Q 峰值更大，更早低于阈值 |
| 3 | 同上，修正后 | Q=30 只有 0.25ms | 还是 bug | 找"峰值后**第一次**低于阈值"，振荡信号立刻穿过去 |
| 4 | 混响的阻尼效果 | 阻尼越大，高频衰减**越慢** | 阻尼方向写反了 | 信号衰减到**噪声底**后，线性拟合拟合的是噪声的斜率 |
| 5 | Karplus-Strong 音高 | 110Hz 目标测出 1099Hz | 合成算法错了 | `damping=0.5` 让音在 45ms 内消失，**我在测一段静音** |

> [!note] 其实是五次
> 而且第 2、3 次是同一个问题的两次失败尝试。
> 第 5 次最典型：**测量对象已经空了，我还在测。**

## 归纳：五类测量陷阱

### 陷阱 1：用绝对阈值测"相对"的东西

```python
# ❌ 错: 绝对阈值
below = np.where(np.abs(h) < 1e-3)[0]
t60 = below[0] / SR
```

**问题**：高 Q 滤波器的脉冲响应**峰值更大**（约等于 Q），
所以它更快"低于 1e-3"——但这是因为它起点高，不是因为衰减快。

**正确**：用**相对峰值**的阈值。

### 陷阱 2：找"第一次"穿越而不是"最后一次"

```python
# ❌ 错: 振荡信号在峰值后立刻穿过阈值
below = np.where(env[ipk:] < pk*1e-3)[0]
t60 = below[0] / SR

# ✅ 对: 找最后一次高于阈值的位置
above = np.where(env > pk*1e-3)[0]
t60 = above[-1] / SR
```

> [!tip] 这个 bug 极其隐蔽
> 因为**它给出的数字看起来完全合理**（0.25ms 是个正常的毫秒数）。
> 如果我不去对比 Q=5 和 Q=30 的**相对关系**，就永远发现不了。

### 陷阱 3：在噪声底上做拟合

```python
# ❌ 错: 信号早就衰减到 1e-30 了，还在拟合
db = 10*np.log10(energy)
slope = np.polyfit(t, db, 1)[0]
```

**问题**：信号衰减到浮点噪声底后，dB 曲线变成一条**水平线或乱线**，
把这段数据一起拟合，会污染整个斜率。

**正确**：只拟合**有效衰减区间**（从峰值到噪声底之前）。

### 陷阱 4：测量对象已经不存在了

```python
y = karplus_strong(N, damping=0.5)   # 音在 45ms 内消失
pitch = fft_peak(y)                  # 在测剩下 1.95 秒的静音
```

**正确**：**先看包络**，确认信号在你测量的时间段内还活着。

```python
# 养成习惯: 先画/看包络，再测别的
env = [np.sqrt(np.mean(y[i:i+w]**2)) for i in range(0, len(y)-w, w)]
```

### 陷阱 5：测量方法本身不适合这个任务

**过零计数**测频率：被量化产生的 0 值样本欺骗。
**FFT 峰值**测低频音高：分辨率 = sr/N，测 110Hz 误差可达 1%，而且
FFT 找的是**最强频点**不是**基频**（真实乐器常是泛音更强）。

**正确**：
- 测频率 → **FFT**（中高频）或**自相关**（低频）
- 测频响 → **脉冲响应 + FFT**（不要用白噪声，有随机起伏）
- 测衰减 → **相对阈值 + 最后一次穿越**

## 防御手段（这是本页真正的价值）

> [!important] 三条可操作的规则
>
> **1. 结果"反常"时，先怀疑测量，再怀疑代码。**
> 尤其是当你刚写了一个自己都不太确定的验证脚本时。
> 新手最常见的错误是：**改正确的代码去迎合错误的测试**。
>
> **2. 用已知正确的简单例子校准你的测量方法。**
> 测滤波器前，先测一个**纯正弦**——如果你测不出 440Hz，是你的方法错了。
> 测 RT60 前，先测一个**指数衰减** `exp(-t/tau)`——理论值已知。
>
> **3. 交叉验证：用两种独立的方法测同一个东西。**
> 例如：FFT 主峰 vs 自相关。两者一致 → 可信；不一致 → 至少一个错了。

### 已经固化进工具库的修正

`50-Playground/tools/audio_io.py` 现在提供：

| 函数 | 解决哪个陷阱 |
|---|---|
| `dominant_freq()` | 用 FFT 测中高频（不要用过零计数） |
| `dominant_freq_autocorr()` | 用自相关测低频基频（FFT 在低频不准） |
| `decay_time()` | 用**相对阈值 + 最后一次穿越**测衰减 |
| `check_response()` | 和**解析解**对比，而不是"听起来对" |
| `null_test()` | 用相减把"听起来差不多"变成"数值一致" |
