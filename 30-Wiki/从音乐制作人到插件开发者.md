# 从音乐制作人到插件开发者

> [!important] 这一页是关于"你"的
> 它不是通用知识，是你个人的**知识盘点与缺口地图**。
> 它应该随着你的进展不断更新——**半年后回看，它会告诉你走了多远**。

## 你已有的资产（别低估）

| 资产 | 为什么稀缺 | 怎么转化成代码 |
|---|---|---|
| **听觉判断力** | 能听出 0.5 dB 的差别，能判断"这个压缩器不对" | 这是 AI 和纯 CS 开发者**没有的验证信号**。你能测出他们测不出的问题 |
| **合成器原理直觉** | 加法/减法/粒子/模块都玩过 | 直接对应 DSP 拓扑：加法=正弦叠加，减法=滤波，粒子=granular，模块=信号流图 |
| **效果器参数语义** | 知道 attack 快了会怎样、Q 值高了会怎样 | 决定参数的**范围、默认值、曲线**——这是插件好不好用的关键 |
| **工作流知识** | 知道音乐人什么时候会放弃一个插件 | 决定 UX 设计，见 [[MOC - UI & UX]] |
| **计算机专业训练** | 能读代码、能学新语言 | 工程实现的地基 |
| **AI/Agent 使用能力** | 现在的杠杆点 | 见 [[Agent 驱动的插件开发工作流]] |

> [!tip] 你的真实优势
> 不是"会写 DSP"——那可以学。
> 是**你能判断什么声音是对的**，而且能把这个判断翻译成参数和算法选择。
> 绝大多数插件开发者缺这个。**别把自己当成"转行的初学者"，你是"带着验证能力的开发者"。**

## 你的缺口（诚实版）

| 缺口 | 严重程度 | 补法 |
|---|---|---|
| 现代 C++（模板、RAII、move、并发） | 🔴 高 | 边做边补，不要先读完整本书 |
| z 变换与差分方程 | 🔴 高 | 只需要理解到"能看懂 H(z) 和极零点" |
| 滤波器设计（系数从哪来） | 🟠 中 | 记公式 + 用现成设计工具，不必手推 |
| 实时编程约束 | 🔴 高 | [[实时音频线程契约]] 一页就够入门 |
| 构建系统（CMake） | 🟠 中 | 抄模板 + 理解基本概念 |
| 平台细节（签名、公证、安装包） | 🟡 低 | 需要时查，[[MOC - Craft & Release]] |
| 数值方法（如果你要做物理建模） | 🟢 暂缓 | 以后再说 |

> [!warning] 最危险的缺口不是上面任何一个
> 是**"我先把理论学完再动手"的倾向**。
> DSP 教材加起来几千页，读完它们不会让你做出插件，只会让你更害怕开始。
> **正确节奏：做一个最小的能出声的东西 → 遇到不懂的 → 查 → 写进知识库 → 继续做。**

## 翻译层：你的经验如何变成工程决策

这是本知识库**最独特的价值**。举例：

| 你的经验 | 工程含义 |
|---|---|
| "这个混响尾巴太干净了，不像真的" | 缺少频变衰减 + 缺少调制去相关。见 [[Schroeder 混响]]、[[反馈延迟网络 FDN]] |
| "压缩器的 release 应该跟音乐走" | 需要 program-dependent release，而非固定时间常数 |
| "这个 EQ 扫频时有颗粒感" | 系数直接重算导致的不连续 → 需要 [[参数平滑 parameter smoothing]] 或滤波器状态插值 |
| "失真在高频有塑料味" | 混叠 → 需要 [[过采样 oversampling]] |
| "这个合成器的滤波扫上去有阶梯感" | 系数更新率太低（每 block 一次）→ 需要每 sample 更新或插值 |
| "立体声变宽了但 mono 兼容性差了" | 相位问题 → 见 [[立体声感知]] |

> [!tip] 请持续扩充这张表
> 每次你遇到"我听得出来但说不清是什么"的情况，就来加一行。
> **这张表就是你的技术路线图**——每一行都指向一个要学的主题。
