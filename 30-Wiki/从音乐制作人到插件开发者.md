# 从音乐制作人到插件开发者

> [!important] 这一页是关于"你"的
> 它基于你 2026-10-14 的回答：
> **C++ 基本为 0 · DSP 数学基本忘了（线性代数还行）· 目标 = VST3/AU 插件 · AI 当开发助手**
>
> 这是你的**知识盘点与缺口地图**。半年后回看，它会告诉你走了多远。

## 你的真实处境（不美化）

| 维度 | 状态 | 说明 |
|---|---|---|
| 音乐制作 | ⭐⭐⭐⭐⭐ | 十年经验，用过各种合成器与效果器 |
| 听觉判断力 | ⭐⭐⭐⭐⭐ | 能听出差别，能判断"对不对" |
| 编程（通用） | ⭐⭐⭐ | 计算机专业，会 Python/Java 之类 |
| **C++** | ⭐ | **基本为 0** |
| **DSP 数学** | ⭐ | **复数/z变换/傅里叶都没把握** |
| 线性代数 | ⭐⭐⭐ | **没问题**（这个比你想的更重要） |
| AI/Agent 使用 | ⭐⭐⭐ | 正在用 |

> [!warning] 最诚实的判断
> **你的瓶颈不是"不会做插件"，是"同时从零学两样东西"。**
> C++ 和 DSP 数学，任何一样单独学都不算难。同时学，难度是相乘的。
>
> 所以这份知识库的第一原则是：**不要同时学。**
> 用 Python 先把 DSP 搞懂（你会 Python），再学 C++ 去实现你已经懂的东西。

## 你已有的资产（别低估）

| 资产 | 为什么稀缺 | 怎么转化成代码 |
|---|---|---|
| **听觉判断力** | 能听出 0.5dB 的差别，能判断"这个压缩器不对" | 这是 AI 和纯 CS 开发者**没有的验证信号**。你能测出他们测不出的问题 |
| **合成器原理直觉** | 加法/减法/粒子/模块都玩过 | **直接对应 DSP 拓扑**，见 [[合成原理与 DSP 拓扑]] |
| **效果器参数语义** | 知道 attack 快了会怎样、Q 值高了会怎样 | 决定参数的**范围、默认值、曲线**——插件好不好用的关键 |
| **混音与空间感** | 知道什么混响"像真的" | 见 [[延迟与回声的原理]]、[[动态处理的原理]] |
| **工作流知识** | 知道音乐人什么时候会放弃一个插件 | 决定 UX 设计，见 [[MOC - UI & UX]] |
| **线性代数** | 没忘 | 混响（FDN）、多声道、空间音频、**神经网络音频**都吃这个 |
| **CS 训练** | 会编程、能学新东西 | 学 C++ 时你会比纯音乐人快得多 |

> [!tip] 你的真实优势
> 不是"会写 DSP"——那可以学，而且你学得会。
> 是**你能判断什么声音是对的**，而且能把判断翻译成参数和算法选择。
> 绝大多数插件开发者缺这个。**别把自己当成"零基础初学者"，你是"带着验证能力的转行者"。**

## 你的缺口（按严重程度）

| 缺口 | 严重程度 | 什么时候补 | 补法 |
|---|---|---|---|
| **DSP 直觉**（不知道算法对不对） | 🔴 最紧急 | **现在** | Python 练习，见 [[Python 优先的 DSP 学习路径]] |
| **C++ 语法与内存模型** | 🔴 高 | 1–3 个月后 | 见 [[C++ 零基础到音频 DSP 路线]] |
| **DSP 数学**（复数、z 变换） | 🟠 中 | **用到再补**，别提前学 | 在 Python 里把公式画出来 |
| **实时编程约束** | 🟠 中 | 阶段 4 | [[实时音频线程契约]] 一页就够 |
| **构建系统（CMake）** | 🟡 低 | 阶段 4 | 抄模板 |
| **平台细节**（签名、公证） | 🟡 低 | 要发布时 | [[MOC - Craft & Release]] |
| **音频环境**（你机器上没 DAW） | 🟠 中 | **本周** | 装 REAPER 或用 GarageBand |

> [!danger] 最危险的缺口不是上面任何一个
> 是**"我先把 C++ 学完再做 DSP"**，或者**"我先把数学补完再动手"**。
>
> 这两条路都会让你在三个月后放弃，而且**什么作品都没有**。
> 正确节奏：**今天就用 Python 生成一个正弦波并播放它。**
> 剩下的，遇到什么学什么。

## 翻译层：你的经验如何变成工程决策

这是本知识库**最独特的价值**。每当你遇到"我听得出来但说不清是什么"的情况，就往这里加一行。

| 你的经验 | 工程含义 | 详见 |
|---|---|---|
| "这个混响尾巴太干净了，不像真的" | 缺少频变衰减 + 缺少调制去相关 | [[延迟与回声的原理]] |
| "压缩器的 release 应该跟音乐走" | 需要 program-dependent release，而非固定时间常数 | [[动态处理的原理]] |
| "这个 EQ 扫频时有颗粒感" | 系数直接重算导致不连续 → 需要参数平滑 | [[参数平滑 parameter smoothing]] |
| "失真在高频有塑料味" | 混叠 → 需要过采样 | [[混叠 aliasing]] |
| "这个合成器的滤波扫上去有阶梯感" | 系数更新率太低 | [[参数平滑 parameter smoothing]] |
| "立体声变宽了但 mono 兼容性差了" | 相位问题 | [[立体声感知]] |
| "这个 FM 音色很脏" | 相位调制产生的混叠 | [[合成原理与 DSP 拓扑]] |
| "磁带 echo 听起来温暖" | 抖晃 + 频响损失 + 反馈中逐次变暗 + 饱和 | [[延迟与回声的原理]] |
| "压缩器有粘性（glue）" | 慢 attack + 低 ratio + 程序相关 release | [[动态处理的原理]] |

> [!tip] 请持续扩充这张表
> **每一行都指向一个要学的主题，所以这张表就是你的技术路线图。**
> 而且它是**从你的耳朵出发的**，不是从教材目录出发的——
> 这意味着你学的每一个东西都有明确的用途。
