# 音频测量基础

> [!important] 一句话
> **你的耳朵能发现"不对"，但只有测量能证明"对"。**
> 这一页是本库所有验证方法的集合——**因为踩过七次"测量方法错"的坑**。

## 为什么这一页比听起来重要

本库的 [[2026-10-14 测量工具会骗你 —— 八次踩坑记录]] 记录了**七次**"代码没错、是测量错了"。
其中最危险的一次：**加窗后没补偿相干增益，所有幅度测量差 6.02 dB**——
而 -6 dB 是个"看起来完全合理"的数字，藏了好几天。

> [!danger] 核心教训
> **测量工具会骗你，而且骗得很像真的。**
> 你的代码可能是对的，但你的验证方法在骗你。
>
> **防御手段**：
> 1. 结果"反常"时，**先怀疑测量，再怀疑代码**
> 2. 用**已知正确的简单例子**校准测量方法
> 3. **交叉验证**：两种独立方法测同一个东西

---

## 一、电平指标：别搞混

| 指标 | 定义 | 用途 | 注意 |
|---|---|---|---|
| **Peak** | 采样点绝对值最大 | 防削波 | 看不到 inter-sample peak |
| **True Peak** | 重建后模拟波形的峰值 | 交付标准 | 需过采样（4x 以上） |
| **RMS** | $\sqrt{\frac{1}{N}\sum x^2}$ | 能量、响度相关 | 与听感相关性比 peak 好 |
| **Crest Factor** | Peak − RMS（dB） | 动态特征 | 鼓 ≈ 12–20dB，正弦 ≈ 3dB |
| **dBFS** | $20\log_{10}(\text{幅度})$ | 数字域电平 | 0 dBFS = 满幅 |
| **LUFS** | 感知响度（ITU-R BS.1770） | 发行响度标准 | 有 K-weighting 滤波 |

> [!warning] dBFS 与 dBu / dBSPL 不是一回事
> | 单位 | 参考点 | 用在哪 |
> |---|---|---|
> | **dBFS** | 数字满幅 | 插件内部、DAW |
> | **dBu / dBV** | 电压（0.775V / 1V） | 模拟设备 |
> | **dBSPL** | 声压（20 μPa） | 声学测量 |
>
> **插件内部只用 dBFS。** 看到"这个插件输出 +6dBu"是概念混乱。

> [!tip] dB 的两种公式（本库踩过的坑）
> - $20\log_{10}$ 用于**幅度**（电压、采样值）
> - $10\log_{10}$ 用于**功率**（能量）
>
> **混用是最常见的错误之一。** 幅度减半 = **-6.02 dB**（不是 -3 dB）。

## 二、频率响应测量

### 方法对比

| 方法 | 精度 | 说明 |
|---|---|---|
| **脉冲响应 + FFT** | ⭐ **最精确** | 确定性，完全描述 LTI 系统 |
| 对数扫频 + 反卷积 | 高 | 抗噪好，适合实测硬件 |
| 白噪声 + FFT | ❌ 差 | **有随机起伏**，单次实现方差大 |
| 多频正弦逐个测 | 高 | 慢但直观 |

> [!important] 为什么推荐脉冲响应
> **脉冲响应是确定性的**——它**完全描述**一个线性时不变系统。
> 白噪声 FFT 有随机方差，你会以为是自己写错了。
>
> 本库的 `exp-002` 用脉冲响应把 Biquad 验证到 **0.0021 dB** 的精度。

```python
import numpy as np
def freq_response(h, sr=48000, nfft=65536):
    """从脉冲响应精确计算频率响应。返回 (频率, dB)"""
    H = np.fft.rfft(np.asarray(h, np.float64), nfft)
    f = np.fft.rfftfreq(nfft, 1.0/sr)
    return f, 20*np.log10(np.abs(H) + 1e-12)

def check_response(h, theory_fn, sr=48000, tol_db=0.1):
    """和**解析解**逐点对比 —— 验证 DSP 正确性的标准做法。

    比"听起来对"强：0.001 dB 的偏差骗不过。
    而且可自动化 —— 以后改代码不会悄悄改坏。
    """
    f, mag = freq_response(h, sr)
    worst = 0.0
    for hz in [100, 250, 500, 1000, 2000, 4000, 8000, 16000]:
        if hz >= sr/2: continue
        measured = mag[np.argmin(np.abs(f - hz))]
        theory = theory_fn(hz)
        worst = max(worst, abs(measured - theory))
    return worst <= tol_db, worst
```

## 三、失真与噪声指标

| 指标 | 定义 | 说明 |
|---|---|---|
| **THD** | 总谐波失真 | 谐波能量 / 基频能量 |
| **THD+N** | 谐波 + 噪声 | 更全面（包含噪声） |
| **SNR** | 信号 / 噪声 | 噪声本底 |
| **SFDR** | 无杂散动态范围 | 最大杂散 / 基频 |

> [!warning] THD 的陷阱
> - **必须指定频率和电平**："THD 0.01%" 没说是多少 Hz、多少 dBFS 时毫无意义
> - **必须加窗**，否则泄漏会污染谐波测量
> - **必须补偿相干增益**（见下）
> - **带宽要说明**：测到 20kHz 还是 100kHz，结果差很多

## 四、⚠️ 两个必踩的测量陷阱

### 陷阱 1：加窗后不补偿相干增益（差 6 dB）

**这是本库工具库里的真实 bug，藏了好几天。**

```python
# ❌ 错：除以样本数
X = np.abs(np.fft.rfft(x * np.hanning(N))) * 2.0 / N

# ✅ 对：除以窗函数之和
w = np.hanning(N)
X = np.abs(np.fft.rfft(x * w)) * 2.0 / np.sum(w)
```

**实测**（0.5 幅度正弦 @440Hz）：

| 窗 | 归一化 | 测得幅度 | 结果 |
|---|---|---|---|
| 无窗 | `*2/N` | 0.5000 | ✅ |
| **Hann** | `*2/N` | **0.2500** | ❌ **差 6.02 dB** |
| Hann | `*2/sum(w)` | 0.5000 | ✅ |

> [!danger] 为什么特别危险
> **Hann 窗的相干增益恰好是 0.5**，所以误差正好是 **-6.02 dB**——
> 一个"看起来完全合理"的数字。
>
> 如果它差 3.7 dB 或 11.2 dB，早就起疑了。
> **它影响所有基于频谱的幅度测量。**

### 陷阱 2：null test 的取整差异（停在 -90 dB）

```python
# Python 的 astype 是**截断**
py = (x * 32767).astype(np.int16)      # 0.5 → 16383

# C 的 lround 是**四舍五入**
c  = lround(x * 32767)                 # 0.5 → 16384
```

| 输入 | Python（截断） | C（四舍五入） | 差 |
|---|---|---|---|
| 0.5 | 16383 | 16384 | -1 LSB |
| 0.25 | 8191 | 8192 | -1 LSB |

> [!important] 最多差 1 LSB ≈ -90 dB，听感上完全无关
> 但它会让 null test 结果停在 **-90 dB 左右**，而不是你以为的 -inf。
>
> **两种做法**：
> 1. **比浮点**（推荐）——两边在内存里用 `float` 比，不经过 WAV 编解码
> 2. **统一取整**——必须比 WAV 时，两边用同一种方式
>
> ⚠️ 否则你会花几小时找"为什么不是 -inf"——**而代码其实完全正确**。

## 五、Null Test：音频开发的核心验证手段

**原理**：两个信号相减，差异应该接近 0。

```python
def null_test(a, b, label="null test"):
    a, b = np.asarray(a, np.float64), np.asarray(b, np.float64)
    n = min(len(a), len(b))
    d = a[:n] - b[:n]
    peak = 20*np.log10(np.max(np.abs(d)) + 1e-12)
    rel = peak - 20*np.log10(np.max(np.abs(a[:n])) + 1e-12)
    verdict = "✅ 等价" if rel < -100 else ("🟠 接近" if rel < -60 else "❌ 有差异")
    print(f"{label}: 最大差异 {peak:.1f} dB (相对 {rel:.1f} dB)  {verdict}")
    return rel
```

**典型用途**：

| 场景 | 期望结果 |
|---|---|
| C++ 实现 vs Python 参考实现 | < -100 dB（浮点误差级） |
| 优化前 vs 优化后 | < -100 dB（**证明优化没改变行为**） |
| 旁路时 vs 原始信号 | **-inf**（完全无染色） |
| 32-bit float 往返 | -inf 或 < -140 dB |

> [!tip] null test 的三个实际价值
> 1. **把"听起来差不多"变成"数值上一致"**
> 2. **优化时的安全网**——改完代码跑一遍，确认行为没变
> 3. **证明"透明"**——比如插件的旁路是否真的无染色

## 六、七类测量陷阱（从踩坑记录提炼）

| # | 陷阱 | 症状 | 防御 |
|---|---|---|---|
| 1 | **绝对阈值测相对量** | 高 Q 滤波器"衰减更快" | 用**相对峰值**的阈值 |
| 2 | **找"第一次"穿越** | 振荡信号给出荒谬的小值 | 找**最后一次**高于阈值的位置 |
| 3 | **在噪声底上拟合** | 斜率符号都反了 | 只拟合**有效衰减区间** |
| 4 | **测量对象已消失** | 测一段静音 | **先看包络**确认信号还在 |
| 5 | **方法不适用** | 过零计数测频率被骗 | 测频率用 FFT 或自相关 |
| 6 | **用错定义/变体** | 对称 vs 周期性 Hann | 确认用的是**哪个变体** |
| 7 | **不补偿窗增益** | 幅度差 6 dB | 除以 `sum(w)` 而非 `N` |

## 八、AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **加窗不补偿相干增益** | 所有幅度差 6 dB | 除以 `sum(w)` |
| 2 | **用白噪声测频响** | 结果有随机起伏，以为代码错了 | 改用脉冲响应 |
| 3 | **用绝对阈值测衰减** | 高 Q 器件被误判 | 用相对峰值 |
| 4 | **在噪声底上做线性拟合** | 斜率错误 | 限制拟合区间 |
| 5 | **`20*log10` 和 `10*log10` 混用** | 差一倍 | 幅度用 20，功率用 10 |
| 6 | **零填充后声称"分辨率提高"** | 概念错误 | 分辨率只由 N 决定 |
| 7 | **不加窗** | 频谱全是毛刺 | `x * window` |
| 8 | **用 `astype` 和 `lround` 混着比** | null test 停在 -90dB | 统一取整，或比浮点 |

> [!warning] 让 AI 自查的提示词
> ```
> 检查这个测量脚本：
> 1. 加窗了吗？补偿相干增益了吗（除以 sum(w) 而非 N）？
> 2. 用的是确定性信号还是随机信号？
> 3. 阈值是绝对的还是相对的？
> 4. 20*log10 还是 10*log10？用对了吗？
> 5. 有没有可能测到的是噪声底？
> ```

## 九、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 幅度差 6 dB | 没补偿窗增益 | 除以 `sum(w)` |
| 频谱全是毛刺 | 没加窗 | 乘窗函数 |
| 结果每次不同 | 用了随机信号 | 用脉冲/扫频 |
| 低频测不准 | $\Delta f = f_s/N$ 限制 | 用自相关 |
| null test 停在 -90dB | 取整约定不同 | 统一，或比浮点 |
| 两个频率分不开 | 观测时间不够 | 增加 N（不是零填充） |
| 测出的衰减时间荒谬 | 阈值方法错 | 见七类陷阱表 |
| THD 结果不可重复 | 没指定频率/电平/带宽 | 完整记录条件 |

## 十、怎么验证你的测量脚本

**三步校准法**：

```python
import sys; sys.path.insert(0, '50-Playground/tools')
from audio_io import sine, spectrum, dominant_freq, peak_db
import numpy as np

# 1. 频率对不对
x = sine(440, 1.0, amp=0.5)
f, mag = spectrum(x, 48000)
assert abs(f[np.argmax(mag)] - 440) < 1, "峰值位置错"

# 2. 幅度对不对（这一步能抓出 6dB 陷阱）
assert abs(peak_db(x) - (-6.02)) < 0.1, "幅度错"

# 3. 两种独立方法是否一致（交叉验证）
assert abs(dominant_freq(x, 48000) - 440) < 1
assert abs(dominant_freq_autocorr(x, 48000) - 440) < 1

print("✅ 测量脚本校准通过")
```

> [!important] 第 2 步是关键
> **如果幅度不对，后面所有测量都不可信。**
> 而且 6 dB 的误差"看起来合理"，所以必须用**已知答案**去卡。
