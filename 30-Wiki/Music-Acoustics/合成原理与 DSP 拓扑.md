# 合成原理与 DSP 拓扑

> [!important] 这一页解决什么问题
> 你玩过加法、减法、粒子、模块合成器——你**知道它们听起来是什么样**。
> 但你不知道：**每一种"听起来是什么样"背后是一个具体的 DSP 结构，
> 而这个结构决定了它必然好听在哪、必然难做在哪。**
>
> 这一页是一张地图：**你拧过的旋钮 → 代码里的结构 → 你会撞上的那堵墙。**
> 它不解释"什么是 FM"，它告诉你"FM 为什么必然混叠，所以你必然要写过采样"。

所有合成器都是同一个骨架，**"哪种合成方式"问的其实是第 ① 步用什么**：
`① 声源（振荡器/采样）→ ② 塑形（滤波器/包络）→ ③ 时变控制（LFO/调制矩阵）`。
第 ② ③ 步的难点对所有合成方式都一样。

---

## 1. 减法合成 → 振荡器 + 滤波器

振荡器产生一个**已经富含谐波**的波形（锯齿、方波），滤波器**减掉**其中一部分。
所以"音色设计"= 选择减掉什么。

### 难点 A：抗混叠振荡器

理想锯齿波有**无限多个**谐波。48 kHz 下奈奎斯特频率是 24 kHz，
1000 Hz 锯齿波的第 25 次以上谐波全部越界——**它们不会消失，会折叠回可听频段**，
变成和基频**不成谐波关系**的成分。谐波衰减越慢的波形越严重（正弦无、三角 −12 dB/oct 轻微、
方波 −6 dB/oct 奇次明显、**锯齿 −6 dB/oct 全谐波最严重**）。
**高音区最严重**：基频越高，越界的谐波越多，折回来的成分也越靠近可听区。

| 解法 | 思路 | 代价 |
|---|---|---|
| 过采样（oversampling） | 高采样率下生成，滤掉带外成分再降采样 | CPU；需要好的抗混叠滤波器 |
| BLEP / BLIT / MinBLEP | 在波形**不连续点**处加带限阶跃做修正 | 需定位不连续点，繁琐但高效 |
| DPW | 多项式波形，差分后自然带限 | 只适合特定波形，高频有损失 |
| 波表 + mipmap | 预计算带限波形 | 内存；见 §4 |

> [!warning] 混叠是不可逆的
> 一旦折回可听频段，它和合法信号**完全无法区分**——输出端加低通也滤不掉。
> 抗混叠必须**在生成时**做。这就是 [[从音乐制作人到插件开发者]] 里"数字味重 = 混叠"的含义。
> 见 [[抗混叠振荡器]]、[[混叠 aliasing]]、[[过采样 oversampling]]。

### 难点 B：模拟滤波器模型

你在硬件合成器上拧的那种"肥"、"有性格"，数字域里很难复刻，原因有两层。

**第一层：模拟滤波器是非线性的。** Moog ladder 的核心是晶体管/二极管饱和，带来：
输入电平越大截止频率和 Q 越**漂移**、谐振自限幅、轻微谐波失真。
一个"数学上正确"的 biquad 完全没有这些——**所以它干净但死板。** 见 [[非线性失真感知]]。

**第二层：零延迟反馈（ZDF）问题。** Moog ladder 是四级一阶低通串成反馈环，朴素实现：

```cpp
// ❌ 反馈环里插入一个采样延迟（unit delay）
// 这个延迟改变了环路相位 → 谐振频率随截止频率偏移
// 而你正是要"扫"这个截止频率，所以问题在扫频时最刺耳
float y = lp4.process (input - k * yPrev);
yPrev = y;
```

**解法**：把反馈环当作**代数方程**直接解出 $y[n]$，而不是用 $y[n-1]$：

$$y[n] = \frac{H_{\text{forward}}(x[n])}{1 + k \cdot H_{\text{feedback}}}$$

这需要每一级的**瞬时**响应，就是 ZDF / TPT（topology-preserving transform）的核心思想。

> [!important] 为什么 [[状态变量滤波器 SVF]] 值得单独一页
> 它的**系数与参数近似线性**，所以可以被 LFO 快速调制而不产生伪影、可以做 ZDF 拓扑、
> 扫频时没有"阶梯感"。用 Biquad 级联做的 ladder 在**静态**下可能听不出问题，
> 一扫截止频率就暴露——**这是"这个插件听起来像玩具"的常见原因。**

## 2. 加法合成 → 正弦叠加 + 包络

$$y(t) = \sum_{k=1}^{N} a_k \sin\!\big(2\pi k f_0 t + \varphi_k\big)$$

直接指定每个谐波的幅度 $a_k$ 和相位 $\varphi_k$——傅里叶级数就是这个公式。
**计算成本是主要障碍**：32 个部分 × 8 复音 = 256 个振荡器 × 每采样一次正弦 → 灾难。

| 解法 | 思路 | 代价 |
|---|---|---|
| 查表 + 线性插值 | 一个周期存 2048 点 | 精度受表长限制 |
| **相位累加器共享** | 所有谐波相位都是基频整数倍 → 只累加一次 | **关键优化：N 个谐波只需 1 个累加器** |
| SIMD 批量 | 一次算 4/8 个谐波 | 需要数据布局配合 |
| **逆 FFT** | 把 $a_k$ 填进频谱数组，一次 IFFT 产生**整个 block** | **现代加法合成器的标准做法**；$O(N)$/采样 → $O(\log N)$/采样 |

> [!tip] 逆 FFT 是加法合成的关键洞察
> 加法合成在**时域**上很贵，在**频域**上极其便宜。代价是分块处理（block size 的延迟）
> 和块间**相位连续性**问题。见 [[FFT 与 STFT]]、[[重叠相加 overlap-add]]。

### 为什么加法合成听起来"电子"

这是 [[MOC - Music & Acoustics]] 点名的问题。答案是**四个具体的缺失**：

| 缺失 | 真实乐器有 | 纯加法有 | 听感 |
|---|---|---|---|
| **相位关系** | 相位由振动模式和激励位置决定，随时间演化 | 通常零相位（全余弦从 0 开始） | 零相位在起音处造成**巨大脉冲峰** → 听成"咔" |
| **噪声成分** | 呼吸、弓毛摩擦、按键、指甲、气声 | 只有谐波 | 过分干净、"塑料" |
| **时变频谱** | 谐波幅度持续变化（钢琴高次谐波先衰减） | 每个音符一个固定频谱 | 静态、像风琴 |
| **非谐性** | $f_k \approx k f_0\sqrt{1 + Bk^2}$，略微偏离整数倍 | 严格整数倍 | 严格谐波听起来"电子/管风琴" |

> [!important] 这张表就是"让加法合成不那么电子"的待办清单
> ① 给每个谐波**随机的、缓慢演化的**初始相位（不要全零）
> ② 加一层**噪声成分**（滤波后的白噪声，跟随包络）
> ③ 让谐波幅度有**各自的包络**（高次谐波衰减更快）
> ④ 引入**轻微非谐性**
>
> 四条全做，加法合成就能听起来像真实乐器。这不是玄学，是四个可实现的改动。
> 见 [[谐波与泛音列]]、[[音高感知]]。

## 3. FM 合成 → 相位调制

**相位调制（PM）**：$y[n] = \sin\!\big(\phi_c[n] + I \cdot \sin(\phi_m[n])\big)$

**频率调制（FM）**：$f(t) = f_c + \Delta f \sin(2\pi f_m t)$。两者**数学上可互相转换**：

$$\boxed{I = \frac{\Delta f}{f_m}}$$

**但"旋钮语义"完全不同**：

| | 相位调制（PM） | 频率调制（FM） |
|---|---|---|
| 深度参数 | 调制指数 $I$（无量纲） | 频偏 $\Delta f$（Hz） |
| 提高 $f_m$ 时 | $I$ 不变 → 音色**保持同一性格**，只是变宽 | $I = \Delta f/f_m$ 下降 → 音色**变简单、变暗** |
| $f_m \to 0$ 时 | 正常 | $I \to \infty$ → 音色爆炸 |
| 实现 | **累加器直接相加**，无需积分 | 需要对调制信号积分 |
| 数值稳定性 | 好 | 差 |

> [!important] 所以"FM 合成器"其实都是 PM
> 商业上叫 FM 的合成器实现上几乎都是**相位调制**。原因就是上表：
> PM 的调制指数与 $f_m$ 无关，所以"亮度"和"音高"是两个独立旋钮；
> 真正的 FM 会让这两个旋钮互相干扰，用户根本没法调。
>
> **这就是"数学上等价但实现和音色不同"的准确含义**——
> 等价性只在换算关系上成立，而**参数化的方式**决定了好不好用。

```cpp
struct FmOperator
{
    double phase = 0.0, sampleRate = 48000.0;
    // phaseMod: 来自调制器的相位偏移（弧度）
    float process (float freqHz, float phaseMod)
    {
        phase += 2.0 * double_Pi * (double) freqHz / sampleRate;
        if (phase > 2.0 * double_Pi) phase -= 2.0 * double_Pi;  // 防精度损失
        return std::sin ((float) phase + phaseMod);              // ← 是 + 不是 ×
    }
};
// 载波 + 调制器：index 就是调制指数 I
float fmSample (FmOperator& c, FmOperator& m, float cHz, float mHz, float index)
{ return c.process (cHz, index * m.process (mHz, 0.0f)); }
```

**难点：FM 极易混叠。** **Carson 带宽法则**：$\text{BW} \approx 2(I + 1) f_m$。
PM 产生位于 $f_c \pm n f_m$ 的**边带**，幅度由贝塞尔函数 $J_n(I)$ 决定；$I$ 越大边带越多。
例：$f_c$=2 kHz、$f_m$=1 kHz、$I$=10 → BW = 22 kHz，**已经贴住 24 kHz 的奈奎斯特**。

风险最高的是：高 $I$（"金属"音色）、高 $f_m$（"铃声"音色）、**高音区演奏**（基频已高，边带立刻越界）、
以及算子反馈 FM（产生噪声状宽带谱）。
**解法**：过采样（2×–8×，FM 是非线性过程，过采样是**必需品**而非优化）；
限制 $I$ 随音高下降（很多经典 FM 合成器就这么做）；调制器本身要用带限波形。

> [!warning] FM 的混叠听起来不像"混叠"
> 减法合成的混叠是"沙沙的脏高频"；FM 的混叠产生的是**非谐波成分**，
> 听起来像"音不准"、"有奇怪的铃声"、"脏但说不上哪脏"。
> **用户不会说"你混叠了"，他会说"这个音色不对"。**

## 4. 波表合成 → 采样 + 插值 + 抗混叠

把**一个周期**存成表，用相位累加器循环读取：
`phase += f0/fs → 取小数部分 → × 表长 → 插值读出 → 输出`。

**关键洞察**：表里存的是"一个周期"，但**播放速率决定基频**。
同一个表，低音播放时谐波都在带内；高音播放时表里的高次谐波就**越界**了——
表含 128 次谐波时，100 Hz 播放第 128 次是 12.8 kHz（✅ 在带内），
500 Hz 播放就是 64 kHz（❌ 远超奈奎斯特 → 混叠）。

**解法：mipmap**——预计算同一波形的一组带限版本，每层限制的谐波数不同，播放时按基频选层：

```cpp
// 每层覆盖一个八度，所以用 log2 索引
int selectMip (float freqHz, double sampleRate)
{
    const float ratio = (float) (sampleRate * 0.5) / std::max (freqHz, 1.0f);
    return std::clamp ((int) std::floor (std::log2 (std::max (ratio, 1.0f))),
                       0, numMips - 1);
}
```

> [!important] 这就是图形学里的 mipmap
> **为不同缩放级别预计算不同细节层次，运行时按需选择。**
> 代价是内存（所有层约是单层的 2 倍，几何级数）和**跨八度换层时的音色跳变**——
> 需要交叉淡化，或让相邻层差异足够小。

| 插值方式 | 质量 | 代价 | 说明 |
|---|---|---|---|
| 取最近点 | 很差 | 0 | 严重量化噪声 |
| **线性** | 可用 | 1 次乘法 | **本身是一个低通**——音越高越暗，还引入少量混叠 |
| **三次 / Hermite** | 好 | 3–4 次乘法 | 常用默认值 |
| 窗化 sinc | 最好 | 很贵 | 母带级重采样才用 |
| 全通 | 幅频平坦 | 中 | 常用于分数延迟，但瞬态有 pre-ringing |

> [!warning] 线性插值不是"够用就行"
> 用线性插值读波表，**高音区**会明显损失高频，而且损失程度**随音高变化**——
> 同一个音色在不同音区听起来不一样。**用户会说"你这个合成器高音区很闷"。**
> 至少用三次插值，或按音高选择插值方式。见 [[插值]]。

## 5. 粒子合成 → 窗口化采样 + 重叠相加

$$\text{out}[n] = \sum_{i} w[n - n_i] \cdot x\big[\,r_i (n - n_i) + p_i\,\big]$$

$w$ = 窗函数，$n_i$ = 粒子起始时刻，$r_i$ = 播放速率（音高），$p_i$ = 读取位置。

| 你拧的旋钮 | 符号 | 听感作用 | 工程注意 |
|---|---|---|---|
| **Grain Size** | 窗长 $L$ | 短（<20 ms）= 颗粒/金属感；长（>100 ms）= 平滑，接近时间拉伸 | 频谱扩散 ≈ $1/L$ |
| **Density** | 每秒粒子数 $D$ | 稀疏 = 听得见单个粒子；密集 = 连续音墙 | $D \times L$ = 重叠因子 |
| **Position** | $p_i$ | 在源素材里"扫描" | 必须**分数延迟**读取 |
| **Spray / Jitter** | $p_i$ 的随机量 | 0 = 干净有音高；大 = 云雾状、失去音高感 | 破坏粒子间相位关系 |
| **Pitch / Speed** | $r_i$ | 变调 / 时间拉伸 | $r \ne 1$ 就是**重采样** → 会混叠 |
| **Window Shape** | $w$ | Hann 最平滑；矩形有咔哒声 | 决定 COLA 条件 |
| **Stereo Spread** | 每粒子声像 | 宽度 | 每声道独立随机 → mono 兼容性下降 |
| **Rate Sync** | $D$ 与 BPM | 颗粒感对齐节拍 | 从宿主取 transport |

**窗函数与重叠相加**：用 **Hann 窗**、50% 重叠（hop = $L/2$）时，**对所有 $n$**：
$w[n] + w[n + L/2] = 1.0$——重叠相加恰好等于 1，输出幅度恒定。
这是 [[重叠相加 overlap-add]] 的 **COLA**（constant overlap-add）条件。

```cpp
// Hann 窗（周期性定义，用于 OLA）
inline float hann (int i, int L)
{ return 0.5f * (1.0f - std::cos (2.0f * float_Pi * (float) i / (float) L)); }

// 重叠因子 = density × grainDuration
// Hann 窗在 hop = L/2（即重叠因子 = 2.0）时满足 COLA
```

> [!warning] 重叠因子不匹配 → 振幅起伏
> 如果 density 和 grain size **独立可调**，用户就能调出 $D \times L < 1$——
> 粒子间有空隙，输出出现**周期性音量起伏**（频率 = $D$）。
> 当 $D$ 落在音频频段（比如 50 粒子/秒），你会听到一个 **50 Hz 的嗡声**。
> **设计决策**：要么绑定 density 与 grain size 保证重叠 ≥ 2，
> 要么重叠不足时自动补偿增益，要么明确告诉用户这是"颗粒感"特性。

**为什么粒子合成特别容易出问题**：① **混叠来源一**——$r \ne 1$ 播放粒子就是重采样，
源素材高频被折叠；② **混叠来源二**——粒子窗本身是**快速幅度调制**，产生的边带可越界；
③ **相位不连续**——相邻粒子取自源素材不同位置，接缝处相位随机；
④ **峰值堆积**——多个粒子波峰同时出现，输出峰值远高于平均电平 → 削波；
⑤ **CPU** 随粒子数线性增长（每粒子独立读取 + 窗 + 插值）。

> [!important] "失去音高感"在粒子合成里是特性，不是 bug
> 位置随机化（spray）破坏了粒子间的相位关系，而**相位关系是音高感知的基础之一**。
> 所以你拧大 spray，声音就从"有音高的音"变成"音云"。
> **这正是粒子合成最独特的音乐价值**——一个"在音高和噪声之间连续移动"的旋钮。
> 见 [[音高感知]]、[[粒子合成 granular synthesis]]。

## 6. 物理建模 → 波导 / Karplus-Strong

```cpp
// Karplus-Strong 的核心只有三行
float karplusStrong (float excitation, float feedback, float damping)
{
    const float delayed = delayLine.read (delaySamples);   // N = fs / f0 → 基频
    // 环路低通：经典的"两点平均"（一阶 FIR）
    const float filtered = 0.5f * (delayed + lastDelayed) * damping;
    lastDelayed = delayed;
    delayLine.write (excitation + filtered);
    return delayed;
}
```

**延迟线长度** → 基频；**环路低通** → 衰减速度 + 衰减时的亮度变化；
**激励信号**（噪声脉冲 / 拨片噪声）→ 起音性格。

**为什么它"真实"**：它模拟的是**物理过程本身**——波在介质中传播、在端点反射、
每次往返损失一点能量（高频损失更多）。真实弦就是这样衰减的。这带来三个"免费"的真实感：

| 现象 | 物理建模里怎么来的 | 其他合成方式 |
|---|---|---|
| **高音衰减更快** | 环路往返更频繁 → 单位时间损失更多能量 | 需手动为每个音高设不同包络 |
| **衰减时高频先消失** | 环路低通每次往返都削高频 | 需手动为每个谐波设包络 |
| **非谐性** | 加入刚度（色散）项，波速随频率变化 | 需手动改成 $k f_0\sqrt{1+Bk^2}$ |

> [!important] "物理建模最真实"的准确含义
> 不是"算法更高级"，而是**它的结构里天然包含了真实乐器的因果链**。
> 你调的不是"谐波幅度"，而是"弦的阻尼"和"长度"——**音乐人能理解的物理量。**
> 见 [[物理建模]]。

### 难点：延迟线长度 ≠ 音高周期

**这是 Karplus-Strong 最常见的实现 bug。** 真实环路周期 = 延迟线长度 **+ 环路滤波器的相位延迟**：

$$f_0 = \frac{f_s}{N + \phi_{\text{filter}}(f_0)}$$

"两点平均"低通在低频处相位延迟约 **0.5 个采样**。所以设 $N = f_s/f_0$ 会让音**偏低**，
而且**不同音高偏低的比例不同**。

| 症状 | 原因 | 解法 |
|---|---|---|
| 音不准，且高音偏低更多 | 没补偿环路滤波器相位延迟 | 用**全通滤波器**调音，或解上式求 $N$ |
| 扫阻尼时音高跟着变 | 阻尼改变了环路相位延迟 | 调音滤波器必须与阻尼解耦 |
| 高音区音高跳变 | 用了整数 $N$ | 用**分数延迟**，见 [[插值]] |

> [!warning] 这个坑极难自己发现
> 你听到的只是"音有点不准"，于是会去查 MIDI 音高换算、采样率、A4=440 还是 432——
> **全都是对的，问题在环路滤波器的相位延迟上。**
> 验证方法：FFT 测实际基频，对比 $f_s/N$，差值就是相位延迟。
>
> **延伸**：Karplus-Strong 是**数字波导（digital waveguide）**的最简形式。
> 完整波导用**两条延迟线**表示两个方向传播的波，可以模拟管的开孔（接分支）、
> 吹奏（非线性激励）、鼓面（二维网格）、人声（波导 + 共振峰）。**它是物理建模的通用语言。**

## 7. 噪声与随机

没有噪声，你无法做气声、镲片、风声、起音的"毛刺"，以及**抖动与去相关**。

| 类型 | 功率谱密度 | 幅度谱斜率 | 听感 |
|---|---|---|---|
| **白噪声** | 平坦（$1/f^0$） | 0 dB/oct | "嘶——"，明亮刺耳 |
| **粉噪声** | $1/f$ | **−1.5 dB/oct** | "沙——"，平衡自然 |
| **布朗噪声** | $1/f^2$ | **−3 dB/oct** | "轰——"，像瀑布/雷声 |

> [!warning] −3 dB/oct 说的是功率，不是幅度
> **功率**谱按 −3 dB/oct 下降，对应的**幅度**谱按 **−1.5 dB/oct** 下降（功率 ∝ 幅度²）。
> 如果你按 −3 dB/oct 去衰减幅度，得到的不是粉噪声，是"更红的噪声"。

> [!important] 为什么粉噪声听起来"更自然"
> **人耳分析频率的方式是对数的**（见 [[临界频带与 Bark 尺度]]）——每个八度占的"听觉空间"大致相同。
> - **白噪声**：每个八度的能量**翻倍** → 最高那个八度的能量等于**它下面所有八度之和** → 听成"只有高频，很刺"
> - **粉噪声**：每个八度的能量**相等** → "每个频段都差不多响" → 平衡、自然
>
> **这就是"粉噪声更自然"的全部原因**：不是更"物理"，而是**更匹配听觉的频率分辨率**。

```cpp
// ⚠️ 下面把 RNG 和状态写成全局，只是为了**看清算法**。
//    真实插件里它们必须是**类的成员**，在 prepareToPlay 里构造/播种 ——
//    否则多个插件实例会互相干扰，而且违反实时契约。
// ❌ 不要用 std::random_device（系统调用，会阻塞音频线程）
// ❌ 不要把分布对象写成函数内 static（初始化可能发生在音频线程）
std::mt19937 gen;  std::uniform_real_distribution<float> dist { -1.0f, 1.0f };
float white() { return dist (gen); }

// 粉噪声 Voss-McCartney：叠加 16 行白噪声，第 k 行每 2^k 个采样才更新一次。
// 更新越慢的行能量越集中在低频，加起来就是近似的 1/f 谱。
// 实测频谱斜率 -3.5 dB/oct（理论 -3.0），对听感已足够"粉"。
std::array<float,16> v {};  std::uint32_t counter = 0;
float pink()
{
    ++counter;  std::uint32_t mask = 1;  int row = 0;
    while (row < 15 && (counter & mask) != 0) { mask <<= 1; ++row; }
    v[row] = white();                        // 最低的 0 位 → 更新哪一行
    float sum = 0.0f;  for (float x : v) sum += x;
    return sum * (1.0f / 16.0f);
}

// 布朗噪声：有泄漏的积分（leak < 1 防止直流漂移累积）
float brown (float& s) { s = 0.99f * s + 0.05f * white();  return s * 4.0f; }
```

> [!warning] 待验证：粉噪声的滤波器系数
> 一个更省 CPU 的做法是用白噪声过一个近似 −3 dB/oct 的**滤波器**（几个极零点组合），
> 比 Voss-McCartney 便宜但精度略差。网上流传的系数版本很多，归一化各不相同——
> **本页不给具体系数**，请自己用 FFT 测频谱斜率确认后再采用（见文末「怎么验证」测试 3）。

| 噪声 | 音乐用途 |
|---|---|
| 白噪声 | 镲片 / 军鼓的"沙"；**抖动（dither）**；测试信号（测频响、测混响 IR） |
| 粉噪声 | **混响 / 空间感的参考信号**；风的底噪；"自然的"背景层；测房间声学 |
| 布朗噪声 | 雷声、瀑布、低频隆隆；电影音效；**LFO 的随机源** |
| 采样保持随机（S&H） | 阶梯状随机 LFO → "随机步进"的调制感 |
| 平滑随机 | 缓慢漂移 → 模拟"元件容差"、模拟味 |

> [!tip] 噪声是"模拟味"的廉价来源
> [[从音乐制作人到插件开发者]] 说"很模拟 = 轻微噪声 + 偶次谐波 + 元件容差"。
> **具体做法**：在反馈环或增益级加入**极低电平**（−90 dB 量级）的噪声。
> 它有三个作用：① 听感上"活"了 ② 打破数字的完美静音 ③ **顺便解决 denormal 问题**。
> **一个操作解决三个问题。** 见 [[denormal 数处理]]。

## 8. 包络与 LFO

**线性包络**每段是直线斜坡；**指数包络**每段是一阶低通的充放电曲线：

$$y(t) = y_{\text{target}} + (y_{\text{start}} - y_{\text{target}}) \cdot e^{-t/\tau}$$

> [!important] 为什么模拟包络是指数的
> 因为模拟包络就是 **RC 电路**：电容通过电阻充放电，电压天然服从上式。
> **这不是设计选择，是物理必然。** 所以"模拟味包络" = "指数包络"，
> 而且**上升段也是指数的**（线性包络的上升段是直线）。
>
> 对**幅度**而言指数更自然：指数衰减在**幅度**上是指数，在 **dB** 上是**直线**——
> 符合听感上的"均匀衰减"。真实乐器的自然衰减（拨弦、击键）也都是指数衰减。

```cpp
// 关键技巧：内部目标值要**超过**最终值，才能在指定时间内到达
void startSegment (float start, float final, float timeSec, float curve)
{
    current = start;
    const float tau = timeSec / curve;              // curve ≈ 4.6 时接近"4.6τ 到达"
    coeff = 1.0f - std::exp (-1.0f / (sampleRate * tau));
    // 反解过冲目标，使 y 在 timeSec 后恰好等于 final：y(t) = target + (start-target)·k
    const float k = std::exp (-timeSec / tau);
    target = (k < 0.9999f) ? (final - k * start) / (1.0f - k) : final;
}
float next() { current += (target - current) * coeff; return current; }  // 每采样调用
```

> [!warning] 指数包络的"永远到不了"与过冲陷阱
> 一阶低通**永远不会精确等于**目标值。"过冲目标"技巧解决了到达问题，
> 但**极短的包络时间（如 0.1 ms）会让过冲目标变得极大**，数值上可能溢出或爆音。
> **做法**：给时间设下限（如 0.5 ms），并钳制 `target` 的范围。

| LFO 波形 | 调制特征 | 典型用途 |
|---|---|---|
| 正弦 / 三角 | 平滑无棱角 / 线性升降 | vibrato、滤波扫频、混响去相关；音高调制、tremolo |
| 锯齿 / 方波 | 单向扫描有跳变 / 只有两个状态 | 节奏性的上升下降；trill、八度跳变、硬切换 |
| 采样保持（S&H） | 阶梯随机 | "随机步进"，复古感 |
| 平滑随机 | 缓慢漂移 | 模拟漂移、自然感、**去相关** |

**速率范围**：< 0.1 Hz 听成"参数慢慢变了"；0.1–5 Hz 是 vibrato 下限、混响的"活"感；
**5–8 Hz 是 vibrato 常用区**（人声、弦乐）；8–20 Hz 是 tremolo、音高抖动（flutter）；
> 20 Hz 进入音频速率 → 变成 FM/AM 音色。

> [!warning] 待验证：上面的速率分界
> 这是合成器设计领域的常见惯例，不是从资料推导出的结论，不同来源给出的分界也不一致。
> **做插件时把它当作默认值和参数范围的起点，靠听感调**，不要当成硬性规则。

> [!important] LFO 相位在多声道里是"宽度旋钮"
> 左右用**同一个** LFO（同相）→ 声像不变；左右用**相位差 90°–180°** → 声音变宽。
> 这就是 chorus 变宽的原理。**代价是单声道兼容性**——
> 见 [[立体声感知]]、[[调制效果]]、[[拍频与失谐]]。
> **设计决策**：给用户一个 "stereo width" 参数，默认不要拉满。
>
> **LFO 不能随便加到任何参数上**：加到**延迟时间** → 故意要的多普勒（chorus 就靠这个）；
> 加到**滤波器系数** → 必须每采样更新系数，否则有"阶梯感"；加到**增益** → 相对安全。

## 设计决策表

| 音乐人想要的 | 算法上要实现什么 |
|---|---|
| "一个肥厚的贝斯" | 锯齿/方波 + 陡峭 ladder 低通（24 dB/oct）+ 滤波包络 attack 20–60 ms + 轻微 detune |
| "会呼吸、会扫的 pad" | 波表（或多振荡器 detune）+ 慢 LFO 调制波表位置/截止频率 + 长 attack/release（> 1 s） |
| "铃铛 / 金属音色" | FM/PM + **非整数**频率比 + 高调制指数 + **必须过采样** |
| "电钢琴那种敲击感" | FM + 整数比 + 调制指数**随包络衰减**（index envelope 是关键） |
| "真实感的拨弦/弦乐" | Karplus-Strong / 波导 + 噪声激励 + **全通调音滤波器**补偿相位延迟 |
| "音云 / 纹理 / 不要音高" | 粒子合成 + 大 spray + 短 grain（< 30 ms）+ 高 density |
| "时间拉伸但保持音高" | 粒子合成（$r = 1$，移动 $p_i$）或相位声码器；前者有颗粒感，后者有金属味 |
| "干净的、能到很高音区的锯齿" | 抗混叠振荡器（BLEP/DPW 或过采样）+ 三次插值 + mipmap 波表 |
| "温暖的模拟滤波器扫频" | ZDF/TPT 拓扑 + 环路非线性（饱和）+ **每采样**更新系数 + SVF 而非 Biquad |
| "自然的背景噪声层" | 粉噪声（−3 dB/oct **功率**）+ 缓慢的滤波调制 |
| "有模拟味的漂移" | 平滑随机 LFO（< 0.5 Hz）+ 极低电平噪声 + 轻微的元件不一致 |
| "宽立体声" | LFO 左右相位差 90°–180°，或每声部微失谐；**必须检查 mono 兼容性** |
| "音头要有咔哒的打击感" | 包络 attack < 1 ms **且**从当前值重触发；或直接注入一个短噪声脉冲 |

## 常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 高音区"沙沙"的脏高频 | 混叠（振荡器 / FM 边带 / 重采样） | 过采样 / BLEP / mipmap |
| 同一音色在不同音区不一样 | 插值质量随音高变化；mipmap 换层没淡化 | 三次插值；层间交叉淡化 |
| 扫截止频率有"阶梯感" | 滤波器系数每 block 只更新一次 | 每采样更新，或用 [[状态变量滤波器 SVF]] |
| 滤波器扫频时音高会偏 | 朴素 ladder 实现的单位延迟 | ZDF / TPT 拓扑 |
| Karplus-Strong 音不准 | 环路滤波器相位延迟未补偿 | 全通调音滤波器 |
| 粒子合成输出削波 | 粒子峰值堆积 | 留 headroom、加限制器、按重叠因子补偿增益 |
| 粒子稀疏时有"嗡"声 | 重叠不足，密度本身成了音频速率 AM | 绑定 density 与 grain size，保证重叠 ≥ 2 |
| 包络松键时"咔" | release 太短 | release 下限 5–20 ms |
| 快速连奏爆音 | 包络重触发从 0 开始 | 从**当前值**重触发 |
| 粉噪声听起来不对 | 把 −3 dB/oct 当成了幅度斜率 | 功率 −3 dB/oct = 幅度 −1.5 dB/oct |
| 静音时 CPU 高（噪声） | 用了 `std::random_device` | 用 `std::mt19937`，在 `prepareToPlay` 里构造 |
| 音频线程里分配内存 | 每次音符触发 `new` 一个 voice | 预分配 voice pool；见 [[实时音频线程契约]] |
| 静音后 CPU 飙升 | 反馈环路的 denormal | 见 [[denormal 数处理]] |
| 立体声变宽后 mono 塌掉 | LFO 左右相位差过大 | 提供 width 参数；检查 mono 兼容性 |

> [!warning] 最后三条和合成算法完全无关
> 但它们是"合成器插件在用户机器上不能用"的常见真凶。
> **音频线程契约适用于所有插件，合成器尤其容易违反**——因为合成器有"事件"（音符开/关），
> 而事件最容易诱导你在音频线程里做分配。

## 怎么验证

**听感测试**

1. **混叠**：关掉所有调制，从最低音滑到最高音。高音区不应出现**和基频不成谐波关系**的"沙沙"成分。
2. **扫频**：截止频率 20 Hz → 20 kHz，同时播放持续音。应该**平滑**，没有台阶、没有"咔咔"声。
3. **音准**：弹一个八度内所有半音，逐个测。**Karplus-Strong 和 FM 最容易在这里出问题。**
4. **包络**：attack 和 release 都设到最短，快速连奏。不应有"咔"声或爆音。
5. **粒子**：density 拧到最低应听到**清晰的单个粒子**；拧到最高应是**连续音墙**，无音量起伏。

**数值测试**

```cpp
// 1. 抗混叠（两根支柱之一）：生成 5 kHz 锯齿做 FFT
//    断言所有非谐波峰（不属于 k*f0 的峰）都比基频低 > 60 dB
// 2. 调音精度（另一根支柱）：每个 MIDI 音符用 FFT 测基频
//    断言 |实测 - 理论| / 理论 < 0.1%（约 1.7 cent）
//    这一条能抓出 Karplus-Strong 的相位延迟 bug
// 3. 噪声频谱斜率（10 秒 + Welch 平均）
//    粉噪声 -3 dB/oct（±0.5）；白噪声 0 dB/oct（±0.2）；布朗 -6 dB/oct（±0.5）
// 4. COLA 条件（写粒子引擎之前就能验证窗函数定义）
//    Hann 窗、hop = L/2：断言任意 n 处所有覆盖窗之和 == 1.0（±1e-6）
// 5. 包络到达时间：attack = 100 ms 时，达到最终值 99% 的时间在 100 ms ± 10% 内
// 6. 稳定性（物理建模/反馈结构）：喂脉冲跑 10 秒
//    断言不发散，且最终衰减到 < -80 dBFS
```

> [!tip] 测试 1 和 2 是最高杠杆的两个
> **测试 1（抗混叠）** 决定你的合成器"听起来专不专业"；
> **测试 2（音准）** 决定它"能不能用"。
> 两条都能自动化、几秒跑完。**先写这两个测试，再写振荡器。** 见 [[AI 生成音频测试]]。
