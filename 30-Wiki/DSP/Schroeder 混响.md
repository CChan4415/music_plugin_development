# Schroeder 混响

> [!important] 一句话
> **Schroeder 混响 = 4 个并联的梳状滤波器 + 2 个串联的全通滤波器。**
> 它是第一个"用少量延迟线造出混响"的实用结构（Manfred Schroeder，1960 年代），
> 至今仍是理解混响的最佳起点。

## 为什么从它开始学

| 理由 | 说明 |
|---|---|
| **结构最简单** | 只有两种构件：梳状 + 全通 |
| **每个构件都能单独听** | 加一个、听一次，因果关系清楚 |
| **Freeverb 是它的直系后代** | 你用过的大部分免费混响都是这个结构 |
| **它的缺陷很典型** | 金属味、回声密度不足 —— 理解了才知道 FDN 好在哪 |

> [!tip] 学习顺序建议
> ```
> 单个反馈延迟 → 梳状滤波器 → + 阻尼 → 全通 → Schroeder → Freeverb → FDN
> ```
> 每一步只加**一个**新概念，而且每一步都能**听出区别**。
> 见 [[exp-003 从延迟到混响]]（可运行）。

## 一、结构

```
                    ┌─→ [梳状 1] ─┐
                    ├─→ [梳状 2] ─┤
   输入 ──┬─────────┼─→ [梳状 3] ─┼──→ Σ ──→ [全通 1] → [全通 2] ──→ 输出
          │         └─→ [梳状 4] ─┘
          │                                        │
          └────────────────────────────────────────┘
                        （干信号，可选）
```

**两级各司其职**：

| 级 | 构件 | 作用 |
|---|---|---|
| 第一级 | **并联梳状滤波器** | 产生**回声**（延迟 + 反馈） |
| 第二级 | **串联全通滤波器** | **打散**回声、增加密度（不改频响，只改相位） |

> [!important] 为什么并联用梳状、串联用全通
> - **并联**：多个不同的回声模式**相加** → 密度提升
> - **串联**：全通**不改变幅度谱**，所以可以串联很多级而不会染色
>   —— 这是全通最关键的性質（见 [[全通滤波器 allpass]]）

---

## 二、梳状滤波器

### 基本形式

```
输入 ──┬──────────────────→ Σ ──→ 输出
       │                    ↑
       └→ [延迟 d] ─────────┘
                     × g
```

$$y[n] = x[n] + g \cdot y[n-d]$$

**频率响应**（这是"梳状"名字的来源）：

$$|H(f)| = \left|\frac{1}{1 - g e^{-j2\pi f d / f_s}}\right|$$

**峰值出现在** $f = k \cdot f_s / d$（$k = 0,1,2,\dots$），间隔 $f_s/d$。

> [!note] 这就是"梳状"
> 频响上有**等间隔的峰和谷**，看起来像梳子的齿。
> 间隔 = $f_s / d$。延迟 $d$ 越长，齿越密。

### 带阻尼的梳状（Freeverb 的关键改进）

```cpp
class Comb
{
public:
    void prepare (int size, float feedback, float damp)
    {
        buffer.assign ((size_t) size, 0.0f);
        idx = 0; fb = feedback; damp1 = damp; damp2 = 1.0f - damp;
        store = 0.0f;
    }
    float process (float x)
    {
        const float out = buffer[(size_t) idx];
        // 一阶低通（阻尼）—— 在反馈路径里
        store = out * damp2 + store * damp1;
        buffer[(size_t) idx] = x + store * fb;
        if (++idx >= (int) buffer.size()) idx = 0;
        return out;
    }
private:
    std::vector<float> buffer;
    int idx = 0;
    float fb = 0.0f, damp1 = 0.0f, damp2 = 1.0f, store = 0.0f;
};
```

**阻尼的作用**：让**高频衰减更快**（模拟空气和软表面对高频的吸收）。

> [!important] 实测证据：阻尼确实在起作用
> 用 8 个梳状滤波器（互质延迟）实测"高频 - 低频"能量差随时间的变化：
>
> | damp | @0–0.1s | @0.5–0.6s | @1.0–1.1s |
> |---|---|---|---|
> | **0.0** | +11.9 dB | +11.7 dB | +11.4 dB |
> | **0.5** | +9.1 dB | **-35.3 dB** | **-68.4 dB** |
> | **0.8** | +7.9 dB | **-131.3 dB** | **-156.9 dB** |
>
> - damp=0：差值**恒定**（~12dB）→ 高低频衰减一样快 → **无阻尼**
> - damp=0.8：差值掉到 **-157 dB** → 高频衰减快得多
>
> **这就是"数字味混响"和"自然混响"的区别。**
> 见 [[exp-003 从延迟到混响]]。

## 三、全通滤波器

```
输入 ──┬──→ [× -g] ──────────→ Σ ──→ 输出
       │                       ↑
       └──→ [延迟 d] ──┬───────┘
                      └──→ [× g] ──→ （反馈回延迟输入）
```

$$y[n] = -g\,x[n] + x[n-d] + g\,y[n-d]$$

**关键性质**：$|H(f)| = 1$ 对**所有频率**成立。

> [!important] 为什么这个性质重要
> 全通**不改变幅度谱**，只改变**相位**。
> 所以你可以串联任意多个全通，**不会让声音变亮或变暗**，
> 只会让回声"糊"起来。
>
> 这是它能当"扩散器"用的唯一原因。

> [!warning] 但全通有个副作用
> 串联的全通会产生**密集的、有规律的时间间隔** →
> 这是 Schroeder 混响"金属味"的**第二个来源**（第一个是延迟比）。

## 四、延迟时间的选择（**最关键的一节**）

### 规则 1：绝不用整数倍关系

> [!danger] 实测证据：整数倍延迟有多糟
> 对比两组延迟时间（8 个并联梳状，反馈 0.9）：
>
> | 延迟组 | 频响范围 | **强共振峰数量** |
> |---|---|---|
> | **互质** `[1116, 1188, 1277, 1356, 1422, 1491, 1557, 1617]` | -5.5 ~ +14.1 dB | **6 个** |
> | **整数倍** `[1000, 2000, 3000, ...]` | -4.7 ~ +20.0 dB | **77 个** ⚠️ |
>
> **77 个强共振峰 vs 6 个**——这就是"金属管"音色的数学解释。
> 整数倍延迟让所有梳状的峰**在同一频率上叠加**，
> 形成又高又尖的共振，听起来像金属管或弹簧。

**规则**：
- ✅ 用**互质**（mutually prime）的延迟时间
- ✅ 或至少避免简单的整数比
- ❌ 绝不用 1000/2000/3000 这种

### 规则 2：Freeverb 的经典调音值

```
1116, 1188, 1277, 1356, 1422, 1491, 1557, 1617   （左声道）
1116+23, 1188+23, ...                             （右声道，偏移 23 样本）
```

> [!note] 这些数字怎么来的
> 它们是**经验调出来的**——这正是 [[10-Sources/articles/Luff - Let's Write A Reverb|Luff 批评的"魔法数字"]]。
> 能用，但你不理解为什么。
>
> **更好的做法**（Luff 的建议）：把延迟范围**等分**，
> 每个声道在一个子区间里随机取值 → 近似均匀分布且随机。

### 规则 3：延迟时间要足够长

太短（< 10ms）→ 回声太稀疏，听得出单个回声。
典型范围：**20–60ms**。

## 五、Schroeder 的三大缺陷（以及怎么修）

| # | 缺陷 | 原因 | 修法 | 谁修了 |
|---|---|---|---|---|
| 1 | **金属味** | 延迟成整数比 → 强共振峰叠加 | 用互质延迟 | Freeverb |
| 2 | **尾巴太亮** | 无频变衰减 | 反馈路径加阻尼低通 | Freeverb |
| 3 | **回声密度不足** | 并联梳状互不干扰，密度增长慢 | 用矩阵混合（FDN） | FDN |
| 4 | **有周期性** | 延迟固定 → 驻波 | 调制延迟线（±1–3ms） | 现代混响 |

> [!tip] 从 Schroeder 到 Freeverb 到 FDN 的演进
> ```
> Schroeder (1960s)   4 梳状 + 2 全通
>      ↓ 加阻尼、加更多梳状、调互质延迟
> Freeverb (2000)     8 梳状(带阻尼) + 4 全通 + 立体声偏移
>      ↓ 用矩阵混合代替固定连接
> FDN (现代)          延迟线 + 正交矩阵 + 频变衰减 + 调制
> ```
> 每一步都在修上一步的缺陷。**理解这条线，你就理解了混响史。**

## 六、RT60 与反馈增益

用户拧的是"decay 秒数"，你要算的是反馈增益：

$$g = 10^{-3 \cdot d / \mathrm{RT60}}$$

其中 $d$ = 延迟时间（秒）。

**推导**：每次循环幅度 × g，衰减 60dB 需要 $g^n = 10^{-60/20} = 0.001$，
所以 $n = \log(0.001)/\log(g)$，$RT60 = n \cdot d$。

> [!tip] 已实测验证
> 单个梳状（延迟 23.27ms）实测衰减到 -60dB 的时间：
>
> | g | 理论 RT60 | 实测 RT60 | 偏差 |
> |---|---|---|---|
> | 0.8 | 0.72s | 0.74s | +3.4% |
> | 0.9 | 1.53s | 1.56s | +2.2% |
> | 0.99 | 15.99s | 16.03s | +0.2% |
> | 0.999 | 160.67s | 160.71s | +0.0% |
>
> 偏差来自"衰减到 1e-3 的那次循环"是离散的。**公式可直接用在插件里。**

> [!warning] 多个梳状滤波器时
> 每个梳状的延迟不同，**同一个 g 会给出不同的 RT60**。
> 要让它们同时衰减到 -60dB，需要**每个梳状单独算 g**：
> $$g_i = 10^{-3 \cdot d_i / \mathrm{RT60}}$$
>
> **这是最容易忽略的细节。** 见 [[反馈延迟网络 FDN]]。

## 七、AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **延迟用 1000/2000/3000** | 强烈金属味（实测 77 个共振峰） | 检查延迟是否成整数比 |
| 2 | **所有梳状用同一个 g** | 各延迟线 RT60 不一致 | 检查 $g_i$ 是否按 $d_i$ 算 |
| 3 | **反馈路径没阻尼** | 尾巴太亮、不自然 | 检查反馈里有没有低通 |
| 4 | **没有 denormal 处理** | 安静时 CPU 飙升 | 见 [[denormal 数处理]] |
| 5 | **反馈增益不钳制** | 用户能调出爆炸 | 检查 `clamp(g, 0, 0.999)` |
| 6 | **全通和梳状的公式搞混** | 结构错误 | 全通有前馈 + 反馈；梳状只有反馈 |
| 7 | **左右声道共用延迟线** | 串音、无宽度 | 检查是否 per-channel 实例 |
| 8 | **在音频线程分配缓冲区** | 违反实时契约 | 检查 `prepare` 里是否分配 |

> [!tip] 第 1 条最容易验证
> 让 AI 写完，你直接看延迟数组：
> ```cpp
> // ❌ 一眼就能看出问题
> int delays[] = {1000, 2000, 3000, 4000};
> // ✅ 互质
> int delays[] = {1116, 1188, 1277, 1356};
> ```

## 八、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 金属味/铃声 | 延迟成整数比 | 用互质延迟 |
| 尾巴太亮 | 无阻尼 | 反馈路径加低通 |
| 回声密度不足 | 全通级数太少 | 增加全通，或改用 FDN |
| 有周期性"嗡嗡" | 延迟太短或有公约数 | 拉长延迟，检查互质性 |
| 发散/爆炸 | 反馈 ≥ 1 | 钳制到 0.999 |
| 安静时 CPU 飙升 | denormal | 见 [[denormal 数处理]] |
| 立体声窄 | 左右延迟相同 | 加偏移（如 +23 样本） |
| 改参数爆音 | 延迟时间突变 | 交叉淡化，见 [[延迟线 delay line]] |

## 九、怎么验证

| 测试 | 方法 | 期望 |
|---|---|---|
| **稳定性** | 喂脉冲跑 10 秒 | 衰减到 0，不发散 |
| **RT60 准确** | 测衰减曲线 | 接近设定值（±20%） |
| **阻尼有效** | 分频段测 RT60 | 高频衰减更快 |
| **无强共振** | 频谱看峰的数量 | 不应有密集尖峰 |
| **无 denormal** | 看安静时 CPU | 不升高 |
| **回声密度** | 看脉冲响应的密度增长 | 应快速变密 |

```python
import numpy as np
# 验证 RT60 公式
def feedback_for_rt60(rt60, delay_sec):
    return 10 ** (-3.0 * delay_sec / rt60)

# 检查延迟是否互质
from math import gcd
from functools import reduce
delays = [1116, 1188, 1277, 1356]
g = reduce(gcd, delays)
print(f"延迟的最大公约数: {g}  {'✅ 互质' if g == 1 else '❌ 有公约数'}")
```
