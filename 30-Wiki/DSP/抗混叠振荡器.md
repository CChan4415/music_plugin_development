# 抗混叠振荡器

> [!important] 一句话
> **理想的锯齿波和方波带宽无限**——它们在 Nyquist 以上也有能量，
> 采样后会**折叠回来**变成不谐和的"金属声"。抗混叠振荡器就是解决这个的。

## 为什么这一页重要

你做减法合成器时，振荡器是**声音的源头**。
一个朴素锯齿在高音区会明显"脏"——那不是你的错觉，是混叠。

| 你的听感 | 原因 |
|---|---|
| 高音区有"金属味"、"沙沙声" | 混叠 |
| 音越高越明显 | 谐波间隔随音高变宽，更多谐波越过 Nyquist |
| 音符之间音质不一致 | 不同音高的混叠程度不同 |
| "这个合成器听起来很数字" | 大概率是振荡器没做抗混叠 |

---

## 一、问题：理想波形的带宽无限

**理想锯齿波**的傅里叶级数：

$$x(t) = \frac{2}{\pi}\sum_{k=1}^{\infty} \frac{(-1)^{k+1}}{k}\sin(2\pi k f_0 t)$$

**每一项的幅度按 $1/k$ 衰减，但项数无限**。

采样后，所有 $k f_0 > f_s/2$ 的成分**不会消失**，而是折叠：

$$f_{\text{alias}} = \left| k f_0 - f_s \cdot \mathrm{round}\!\left(\frac{k f_0}{f_s}\right) \right|$$

> [!danger] 为什么混叠听起来特别"脏"
> 折叠回来的频率与基频**不成谐波关系**——
> 它不是"更高的泛音"，而是一个**无关的音**。
> 人耳对不谐和成分非常敏感，所以听起来"金属"、"刺"。
>
> 对比：失真产生的谐波是**谐波关系**的（虽然多，但和谐）；
> 混叠产生的是**非谐波**成分。这是本质区别。
>
> 见 [[混叠 aliasing]]。

---

## 二、⚠️ 实测：朴素锯齿有多糟

**测试条件**：48kHz，$f_0$ = 2000 Hz，16384 点，测"非谐波能量 / 谐波能量"。

| 方法 | 混叠/谐波 | 相对朴素 |
|---|---|---|
| **朴素锯齿**（`2·phase − 1`） | **-17.6 dB** | — |
| **PolyBLEP** | **-67.3 dB** | **-49.7 dB** ✅ |
| 朴素 + 4× 过采样 | -32.4 dB | -14.9 dB |

> [!important] 怎么读
> PolyBLEP 把非谐波能量降低了 **49.7 dB**——
> 这是巨大的改善，而且**几乎不增加 CPU**。
>
> 4× 过采样只降低 14.9 dB，却要 4 倍的计算量。
> **PolyBLEP 性价比远高于过采样。**

> [!note] 关于 DPW 的诚实说明
> DPW（Differentiated Parabolic Waveform）也是常见方法，
> 但**它需要额外步骤**：差分后要按 $1/\Delta t$ 缩放、再积分回去、并去除差分引入的直流。
>
> 我尝试实现时漏了这些步骤，测出"比朴素更差"（+9.4 dB）的结论——
> **那是我的实现错误，不是 DPW 的问题。**
> 因为我没有把握给出正确的 DPW 实现，**本页不给 DPW 的对比数字**。
> 只说明它的原理和"需要额外处理"这一事实。

## 三、PolyBLEP：最实用的方法

**核心思想**：在波形的**不连续点附近**加一个多项式修正，
把"一步跳变"换成"平滑过渡"——平滑的过渡意味着高频能量少。

**BLEP** = Band-Limited Step（带限阶跃）。
**PolyBLEP** = 用多项式近似的 BLEP。

### 修正函数

```cpp
// t: 相位（归一化到 [0,1)），dt: 每采样相位增量 = f0/sr
inline float polyBlep (float t, float dt) noexcept
{
    if (t < dt)                     // 刚跳过不连续点
    {
        t /= dt;
        return t + t - t * t - 1.0f;
    }
    if (t > 1.0f - dt)              // 即将跳到不连续点
    {
        t = (t - 1.0f) / dt;
        return t * t + t + t + 1.0f;
    }
    return 0.0f;
}
```

### 锯齿波

> [!note] 下面的类用到上面的 `polyBlep` 函数
> 三个代码块按顺序组合即可编译（本库已验证）。

```cpp
class SawOscillator
{
public:
    void prepare (double sampleRate) { sr = sampleRate; phase = 0.0; }

    void setFrequency (float hz) { freq = hz; }

    float process() noexcept
    {
        const float dt = (float) (freq / sr);

        float value = 2.0f * (float) phase - 1.0f;   // 朴素锯齿
        value -= polyBlep ((float) phase, dt);       // ← 关键修正

        phase += dt;
        if (phase >= 1.0) phase -= 1.0;

        return value;
    }

private:
    double sr = 48000.0, phase = 0.0;
    float freq = 440.0f;
};
```

### 方波（两个不连续点）

方波有**两个跳变**（上升沿和下降沿），所以要修正两次。
下面是 `SawOscillator` 之外的成员函数片段（需要 `polyBlep` 在作用域内）：

```cpp
float processSquare() noexcept
{
    const float dt = (float) (freq / sr);
    const float t  = (float) phase;

    float value = (t < 0.5f) ? 1.0f : -1.0f;        // 朴素方波（占空比 50%）
    value += polyBlep (t, dt);                       // 上升沿
    value -= polyBlep (std::fmod (t + 0.5f, 1.0f), dt);  // 下降沿（相位偏移 0.5）

    phase += dt;
    if (phase >= 1.0) phase -= 1.0;
    return value;
}
```

> [!tip] 三角波不需要抗混叠
> 三角波的谐波按 $1/k^2$ 衰减，高频能量本身就很低。
> 朴素三角波在高音区可接受（除非你要极高的音质）。
>
> **需要抗混叠的**：锯齿、方波、脉冲（有不连续点）。

## 四、其他方法对比

| 方法 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| **PolyBLEP** | 在不连续点加多项式修正 | **性价比最高**、CPU 低 | 修正只对跳变有效 |
| **BLIT/BLEP** | 用带限脉冲求和 | 质量更高 | 实现复杂、有直流问题 |
| **DPW** | 差分把不连续变成连续 | 简单 | **需要额外缩放/积分/去直流** |
| **波表 + mipmap** | 每个八度一套带限波表 | 质量最好、适合复杂波形 | 内存占用、切换要处理 |
| **过采样** | 在高采样率下生成再滤除 | 通用（任何波形都行） | CPU 高（实测只降 14.9 dB @ 4×） |
| **加法合成** | 只叠加 $f_s/2$ 以下的谐波 | 天然带限、精确可控 | CPU 随谐波数增长 |

> [!tip] 实际选型
> | 场景 | 推荐 |
> |---|---|
> | 简单锯齿/方波合成器 | **PolyBLEP** |
> | 复杂波形（多波形、变形） | **波表 + mipmap** |
> | 需要极致音质、CPU 充裕 | BLIT 或加法合成 |
> | 已经要过采样（如失真） | 可以顺便用朴素振荡器 |
>
> **绝大多数情况下 PolyBLEP 就够。**

## 五、波表 + mipmap（另一种主流方案）

**原理**：预先算好**每个八度**的带限波表。

```
八度 0（最低）：完整谐波
八度 1：谐波数减半
八度 2：再减半
...
```

播放时按音高选对应的表，并在相邻表之间**插值**（避免切换时的"台阶"）。

| 优点 | 缺点 |
|---|---|
| 质量最高 | 内存占用（表数量 × 表长度） |
| CPU 低（查表） | 需要生成表的工具链 |
| 可以做复杂波形变形 | 切换八度要平滑处理 |

> [!warning] mipmap 的实现细节本页不展开
> 涉及：表长度选择、八度边界、交叉淡化、内存布局。
> 需要时查专门资料。见 [[_meta/open-questions]]。

## 六、AI 会怎么写错

| # | AI 常犯 | 后果 | 怎么查 |
|---|---|---|---|
| 1 | **写朴素锯齿/方波不加抗混叠** | 高音区金属味（实测 -17.6 dB） | 看有没有 `polyBlep` 调用 |
| 2 | **PolyBLEP 修正方向错（加/减反了）** | 比朴素更差 | 实测混叠应降低 20dB 以上 |
| 3 | **方波只修正一个跳变** | 只修一半 | 两个跳变都要修 |
| 4 | **`dt` 用错**（用了固定值或旧的 freq） | 高音区修正失效 | `dt = freq/sr`，每采样更新 |
| 5 | **相位用 `float` 累加** | 长时间播放精度损失 | 用 `double` 存相位 |
| 6 | **相位回绕写成 `phase = phase - 1`** 但 phase 可能 > 2 | 相位跑飞 | 用 `while` 或 `fmod` |
| 7 | **以为三角波也需要抗混叠** | 多余复杂度 | 三角波谐波衰减快（$1/k^2$） |
| 8 | **DPW 不加缩放/积分/去直流** | 输出完全错误 | 见第二节的诚实说明 |
| 9 | **忘了处理负频率/极端参数** | 除零或 NaN | 钳制 freq |

> [!danger] 第 2 条最难发现
> PolyBLEP 的修正符号写反时，**波形看起来"更平滑"了**，
> 你可能以为"抗混叠生效了"——但实际混叠**更严重**。
>
> **必须实测混叠能量**，不能靠看波形或听感。

## 七、常见坑

| 症状 | 原因 | 解法 |
|---|---|---|
| 高音区金属味 | 没做抗混叠 | 用 PolyBLEP |
| 修正后反而更脏 | 修正符号反了 | 实测混叠能量 |
| 方波只有一边有咔哒 | 只修正了一个跳变 | 两个跳变都修 |
| 长时间播放音准漂移 | 相位用 float | 用 double |
| 高音区修正失效 | `dt` 计算时机错 | 每采样算 `dt` |
| 频率为负/0 时崩 | 没钳制 | 钳制 freq ≥ 0 |
| 波表切换有爆音 | 没做交叉淡化 | 相邻表插值 |

## 八、怎么验证

**核心指标：混叠能量 / 谐波能量**（越低越好）。

```python
import numpy as np
SR = 48000

def alias_to_harmonic_db (x, f0, sr=SR, tol_hz=30.0):
    """测量非谐波能量相对谐波能量的 dB 值"""
    w = np.hanning (len(x))
    X = np.abs (np.fft.rfft (x * w)) ** 2
    fr = np.fft.rfftfreq (len(x), 1/sr)

    harm = np.zeros (len(fr), bool)
    k = 1
    while k * f0 < sr / 2:
        harm |= np.abs (fr - k*f0) < tol_hz
        k += 1

    total = np.sum (X)
    h = np.sum (X[harm])
    return 10 * np.log10 ((total - h) / (h + 1e-30))

def saw_naive (f0, n, sr=SR):
    ph = (np.arange (n) * f0 / sr) % 1.0
    return 2*ph - 1

def polyblep (t, dt):
    if t < dt:
        t /= dt;  return t + t - t*t - 1.0
    if t > 1.0 - dt:
        t = (t - 1.0) / dt;  return t*t + t + t + 1.0
    return 0.0

def saw_polyblep (f0, n, sr=SR):
    dt = f0 / sr
    out = np.zeros (n)
    ph = 0.0
    for i in range (n):
        v = 2*ph - 1
        v -= polyblep (ph, dt)
        ph += dt
        if ph >= 1.0: ph -= 1.0
        out[i] = v
    return out

# 实测对比
f0, N = 2000.0, 16384
a_naive = alias_to_harmonic_db (saw_naive (f0, N), f0)
a_blep  = alias_to_harmonic_db (saw_polyblep (f0, N), f0)

print (f"朴素锯齿: {a_naive:>7.1f} dB")
print (f"PolyBLEP: {a_blep:>7.1f} dB")
print (f"改善:     {a_blep - a_naive:>7.1f} dB")

assert a_blep < a_naive - 20, "PolyBLEP 没有生效！检查修正符号"
print ("✅ PolyBLEP 生效（混叠降低 > 20 dB）")
```

> [!tip] 这个断言就是最好的自检
> `assert a_blep < a_naive - 20`
>
> 它同时抓住：
> - 忘了加抗混叠（两者相同）
> - 修正符号写反（PolyBLEP 更差）
> - `dt` 算错（改善不足）

**另一个测试：扫频听高频**

```python
# 让振荡器从 100Hz 扫到 15kHz，听高音区是否有金属声
# 有抗混叠 → 音色一致地"干净"
# 无抗混叠 → 高音区出现沙沙/金属声
```
